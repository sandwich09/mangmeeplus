# เอกสารซอฟต์แวร์ มั่งมี Plus (MangmeePlus / WatchDog-BMS) — ชุดปิดโครงการ

ชุดเอกสารนี้เป็นบันทึกทางวิศวกรรมซอฟต์แวร์ฉบับถาวรของระบบมั่งมี Plus จัดทำเมื่อปิดโครงการ (2026-11-16)
เพื่อให้ทีมในอนาคตเข้าใจ สร้างใหม่ และดูแลระบบได้จากเอกสารชุดนี้ร่วมกับโค้ดที่เก็บถาวรไว้

- **เขียนจากโค้ดจริง** ของ `origin/main` commit `08850deaf` (2026-11-10) ซึ่งเป็นรุ่นที่ให้บริการ Production ครั้งสุดท้าย
  บวก commit เอกสารหนึ่งรายการ เอกสารเก่าใน `docs/` ใช้เป็นข้อมูลประกอบเท่านั้น ที่ใดเอกสารเก่าไม่ตรงกับโค้ด
  ชุดนี้ยึดตามโค้ดและระบุความต่างไว้
- **ขอบเขต:** ทุกฟีเจอร์ที่ขายถึงแพ็ก 1,999 บาท (`ENTERPRISE_1999` ซึ่งเป็นแพ็กสูงสุด) รวมส่วนเสริม ระบบหลังบ้าน
  ระบบขาย และ LINE/AI ที่มีไว้เพื่อขายและให้บริการแพ็กเหล่านั้น
- **ภาษา:** ไทย โดยคงชื่อในโค้ด (path, route, model, permission key, enum) เป็นภาษาอังกฤษตามจริง
- **ขนาด:** 15 ไฟล์ ประมาณ 22,800 บรรทัด

- **ผู้บริหารหรือเจ้าของ:** เล่ม 01 แล้วข้ามไปบันทึกการปิดโครงการและขั้นตอนกู้ระบบท้ายเล่ม 08

- **นักพัฒนาที่จะกู้หรือพัฒนาต่อ:** เล่ม 03 → 04 → 05 → 08 แล้วใช้ 02a–02f เป็นข้อมูลอ้างอิงรายฟีเจอร์
- **ผู้ออกแบบหรือฝ่ายสนับสนุน:** เล่ม 06

## วิธีจัดทำและการตรวจสอบ

- แต่ละเล่มเขียนโดยอ่านโค้ดที่ commit เดียวกัน ไม่มีการรัน build ทดสอบ หรือระบบจริง เพราะโครงสร้างพื้นฐานถูกปิดแล้ว
  ผลการทดสอบและตัวเลขประสิทธิภาพที่อ้างถึงคัดจากบันทึกในคลังโค้ด ไม่ได้วัดใหม่
- ตารางขนาดใหญ่ (ฟีเจอร์ต่อแพ็ก สิทธิ์และบทบาท ตารางฐานข้อมูล enum รายการ API รายการหน้าจอ ตัวแปรตั้งค่า)
  สร้างด้วยสคริปต์จากไฟล์ต้นทาง และตรวจจำนวนเทียบกับโค้ดแล้ว: ฟีเจอร์ 62, สิทธิ์ 391, ตาราง 281, enum 291,
  API 1,068, หน้าจอ 207
- หลังรวมเล่ม ตรวจ path ของไฟล์ในโค้ดที่ทุกเล่มอ้างถึง 1,197 รายการ พบ 16 รายการที่ไม่มีไฟล์ ซึ่งเป็นกรณีที่ตั้งใจ
  (ผลลัพธ์ของการ build, ไฟล์ที่เล่มนั้นระบุเองว่าเอกสารอ้างถึงแต่ไม่มีในคลัง, ชื่อคอมโพเนนต์ที่ไม่ใส่นามสกุลไฟล์)
  และตรวจชื่อไฟล์ทดสอบที่อ้างถึงกว่า 1,200 ชื่อว่ามีอยู่จริง
- รหัสข้อกำหนดที่ไม่ใช่ฟังก์ชันของเล่ม 02a และ 04 ถูกเปลี่ยนเป็นช่วง `NFR-1xx` และ `NFR-9xx` ตอนรวมเล่มเพื่อไม่ให้ซ้ำกับเล่ม 03

## ข้อจำกัดที่ผู้อ่านต้องรู้

1. **ไม่ได้อ่านทุกบรรทัดของไฟล์ขนาดใหญ่** เช่น `process-line-webhook.use-case.ts` (ราว 15,500 บรรทัด)
   repository ของค่าใช้จ่ายและเบิกจ่าย และบริการ billing บางตัว ส่วนนี้เขียนจากโครงสร้างเมธอด กฎในชั้น domain
   รหัสข้อผิดพลาด และ DTO แต่ละเล่มมีหัวข้อ "สิ่งที่ตรวจสอบไม่ได้" ระบุจุดเหล่านี้ไว้ ถ้าต้องใช้ระดับเงื่อนไขย่อย
   ให้อ่านโค้ดประกอบ
2. **ค่าจริงของ Production ไม่อยู่ในคลังโค้ด** เช่น นโยบาย billing ที่ใช้งาน ราคาที่ผูกกับ Stripe แคมเปญที่เผยแพร่
   ค่าตัวแปรสภาพแวดล้อม เอกสารบันทึกเฉพาะค่าเริ่มต้นในโค้ด ค่าจริงอยู่ในฐานข้อมูลสำรองและไฟล์กุญแจลับของชุดสำรอง
3. **คำอธิบายภาษาไทยของ API แต่ละเส้นในเล่ม 05** สร้างจากชื่อฟังก์ชันด้วยกฎอัตโนมัติ บางประโยคแข็งหรือกำกวม
   ส่วน method, path, ไฟล์ controller และ permission ถูกต้องตามโค้ด
4. **คู่มือผู้ใช้ในเล่ม 06** เขียนจากโค้ดและคู่มือในแอป ไม่ได้กดหน้าจอจริง
5. **คอลัมน์ "แพ็ก" ที่มี `*` ในเล่ม 09** กำหนดจากกฎระดับหมวด ไม่ได้คัดจากข้อความรายข้อ
6. **ไม่มีข้อมูลลับในชุดเอกสารนี้** มีเฉพาะชื่อตัวแปรและชื่อกุญแจ ไม่มีค่า

## สิ่งที่เอกสารเก่าหรือความคาดหวังบอก แต่โค้ดจริงไม่ได้ทำ (สรุปข้ามเล่ม)

- ลูกค้าซื้อส่วนเสริม (เครดิตแชต รูปใบเสร็จ) ผ่าน Stripe เองไม่ได้ มีเฉพาะฐานรากและการเติมโดยผู้ดูแล (เล่ม 02f, 06)
- ไม่มีการทดลองใช้ฟรีแบบสมัครเองแล้วตั้งแต่ 2026-09-20 ร้านใหม่ต้องซื้อแพ็กก่อนใช้ (เล่ม 01, 02f)
- ไม่มีเงินทดรองจ่ายและการเคลียร์ ไม่มีงบประมาณหรือวงเงินค่าใช้จ่าย การอนุมัติเบิกจ่ายเป็นชั้นเดียวต่อรอบ (เล่ม 02b)
- ไม่มีการยืนยันตัวตนสองชั้น (MFA) และไม่มีการเชิญพนักงานทางอีเมล รหัสผ่านเริ่มต้นของพนักงานสร้างจากวันเกิด (เล่ม 02a, 03)
- e-WHT ไม่ได้เชื่อมธนาคารหรือกรมสรรพากร รายงานส่งออกได้เฉพาะ CSV (เล่ม 02c)
- โมดูลสิทธิ์เจ้าของข้อมูลจัดการเรื่องและหลักฐานเท่านั้น ไม่มีโค้ดลบหรือทำข้อมูลนิรนามจากเรื่องที่เปิด (เล่ม 04)
- การแยกข้อมูลระหว่างร้านบังคับที่ชั้นแอปพลิเคชัน ฐานข้อมูลไม่มี row-level security (เล่ม 03)
- หลักการ "ไม่มีสวิตช์เปิดปิดฟีเจอร์" ใช้กับความสามารถของ LINE AI ฝั่ง gateway โค้ดส่วนอื่นยังมีสวิตช์ผ่านตัวแปรสภาพแวดล้อม (เล่ม 02a, 03)
- ADR บางฉบับไม่ตรงกับของจริง: ระบุ ECS Fargate และ AWS CDK แต่ระบบจริงใช้ Kamal บน EC2 และไม่มี CDK ในคลัง (เล่ม 03)

## สิ่งที่ต้องมีถ้าจะกู้ระบบ

รายละเอียดอยู่ท้ายเล่ม 08 ประเด็นที่ห้ามพลาด:

- กุญแจ `CREDENTIAL_ENCRYPTION_KEY` และ `PDPA_PSEUDONYMIZATION_KEY` จากชุดสำรอง ถ้าไม่มี ข้อมูลที่เข้ารหัสในฐานข้อมูลสำรองจะอ่านไม่ได้
- สร้างฐานข้อมูลด้วย `prisma migrate deploy` ตามลำดับ migration เท่านั้น กฎ CHECK, partial index และ trigger จำนวนมากไม่อยู่ใน `schema.prisma`
- กุญแจเซ็น release เดิมถูกลบถาวร ต้องสร้างใหม่ และต้องขอข้อมูลรับรองใหม่ของ LINE, Stripe, Postmark และบัญชีคลาวด์ใหม่
- ไฟล์ Cloudflare Worker ในคลังยังชี้ที่อยู่ปลายทางรุ่นเก่า ต้องแก้ก่อนเผยแพร่
