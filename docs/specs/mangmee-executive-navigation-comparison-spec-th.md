## 1. หลักการและคำถาม

ใช้ภาพรวมเป็นจุดเริ่ม 30 วินาที: ขนาดลูกค้า / ใช้งานจริง / รับเงิน / เรื่องที่ควรดูต่อ
รายละเอียดแยกหน้าตามงานวิเคราะห์; ไม่รวมกราฟทุกชนิดไว้ใต้ “วิเคราะห์ธุรกิจ” ยาวหน้าเดียว
ผู้บริหารควรเดิน Summary → Analysis → Company list → Company detail และย้อนกลับพร้อมบริบทได้
หนึ่งหน้าเจาะลึกแสดงประเด็นหลักเดียว; ใช้ tabs สลับมุมมองของประเด็นเดียว ไม่ซ่อนทุกงานไว้ใน tab ชั้นเดียวจำนวนมาก
ไม่เพิ่มคะแนนสุขภาพ/คำแนะนำอัตโนมัติหรือข้อสรุปเหตุและผลจากข้อมูลเพียงเดือนเดียว

## 2. Information architecture

รายการหน้า รหัส และเส้นทางเป็นชุดเดียวกับสเปกหน้าจอ §3 (**ข้อเสนอ รอเจ้าของยืนยัน — D2**; ถ้าเจ้าของให้กลับไปหน้า “วิเคราะห์” หน้าเดียว เอกสารนี้ใช้เฉพาะ §4 และต้องเขียนสเปกหน้าจอ §5, §7 ใหม่)

| รหัส | เมนู | คำถามผู้บริหาร | เนื้อหาเริ่มต้น | ทางไปต่อ |
|---|---|---|---|---|
| EX-01 | ภาพรวมธุรกิจมั่งมี | ตอนนี้ธุรกิจเป็นอย่างไร ควรสนใจอะไร | การ์ดตัวเลข 4 ใบ (N01, N02, N03, N06), สรุปการเริ่มใช้ใบเสร็จ (N08), “เรื่องที่ควรดูต่อ” 3 รายการ: จ่ายแล้ว ยังไม่เริ่มใช้ / เคยใช้ แต่ไม่ใช้ในเดือน / สัดส่วนรายรับของกลุ่มที่จ่ายสูงสุด | ไปหน้าวิเคราะห์ที่เกี่ยวข้องหรือกลุ่มบริษัท |
| EX-03A | การใช้งาน | ลูกค้าเริ่มใช้หรือยัง ใช้มากแค่ไหน | แท็บ การเริ่มใช้: กราฟการเริ่มใช้ใบเสร็จ + กล่อง “ชำระเงินแล้ว ใช้งานเป็นอย่างไร” (N05); แท็บ อันดับการใช้: ใบเสร็จในเดือน / วันใช้งาน / ใช้ผู้ช่วย | เจาะรายชื่อ/รายละเอียดบริษัท |
| EX-03B | รายรับ | รับเงินจริงเท่าไร พึ่งลูกค้ากลุ่มใด | แท็บ สรุปรายรับ: การ์ดเงินรับ คืนเงิน ยอดรับสุทธิในเดือน (N07, N06) ค่าธรรมเนียมแสดงแยก (N14) และกราฟแนวโน้ม; แท็บ ลูกค้าที่สร้างรายรับสูง: สัดส่วนของกลุ่มที่จ่ายสูงสุดและกลุ่มที่รวมยอดรับถึง 80% (N12) | รายชื่อกลุ่มที่จ่ายสูงสุด / นอกกลุ่ม / ถึง 80% / อันดับตามเงิน |
| EX-03C | ลูกค้าและที่มา | ธุรกิจ/ช่องทาง/เซลล์ไหนสร้างลูกค้าและรายรับ | แท็บ ธุรกิจ / ช่องทาง / เซลล์; แสดงเพียงตารางของแท็บที่เลือก (รายการตารางอยู่ในสเปกหน้าจอ §7) | เปิดบริษัทในกลุ่ม / ไปเปรียบเทียบ |
| EX-03D | เปรียบเทียบ | สองกลุ่มต่างกันตรงไหน | เลือกมิติและฝั่ง A/B; ค่าเดียวกัน หน่วย/ช่วงเดียวกัน พร้อมขนาดฐาน | รายชื่อกลุ่ม A/B หรือรายละเอียดบริษัท |
| EX-02 | บริษัทลูกค้า | บริษัทไหนต้องตาม ดูรายละเอียดร้านใด | ค้นหา + เรียง + รายชื่อ; ตัวกรองเพิ่มเติมแบบเปิดเมื่อใช้ | รายละเอียด; กลับพร้อมกลุ่ม การเรียง และเลขหน้าเดิม |
| EX-07/08 | บัญชีผู้บริหาร | ใครเข้าถึงรายงานได้ | เฉพาะผู้จัดการบัญชี; แยกจากงานรายงาน | เพิ่ม / รายละเอียด / สถานะ ตามสเปกหน้าจอ §9.2 |

- เมนูอยู่ใน `SystemHeader` เดิมเป็นกลุ่มเดียว “รายงานผู้บริหาร” หกรายการเรียงตามตาราง (EX-01, EX-03A–D, EX-02) ส่วน “บัญชีผู้บริหาร” อยู่ในกลุ่ม “ตั้งค่าระบบ” เดิม ไม่ทำกลุ่มซ้อนกลุ่ม เพราะ shell เดิมมีกลุ่มเมนูชั้นเดียว ใครเห็นรายการใดเป็นไปตามสเปกหน้าจอ §3.1
- มือถือใช้ปุ่ม “เมนู” แบบพับได้เดิมของ shell รายการเป็นลิงก์ ไม่ใช้ตัวเลือกแบบ dropdown เป็นเมนู
- เส้นทาง: `/system/executive/{usage,revenue,customers,compare}`; บริษัทและบัญชีตามสเปกหน้าจอ §3 ไม่มีเส้นทาง `/system/executive/analysis`
- ไม่เพิ่มสิทธิ์ cross-tenant ใหม่และไม่เพิ่ม generic analytics service
- deletion routes ยังซ่อน: แอปจริงไม่สร้างหน้าและเส้นทางของคำขอลบข้อมูล

## 3. ความหนาแน่นหน้าจอ

- แถวเวลา: เดือน +ข้อมูลถึงเวลาใด +ปุ่มตัวกรอง; ไม่วาง4fieldใหญ่ในทุกหน้า
- industry/source/referrer panel เปิดเมื่อผู้ใช้ขอ; เมื่อปิดต้องมี label/จำนวน filter ที่ใช้อยู่และล้างได้ ห้าม hidden filter
- directory แสดง search/sort ก่อน และตัวกรองละเอียดใน panel; cohortจากกราฟต้องมีชื่อและจำนวนแม้ panel ปิด
- ภาพรวมไม่ใส่ตารางแยกธุรกิจ/รายชื่อTop10/ตารางเซลล์/ทุกchart; แต่ละสรุปมีทางไปหน้ารับผิดชอบ
- หน้า usage/revenue/customer ใช้ tabs เพื่อลดการเลื่อน; ไม่ shrink font/control เพื่อยัดทั้งหมด
- คง tokens/shared fields/buttons/month picker; mobile dropdown/filter keyboard/portal ไม่หลุดธีม
- Demo footer สำหรับตรวจ permission/state พับได้ ไม่เป็นเนื้อหาของ dashboard (มีเฉพาะในต้นแบบ)
- ความหนาแน่นวัดที่จอมือถือ 390×844 ก่อน: หน้าภาพรวมเห็นการ์ดตัวเลขครบ 4 ใบในจอแรก และปุ่มหลักของแต่ละหน้าอยู่ในจอแรก เกณฑ์ครบอยู่ในสเปกหน้าจอ §11.1
- ตารางของหน้าวิเคราะห์และตารางเปรียบเทียบใช้รูปแบบมือถือตามสเปกหน้าจอ §11.2 ไม่ใช้ตัวเลื่อนตารางที่กว้างตามเนื้อหา

## 4. Comparison contract

### เปรียบเทียบกลุ่ม/บริษัท

- รองรับ industry A/B, discovery A/B, referring salesperson A/B, company A/B
- ไม่ใช้ credited salesperson แทน referrer; เครดิตยอดเปิดเป็นคนละมุมในหน้าลูกค้าและที่มา
- ช่วงเวลาเดียวกัน, eligible CUSTOMER population และ cutoff เดียวกัน; source policy/coverage ตามสเปกเดิม
- หน้านี้เริ่มจากบริษัทลูกค้าทั้งหมดในเดือนที่เลือก (N01 แบบไม่ใช้ตัวกรองร่วม) ไม่ใช้ shared segment filter ที่ซ่อนอยู่จากหน้าอื่น; label ฐานต้องชัด
- เปิดหน้าครั้งแรกยังไม่เลือกฝั่งใด แสดง “เลือกสองกลุ่มที่ต้องการเปรียบเทียบ” ไม่เลือกคู่ให้เอง
- ค่า A/B แยกจากตัวกรองร่วมของรายงาน และอยู่ใน URL ของหน้านี้ (`by`, `a`, `b`) ตัวกรองร่วมที่ผู้ใช้ตั้งไว้ยังอยู่ใน URL แต่หน้านี้ไม่ใช้ และยังอยู่ครบเมื่อไปหน้าอื่น
- รายชื่อที่เปิดจากฝั่ง A หรือ B ใช้เงื่อนไขของฝั่งนั้นเฉพาะในหน้ารายชื่อนั้น (`pick` กับ `from=compare` ตามสเปกหน้าจอ §3.3) ไม่เขียนทับตัวกรองร่วมของรายงานทุกกรณี; ปุ่ม “← กลับเปรียบเทียบ” คืนค่าฝั่งเดิม
- company A/B ต้องคนละบริษัท; กลุ่มA/Bต้องต่างกัน; ถ้าเหมือนให้ขอเลือกต่างกัน ไม่ทำผลชนะ/แพ้ปลอม
- บริษัทต้องอยู่ใน eligible population ของช่วงนั้น; ค่าใน URL ที่ไม่มีในเดือนนั้นไม่เปลี่ยนเป็นบริษัทแรกเงียบ ๆ ให้แสดงว่าต้องเลือกใหม่
- การเลือกบริษัทใช้ช่องค้นหา (พิมพ์อย่างน้อย 2 ตัวอักษร แล้วเลือกจากผลไม่เกิน 20 รายการ) ไม่ใช้ dropdown ที่บรรจุทุกบริษัท
- ตารางแสดง 7 รายการ ใช้ชื่อและนิยามของสเปกหน้าจอ §4.2: บริษัทลูกค้า (N01), ยอดรับสุทธิในเดือน (N06), ยอดรับสุทธิต่อบริษัท (N13), ใบเสร็จในเดือน (N09), ใบเสร็จต่อบริษัท (N13), สัดส่วนบริษัทที่เคยเพิ่มใบเสร็จ (N08) และใช้งานในเดือน (N02)
- ค่าเฉลี่ยต่อบริษัทใช้ฐานบริษัทจริงทั้งหมดของแต่ละฝั่ง ไม่ใช่เฉพาะผู้จ่าย/ผู้ใช้; ตั้งชื่อให้ชัด
- raw total ใช้ดูขนาด; per-company/rate ใช้ประกอบการเทียบกลุ่มขนาดไม่เท่ากัน; ไม่กล่าวว่าเป็น causal conversion หรือ ROI
- ส่วนต่างกำหนด A−B; อัตราแสดงเป็น percentage points (จุดเปอร์เซ็นต์) ไม่สลับกับ percent change (บนจอใช้คำว่า “จุด” ตามเอกสารคำบนหน้าจอ)
- ค่าที่ข้อมูลไม่ครบใช้กติกาเดียวกับทุกหน้า (สเปกหน้าจอ §4.2–§4.3): จำนวนนับแสดง “อย่างน้อย N” เงินแสดง “ยอดเฉพาะรายการที่ยืนยันแล้ว” ค่าที่ไม่มีเลยแสดง —; ผลต่างที่ต้องใช้ค่าที่ไม่ครบแสดง —; ฐานเป็น 0 ใช้ — สำหรับ rate/average
- การปัดเศษเป็นไปตามสเปกหน้าจอ §4.3 (คำนวณจากจำนวนเต็ม ปัดครึ่งขึ้น แบบเดียวกันทั้งหน้าจอและไฟล์ Excel); signed cash ไม่ clip เป็น 0 ในตาราง
- บนมือถือแสดงทีละรายการเป็นบล็อก: ชื่อรายการ → ฝั่ง A → ฝั่ง B → ต่างกัน (A ลบ B) ให้เห็นครบโดยไม่เลื่อนแนวนอน
- period snapshot/provenance/permission ต้องตรงทั้งสองฝั่ง; requestหนึ่งฝั่งล้ม ไม่วางฝั่งเก่าเทียบกับฝั่งใหม่

### เปรียบเทียบช่วงเวลา (ข้อเสนอสำหรับ integration)

- ตัวเลือกเดือนนี้เทียบเดือนก่อน **ยังไม่แสดงในเมนูของรุ่นแรก** จนกว่าจะมีข้อมูลย้อนหลังครบ เพราะตัวเลือกที่กดแล้วใช้ไม่ได้ทุกครั้งไม่มีประโยชน์กับผู้ใช้; ต้นแบบมี fixture เต็มเฉพาะกันยายน จึงแสดง unavailable แทนสร้าง % โตปลอม
- ช่วงยังไม่ครบเดือนต้องเทียบ elapsed interval เท่ากันใน Bangkok และโชว์วันcutoffทั้งสองช่วง; เดือนเต็มเทียบเดือนเต็มได้
- ระบุ population mode: cohortเดียวกัน หรือประชากรของแต่ละช่วง; cohort/lifecycle changes ต้องอธิบายแยก
- ฐานก่อนหน้า0/unknown ห้ามหารเพื่อแสดงgrowth%; แสดงจำนวนเปลี่ยนหรือไม่มีฐานตามความหมาย
- trend fixtureเดิมไม่ใช่หลักฐาน month-level company/activity sourceครบ ใช้สร้าง delta/KPIgrowthไม่ได้

## 5. Navigation and state

สถานะของหน้า การกดเจาะ และการกลับ เป็นไปตามสเปกหน้าจอ §3.2 และ §3.3 สรุปส่วนที่เกี่ยวกับเอกสารนี้:

- หน้าปลายทางมีชื่อชัดและ navigation selected; แท็บของ usage/revenue/customers อยู่ใน URL (`view`) จึงคงอยู่เมื่อไปรายละเอียดแล้วกลับ โหลดใหม่ หรือเปิดจากลิงก์
- เดือนและตัวกรองร่วมอยู่ใน URL ของทุกหน้ารายงาน และลิงก์เมนูพาไปด้วยเสมอ; หน้าเปรียบเทียบอธิบายฐานของตัวเองและไม่ทำให้ตัวกรองร่วมหาย
- การกดเจาะไม่เขียนทับตัวกรองของหน้าต้นทาง; list→detail→Back คงเลขหน้า การเรียง และกลุ่ม; compare→list→detail→list→compare ครบ และค่าการ์ดของหน้าต้นทางก่อนกดกับหลังกลับต้องเท่ากัน
- loading/error/forbidden ต้องครอบคลุมหน้าวิเคราะห์ใหม่ทุกหน้า; account management และ deletion boundaries คงเดิม

หมายเหตุของต้นแบบ (ไม่ใช่กติกาของแอป): ต้นแบบเก็บสถานะผ่านตัวแสดงในห้องสนทนา (saved state ไม่เกิน 16KiB, host state event ใช้กฎ migration เดียวกับ initial render, route เดิม `analysis` ย้ายไป revenue หรือ usage) กติกาเหล่านี้ไม่นำไปใช้กับแอป แอปใช้ URL ตามสเปกหน้าจอ §3.2
