## 0. คำตอบสั้น

**เสียคุณค่าไปบางส่วน:**

- **ช่องว่างใหญ่ที่สุดคือไม่มีหมวด "วัตถุดิบและสินค้าเพื่อขาย"** ซึ่งเป็นรายจ่ายก้อนใหญ่ที่สุดของคาเฟ่ ร้านอาหาร ซาลอน และร้านค้าปลีก รายการเหล่านี้ไปรวมใน "ค่าใช้จ่ายเบ็ดเตล็ด" ทำให้การแยกยอด การเทียบเดือน และคำแนะนำของน้องมั่งมีเห็นแค่ก้อนใหญ่ก้อนเดียว
- **รองลงมาคือหมวดที่รวมกันเกินไป:** น้ำมันรวมอยู่ในค่าเดินทาง ส่วนไฟฟ้า ประปา และโทรศัพท์รวมอยู่ในสาธารณูปโภค

**แต่ชุดเดิมไม่ได้น้อยโดยบังเอิญ:**

- ชุด V1 ตัดตาม **พฤติกรรมภาษี** (ภาษีซื้อเคลมได้หรือไม่ และอัตราหัก ณ ที่จ่าย) เพื่อไม่ให้ร้านเคลมภาษีผิด
- การเพิ่มหมวดมีต้นทุนสามข้อ:
  - AI เลือกยากขึ้น
  - ผู้ใช้ต้องเลือกจากรายการยาวขึ้น
  - หนึ่งหมวดผูกได้แค่หนึ่งบัญชี
- ข้อเสนอนี้จึงเพิ่มหมวดเฉพาะเมื่อ **บันทึกบัญชีหรือภาษีต่างจากหมวดเดิม** หรือ **ให้ข้อมูลเชิงลึกคุ้มพอ** ตามกติกาเดิมของ template และแยกชุดตามประเภทธุรกิจเป็นตัวเลือก

### 1.3 ข้อเท็จจริงอื่นที่กำหนดขอบเขตข้อเสนอ

- **ร้านเพิ่มหมวดเองได้บนเว็บ** ที่หน้า "หมวดหมู่ค่าใช้จ่าย" (`ExpensesWorkspacePanels.tsx`, เมนูย่อย `expenses.categories`)
  - ต้องมีสิทธิ์ `expense.category.manage` ซึ่ง OWNER, ADMIN และ FINANCE ถือ
  - ระบบสร้าง `accountHintKey` ให้เป็น `expense.custom.<เวลา>` และให้เลือก Tax Code เริ่มต้นได้
  - **หมวดที่ร้านสร้างเองไม่มีการผูกบัญชี** จึงลงบัญชีเป็น `expense_account_unmapped` จนกว่าจะมีผู้ถือ `ledger.posting-rule.manage` มาผูกผ่าน API ซึ่งไม่มีหน้าจอ (มติปิดหน้าบัญชีต่อผู้ใช้ 2026-08-09, `expense-account-binding.use-case.ts`)
- **การผูกบัญชีรับเฉพาะบัญชีของบริษัทที่ active ลงรายการได้ และไม่ใช่บัญชีคุม** ไม่ได้จำกัดชนิดบัญชี บัญชีต้นทุน (COST) จึงผูกได้
  - ในส่วนที่ตรวจของเส้นทางลงบัญชีรายจ่าย (`loadExpenseAccountBindings` ใน `journal.use-case.ts`) ไม่พบข้อจำกัดชนิดบัญชี แต่การลงบัญชีและรายงานกำไรขั้นต้นของบัญชี COST จากรายจ่ายทั้งเส้นทาง — **ต้องตรวจสอบ**
- **บัญชีในผัง `TH_SME_COA_V1` ทุกบัญชีเป็น `isPosting: true`** ยกเว้น 9999-99 ซึ่งเป็นบัญชีคุม บัญชีที่อ้างในเอกสารนี้จึงมีอยู่จริงและลงรายการได้ทุกบัญชี
  - ในผังมีบัญชีต้นทุนร้านความงามอยู่แล้ว: 5130-04 ทำเล็บ, 5130-05 คิ้วและขนตา, 5130-06 แว็กซ์, 5130-07 สปา
- **โปรไฟล์ภาษีที่ onboarding เปิด** (`WATCHDOG_TH_DOMESTIC_EXPENSE_V1`) มี Tax Code แค่ `V7` (ภาษีซื้อขอคืนได้ 7%) กับ `ND` (ขอคืนไม่ได้) หมวดใหม่จึงตั้งค่าเริ่มต้นได้เฉพาะ V7, ND หรือว่าง ซึ่งเป็นแค่คำแนะนำบนหน้าตรวจรายการ
- **หัก ณ ที่จ่ายตัดสินรายรายการ** (`ExpenseRecord.whtCategoryCode`/`whtRate`) จากแคตตาล็อกประเภทเงินได้
  - แคตตาล็อกที่ seed มี: บริการ 3%, ค่าเช่า 5%, วิชาชีพ 3%, โฆษณา 2%, ขนส่ง 1%, ดอกเบี้ย 1%, อื่น ๆ 3%
  - **หมวดไม่ได้เก็บอัตราหัก ณ ที่จ่าย** คอลัมน์หัก ณ ที่จ่ายในตาราง §3–§4 จึงเป็นข้อมูลอ้างอิง ไม่ใช่ค่าที่ระบบตั้งให้
- **AI เลือกหมวด** จาก `activeCategories` ที่มีแค่ `{id, name}` (`expense-extraction.use-case.ts`, prompt ใน `apps/ai-gateway/src/modules/line-ai/presentation/http/line-ai-internal.controller.ts`)
  - เลือกได้หนึ่งหมวดต่อเอกสาร ต้องเป็นหมวดที่เปิดใช้ และต้องอ้างข้อความจากใบเสร็จ 1–5 ช่วง
  - ไม่ชัดให้เว้นไว้ และห้ามใช้หมวดตัดสิน VAT, Tax Code หรือบัญชี
  - schema มีหมวดระดับบรรทัด (`ExpenseLine.expenseCategoryId`) แต่ AI ให้หนึ่งหมวดต่อเอกสาร
- **สถานะโมดูลที่เกี่ยวข้อง** (Owner 2026-09-29: "ยอดขาย สต็อก เรายัง dev ไม่เสร็จเลย ไม่อยู่ในแพ็กเกจถูกแล้ว"):
  - โมดูลยอดขายและสต็อกยังพัฒนาไม่เสร็จ จึงยังไม่มีรายได้จากการขายหรือสินค้าคงเหลือในระบบ
  - บัญชีแยกประเภท (`double_entry_ledger`) และรายงานงบ (`reports`) ไม่อยู่ในแพ็กเกจที่ขาย และยืนยันไม่ได้ว่าเปิดใช้กับลูกค้า — **ต้องตรวจสอบ**
  - การผูกบัญชีของหมวดยังจำเป็นแม้ยังไม่เปิดบัญชีแยกประเภท เพราะ bootstrap ตรวจบัญชีก่อนสร้างหมวด และใบรับรองแทนใบเสร็จต้องใช้หมวดที่ผูกบัญชีแล้ว ผลต่อการลงบัญชีใน §5.3 จะเกิดเมื่อการลงบัญชีอัตโนมัติเปิดใช้
- **หมวดถูกใช้ใน:**
  - การลงบัญชี (หมวด → บัญชี) เมื่อการลงบัญชีอัตโนมัติเปิดใช้ (ต้องตรวจสอบ)
  - การแยกยอด (`expense.get_breakdown` ทั้งเว็บและ LINE)
  - ไฟล์ส่งนักบัญชี (`category_name`)
  - ใบรับรองแทนใบเสร็จ (ต้องมีหมวดที่ผูกบัญชีแล้ว)
  - flow ใบรับรองใน LINE ให้เลือกหมวดด้วยเลขลำดับจากรายการทั้งหมด (`line-substitute-receipt-continuation.use-case.ts`)

## 2. หลักการของข้อเสนอ

1. **แยกเมื่อบันทึกต่างกัน รวมเมื่อบันทึกเหมือนกัน** (กติกาของ V1) เว้นแต่การแยกให้ข้อมูลเชิงลึกคุ้มชัดเจน ทุกแถวในตาราง §3–§4 เขียนเหตุผลและสิ่งที่ต้องแลกไว้
2. **หนึ่งหมวดผูกหนึ่งบัญชี:** ถ้าผังไม่มีบัญชีที่ตรง ให้เขียนตรง ๆ ว่า **ต้องตรวจสอบ** และเสนอทางเลือก ไม่เดาบัญชี
3. **Tax Code เริ่มต้นเป็นแค่คำแนะนำ:** ถ้าภาษีขึ้นกับรายละเอียดที่หมวดรู้ไม่ได้ (เช่น ชนิดรถ) ให้เว้นว่างเพื่อให้คนเลือก ตามแบบของ V1
4. **ไม่ลบหรือเปลี่ยนชื่อหมวด V1** เพราะประวัติรายการและรายงานเดิมอ้างชื่อเหล่านี้
5. **ไม่มีสวิตช์:** ชุดใหม่เป็นข้อมูลที่เปิดเสมอ ชุดตามประเภทธุรกิจเป็นการเลือกข้อมูล ไม่ใช่ feature flag
6. **ตารางภาษีทั้งหมดต้องให้นักบัญชีไทยตรวจก่อนเปิดใช้** เพราะค่าเริ่มต้นมีผลกับการยื่นภาษีของร้าน ข้อกฎหมายที่อ้างเป็น "ตามที่ทราบ"

### 3.2 พิจารณาแล้วไม่แนะนำให้แยกในชุดพื้นฐาน

- **ค่าไปรษณีย์:** การส่งพัสดุให้ลูกค้าคือค่าขนส่ง (ยกเว้น VAT, หัก 1% เมื่อจ่ายผู้ขนส่ง) จึงใช้หมวด "ค่าขนส่ง" เดิม
  - ถ้าต้องแยกภายหลัง ผังมีบัญชี 5330-04 ค่าไปรษณีย์
  - การจ่ายไปรษณีย์ไทยต้องหักหรือไม่ — ต้องตรวจสอบ
- **ค่าจ้างแรงงานรายวันหรือพาร์ทไทม์:**
  - เป็นเงินได้ตาม ม.40(1) หักตามการคำนวณภาษีเงินเดือน ไม่ใช่อัตราคงที่ และอาจมีประกันสังคม จึงใกล้งานเงินเดือนซึ่งระบบยังไม่มี
  - ใส่เฉพาะในชุดร้านอาหารและซาลอน (§4) พร้อมคำเตือน
- **ค่าจ้างทำของหรือผู้รับเหมาช่วงแบบรวม:**
  - ภาษีเหมือน "ค่าซ่อมแซมและบำรุงรักษา" (V7, 3%) และผังไม่มีบัญชีรวม
  - ใส่เฉพาะชุดธุรกิจบริการ

- **แนะนำ:** ถามแบบไม่บังคับตอนสมัคร ("ร้านของคุณทำธุรกิจอะไร") และให้เลือกหรือเปลี่ยนได้ภายหลังในหน้า "หมวดหมู่ค่าใช้จ่าย" ในส่วน "เพิ่มชุดหมวดตามประเภทธุรกิจ"
- **ไม่ผูกกับ `Company.businessCategory`:** field นั้นเป็นตัวเตือน PDPA ของธุรกิจเกี่ยวกับสุขภาพ (RETAIL, TRADING, SERVICE, CLINIC, WELLNESS_SPA, MEDICAL_RETAIL, OTHER) และไม่มีค่าของร้านอาหาร การแก้ field นั้นเพื่อเลือกหมวดเสี่ยงไปกระทบการเตือน
- **เรื่องที่ Owner ต้องตัดสิน (§9 ข้อ 2):** จะเก็บชุดที่เลือกไว้ใน field ใหม่ หรือเพิ่มหมวดเข้าไปเลยโดยไม่ต้องจำว่าเลือกชุดไหน

## 5. ร้านที่มีอยู่แล้ว

### 5.1 ทางเลือก

| ทางเลือก | วิธี | ข้อดี | ข้อเสีย |
|---|---|---|---|
| ก. เพิ่มชุดพื้นฐานให้อัตโนมัติ | สคริปต์ครั้งเดียวที่รันซ้ำได้ ตามแบบ `apps/api/src/scripts/backfill-revenue-categories.ts` | ทุกร้านได้คุณค่าทันที | รายการหมวดของร้านเปลี่ยนโดยร้านไม่ได้ขอ |
| ข. ให้ร้านกดเพิ่มเอง | ส่วน "หมวดแนะนำ" ในหน้าหมวดหมู่ กดเพิ่มทีละหมวดหรือทั้งชุด (สิทธิ์ `expense.category.manage`) | ร้านควบคุมเอง | ร้านส่วนใหญ่อาจไม่เคยเข้าไปกด |

**แนะนำ:**

- ใช้ **ก** กับชุดพื้นฐาน เพราะเป็นการเพิ่มอย่างเดียว ไม่ลบหรือย้ายของเดิม
- ใช้ **ข** กับชุดตามประเภทธุรกิจและหมวดเสริม
- Owner ตัดสินใน §9 ข้อ 3

### 5.2 กลไก

- **ชุดใหม่ในโค้ด:** เพิ่ม `TH_SME_EXPENSE_CATEGORIES_V2` ประกอบด้วยแถว V1 เดิมทั้งหมดในลำดับเดิมบวกชุด §3 และให้ `bootstrapCompanyExpenseCategories` ของบริษัทใหม่ใช้ V2
- **ฟังก์ชันเพิ่มหมวดที่รันซ้ำได้:** `ensureCompanyExpenseCategories(tx, { companyId, rows })`
  - ตรวจบัญชีด้วยกติกาเดียวกับ bootstrap
  - `createMany` แบบ `skipDuplicates` (unique `[companyId, name]`)
  - ข้ามหมวดที่ชื่อเหมือนหรือ `accountHintKey` เหมือนหมวดเดิม และข้ามหมวดชื่อใกล้กัน (เช่น ร้านสร้าง "ค่าน้ำมัน" เองไว้แล้ว) แล้วรายงานรายการที่ข้าม
  - ใช้ร่วมกันทั้งสคริปต์ย้อนหลัง ปุ่ม "หมวดแนะนำ" และการเลือกชุด
  - ต้องทำฟังก์ชันใหม่เพราะ `createMany` ของ V1 วันนี้ไม่มี `skipDuplicates` (ใช้ได้เฉพาะตอนเปิดร้าน)
- **`accountHintKey` ของหมวดใหม่คงที่:** เช่น `expense.cost_of_goods`, `expense.fuel`, `expense.electricity`, `expense.water`, `expense.telecom`, `expense.software` (ตรงกับหมวดกลางเดิม `ค่าซอฟต์แวร์/บริการ`), `expense.small_equipment`, `expense.insurance`, `expense.government_fees`, `expense.penalties`
  - hint ที่ตรงกันจะซ่อนหมวดกลางชื่อเก่าของบริษัทรุ่นก่อน bootstrap ตามกติกา `selectExpenseCategoryScope`
- **ผู้ตรวจของหมวดใหม่:** เป็นค่า sentinel `system:expense-category-bootstrap` เหมือน V1 นักบัญชีจึงยังเห็นว่าเป็นค่าที่ template เลือก (`awaitingHumanReview`)
- **`sortOrder`:** ต่อท้ายหมวดเดิม ไม่ลบหรือเปลี่ยนชื่อหมวดเดิม และการเก็บเข้าคลังยังทำด้วยมือเหมือนเดิม
- **บริษัทรุ่นก่อน bootstrap:** อยู่นอกข้อเสนอนี้ ต้องตรวจสอบก่อนว่ามีร้านจริงหรือไม่ ถ้ามี ต้อง bootstrap ผังบัญชีก่อน
- **สคริปต์ย้อนหลังบน production:** รันได้เมื่อ Owner อนุมัติตาม runbook เท่านั้น (ต้องใช้การเชื่อมต่อฐานข้อมูล production และแจ้งก่อน)

### 5.3 ผลกระทบ

- **การลงบัญชี** (มีผลเมื่อการลงบัญชีอัตโนมัติเปิดใช้กับลูกค้า — ต้องตรวจสอบ §1.3):
  - หมวดใหม่ผูกบัญชีที่มีอยู่แล้ว จึงพร้อมลงบัญชีได้ รายการเก่าไม่เปลี่ยนหมวดและไม่ย้อนแก้บัญชีที่ลงแล้ว
  - รายการใหม่ที่เข้าหมวดใหม่จะลงบัญชีต่างจากเดิม:
    - น้ำมันยังอยู่ 5200-09 เหมือนเดิม
    - ไฟฟ้า ประปา และโทรศัพท์ย้ายจาก 5330-05 ไปบัญชีของตัวเอง
    - วัตถุดิบย้ายจาก 5370-06 ไป 5130-01 แยกเป็นต้นทุนสินค้า (กำไรขั้นต้นต้องรอโมดูลยอดขาย)
  - ควรแจ้งนักบัญชีของร้าน เพราะไฟล์ส่งนักบัญชีแสดงหมวดใหม่ตั้งแต่วันที่เพิ่ม
- **รายงานและที่ปรึกษา:**
  - การแยกยอดตามหมวดมีกลุ่มใหม่ตั้งแต่วันที่เพิ่ม การเทียบข้ามวันนั้นจึงไม่ใช่ของชนิดเดียวกัน
  - ที่ปรึกษาต้องบอกเรื่องนี้ และเครื่องมือรายจ่ายผิดปกติต้องข้าม "หมวดพุ่ง" ของหมวดที่เพิ่งสร้าง (แผนที่ปรึกษา S4a)
  - ไฟล์ส่งนักบัญชีแสดงชื่อหมวดใหม่
- **ภาษี:** Tax Code เริ่มต้นเป็นคำแนะนำ ผู้ตรวจยังยืนยันเอง ส่วนหัก ณ ที่จ่ายยังตัดสินรายรายการเหมือนเดิม
- **LINE:** รายการหมวดแบบมีเลขใน flow ใบรับรองจะยาวขึ้นบนมือถือ เสนอให้แสดงหมวดที่น่าจะใช่ 5 อันดับแรก พร้อมบอกว่าพิมพ์ชื่อหมวดได้ (ต้องตรวจสอบจุดที่แสดงรายการ)
- **หมวดที่ร้านสร้างเอง:** ยังลงบัญชีไม่ได้จนกว่าจะผูกบัญชี (ปัญหาเดิม)
  - ปุ่ม "หมวดแนะนำ" แก้ปัญหานี้ในทางปฏิบัติเพราะหมวดที่เพิ่มผ่านปุ่มผูกบัญชีมาแล้ว
  - หมวดที่ร้านตั้งชื่อเองยังต้องมีคนผูก (§9 ข้อ 9)

## 6. ให้ AI เลือกถูกเมื่อหมวดมากขึ้น

1. **ส่งคำใบ้สั้นต่อหมวด:** payload เปลี่ยนเป็น `activeCategories: {id, name, hint?}`
   - หมวดที่มาจาก template ส่งตัวอย่าง 3–6 คำ โดยจับคู่ด้วย `accountHintKey` กับแถวใน template จึงไม่ต้องเพิ่มคอลัมน์ในฐานข้อมูล และ template เป็นแหล่งเดียวของคำใบ้
   - หมวดที่ร้านสร้างเองส่งแค่ชื่อ
   - จุดที่แก้: `expense-extraction.use-case.ts` และ `expense-document.use-case.ts` ใน API, prompt การอ่านใน `line-ai-internal.controller.ts` และ intake ของ `intent-router.agent.ts` ใน gateway
2. **กติกาแยกคู่ที่สับสนง่าย** (เพิ่มใน prompt การอ่าน):
   - ปั๊มน้ำมันหรือจำนวนลิตร → ค่าน้ำมัน; แท็กซี่ ทางด่วน หรือที่จอดรถ → ค่าเดินทาง
   - บิลการไฟฟ้า การประปา หรือผู้ให้บริการโทรศัพท์ → หมวดของตัวเอง; แก๊สหุงต้ม → ค่าสาธารณูปโภค
   - วัตถุดิบเทียบกับเบ็ดเตล็ด: ของที่นำไปทำหรือขายต่อ → วัตถุดิบ
   - ค่าอาหารพนักงานเทียบกับค่ารับรอง (กติกาเดิม)
3. **ใบเสร็จผสม** (เช่น ห้างขายส่งที่มีทั้งวัตถุดิบและของใช้): AI เลือกหมวดของยอดส่วนใหญ่ แล้วติดธงให้แยกบรรทัดบนเว็บ ซึ่ง schema รองรับหมวดระดับบรรทัดอยู่แล้ว การให้ AI เลือกหมวดต่อบรรทัดอยู่นอกข้อเสนอนี้
4. **คงกติกาเดิม:**
   - เลือกได้เฉพาะหมวดที่เปิดใช้
   - ต้องมีหลักฐานเป็นข้อความจากใบเสร็จ
   - ไม่ชัดให้เว้นและให้คนเลือก
   - หมวดไม่ใช่เหตุผลในการตัดสิน VAT หรือบัญชีของโมเดล
5. **จำกัดรายการต่อร้าน:** ส่งเฉพาะชุดพื้นฐานกับชุดที่ร้านเลือก ไม่ส่งหมวดของทุกชุด
6. **วัดผลก่อนเปิดใช้:**
   - ชุดใบเสร็จติดป้ายหมวดอย่างน้อย 60 ใบ ใช้ภาพจริงที่ได้รับอนุญาตร่วมกับภาพสังเคราะห์ ครอบคลุมทุกหมวดใหม่และทุกคู่ที่สับสน
   - เกณฑ์: ความถูกต้องของหมวดบนใบชุดเดียวกันไม่ต่ำกว่า V1, สัดส่วนที่ตกเบ็ดเตล็ดลดลง และไม่มีการเลือกหมวดนอกรายการ
   - ต้องผ่านสองรอบติดกันกับโมเดลจริง (กติกาเดียวกับโปรแกรมที่ปรึกษา)
   - ค่าทดสอบประมาณ 150–300 บาท

## 7. ความสัมพันธ์กับที่ปรึกษา

- **การแยกยอด** (`expense.get_breakdown`) และ **รายการผิดปกติ** (S4a) คมขึ้นเพราะวัตถุดิบ น้ำมัน และค่าไฟไม่ถูกกลืนในก้อนใหญ่
- **"ค่าน้ำมันเดือนนี้"** จะใช้การกรองหมวดตรง ๆ (`categoryName`) แทนการเดาจากชื่อร้าน
- **คำถามใหม่ที่ตอบได้:** "ต้นทุนวัตถุดิบเดือนนี้เท่าไหร่" และ "เดือนนี้ค่าไฟขึ้นไหม"
  - "กำไรขั้นต้นเท่าไหร่" ต้องใช้ยอดขาย จึงอยู่ในกลุ่มอนาคตของสเปกที่ปรึกษา (§4.12) จนกว่าโมดูลยอดขายเปิดใช้ ไม่มีคำชวนซื้อหรืออัปเกรด
- **ความพร้อมภาษี** (S4b) ได้ประโยชน์จาก B8–B10 ที่มีภาษีชัด
- **การเทียบข้ามวันที่เพิ่มหมวด** ต้องบอกข้อจำกัด (§5.3)

## 9. คำถามให้ Owner ตัดสิน

1. **อนุมัติชุดพื้นฐาน B1–B10 ทั้งหมดหรือบางข้อ** แนะนำให้อนุมัติ B1–B7 และ B10 ก่อน (บัญชีชัด) ส่วน B8–B9 รอนักบัญชีเลือกบัญชี
2. **ชุดตามประเภทธุรกิจ:** จะทำไหม ชุดไหนก่อน และถามตอนสมัครหรือให้เลือกในหน้าหมวดภายหลัง แนะนำให้ทำคาเฟ่/ร้านอาหารก่อน และให้เลือกได้ทั้งสองจุด
3. **ร้านที่มีอยู่แล้ว:** เพิ่มชุดพื้นฐานให้อัตโนมัติ หรือให้ร้านกดเพิ่มเอง แนะนำเพิ่มให้อัตโนมัติ ส่วนชุดธุรกิจให้ร้านกดเอง
4. **วัตถุดิบลงบัญชีต้นทุนสินค้า** (5130-01 ซื้อ) แยกจากค่าใช้จ่ายดำเนินงาน เพื่อให้พร้อมคำนวณกำไรขั้นต้นเมื่อโมดูลยอดขายเปิดใช้ ขอให้ยืนยันกับนักบัญชี และเมื่อโมดูลสต็อกเปิดใช้ต้องทบทวนอีกครั้ง
5. **หมวดที่ผังยังไม่มีบัญชีตรง** (ประกันภัย, ภาษีและค่าธรรมเนียมราชการ, ค่าเช่าอุปกรณ์, ค่าจ้างรายวัน, ผู้รับเหมาช่วง): ผูกกับบัญชีที่ใกล้ที่สุดก่อน หรือเพิ่มบัญชีในผังรุ่นใหม่
6. **เพิ่มค่าเริ่มต้นอัตราหัก ณ ที่จ่ายต่อหมวดไหม** (ต้องเพิ่มข้อมูลในตารางหมวด วันนี้ตัดสินรายรายการ)
7. **เกณฑ์ราคาที่ควรบันทึกเป็นสินทรัพย์** (เช่น 5,000 หรือ 10,000 บาทต่อชิ้น) โดยระบบแค่เตือนและไม่บังคับ
8. **ใครเป็นนักบัญชีที่ตรวจตารางภาษีก่อนเปิดใช้** (จำเป็นต้องมี)
9. **หมวดที่ร้านตั้งชื่อเองยังลงบัญชีไม่ได้** เพราะไม่มีหน้าผูกบัญชี จะเปิดหน้าผูกบัญชีให้ร้าน หรือให้ทีมงานผูกให้
