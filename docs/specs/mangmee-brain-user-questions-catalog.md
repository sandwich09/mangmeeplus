# คำถามผู้ประกอบการ และคำตอบที่อยากเห็น — Mangmee Brain

สถานะ: **DRAFT v1 (2026-08-26)** — ตอบโจทย์ Owner: "user จะถามและต้องการคำตอบยังไง ในมุมของคนไม่เข้าใจเทคโนโลยี และเป็นผู้ประกอบการต้องการอยากจะรู้อะไร อยากเห็นอะไร"

ใช้คู่กับ [mangmee-brain-real-answers-spec](mangmee-brain-real-answers-spec.md) (รูปแบบคำตอบตาม §0.3) และเป็นแหล่งข้อมูลสำหรับ (1) phrasing golden set ของ families (2) พิมพ์เขียว golden set หมวดรายจ่าย 30 ใบ (`scripts/expense-category.golden.ts`)

## 1. ผู้ใช้ของเราคือใคร และเขาอยากรู้อะไรจริง ๆ

เจ้าของกิจการเล็ก อายุ 40+ ไม่ถนัดเทคโนโลยี เปิด LINE เป็นหลัก คำถามในหัวเขาไม่ใช่ศัพท์บัญชี แต่คือ:

| คำถามในใจ | แปลว่าเขาอยากเห็น |
|---|---|
| "เดือนนี้จ่ายอะไรไปเยอะ" | ยอดรวมก้อนเดียวก่อน แล้วค่อยบอกหมวดที่กินเงินสุด 2–3 หมวด |
| "วันนี้ใช้เงินไปเท่าไหร่แล้ว" | ตัวเลขวันนี้ทันที ไม่ต้องรอเปิดรายงาน |
| "บิลที่ถ่ายไป ลงให้หรือยัง" | จำนวนที่บันทึกแล้ว/รอตรวจ พร้อมทางกดไปดู |
| "มีอะไรค้างจ่ายไหม เดี๋ยวโดนทวง" | ยอดค้างจ่าย + ใกล้ครบกำหนด |
| "ตกลงเดือนนี้หนักกว่าเดือนที่แล้วไหม" | เทียบกับช่วงก่อนแบบสั้น ๆ (ทำได้เมื่อข้อมูลมี — ห้ามเดา) |

หลักการคำตอบ (จาก spec §0.3 แปลเป็นภาษาปฏิบัติ):

1. **ตัวเลขคำตอบขึ้นก่อนเสมอ** — บรรทัดแรกต้องตอบคำถาม ไม่ใช่เกริ่น
2. **ภาษาบ้าน** — "จ่ายไป", "ยังไม่ได้จ่าย", "รอตรวจ"; ห้ามคำว่า status/pending/document type/confidence
3. **บอกช่วงเวลาชัดทุกครั้ง** — "เดือน ส.ค. 69 (1–26 ส.ค.)" กันเข้าใจผิดว่ารวมทั้งเดือน
4. **บอกที่มาแบบคนฟังรู้เรื่อง** — "จากรายการที่บันทึกในระบบถึงวันนี้ 14:30" ไม่ใช่ asOf timestamp ดิบ
5. **ปิดด้วยทางไปต่อหนึ่งทาง** — ลิงก์เปิดหน้ารายการ หรือชวนถามต่อ 1 อย่าง ไม่ใช่เมนูยาว
6. **ตัวเลขทุกตัวมาจากระบบเท่านั้น** — ไม่มีข้อมูล = บอกตรง ๆ ว่ายังไม่มี ไม่ประมาณให้
7. **สั้นพอดีจอมือถือ** — ยอดหลัก + หมวด top 3 + ลิงก์ จบ; รายละเอียดอยู่หลังลิงก์

## 2. สามคำถามหลัก: วิธีถามจริง + คำตอบที่อยากเห็น

### Q1 — สรุปค่าใช้จ่าย (family F1: `expense.list_recent`, default เดือนนี้)

วิธีที่คนจริงพิมพ์ (สำหรับ phrasing golden set — เก็บทั้งแบบสั้น ติดกัน สะกดผิด):

```text
สรุปค่าใช้จ่าย / สรุปค่าใช้จ่ายหน่อย / ค่าใช้จ่ายเดือนนี้ / เดือนนี้จ่ายไปเท่าไหร่
เดือนนี้ใช้เงินไปเท่าไร / รายจ่ายเดือนนี้ / จ่ายอะไรไปบ้างเดือนนี้ / ขอดูรายจ่าย
ค่าใช้จ่ายล่าสุด / สรุปรายจ่ายให้หน่อย / เดือนนี้หมดไปกับอะไร / ยอดใช้จ่ายเดือนนี้
expense summary / how much did we spend this month
```

คำตอบที่อยากเห็น (โครงตายตัว ตัวเลขจาก tool เท่านั้น):

```text
ค่าใช้จ่ายเดือน ส.ค. 69 (1–26 ส.ค.) รวม 113,447.60 บาท จาก 191 รายการ
จ่ายแล้ว 855.99 บาท · ยังไม่ได้จ่าย 112,591.61 บาท
ดูรายการทั้งหมด → [ลิงก์หน้า รายการค่าใช้จ่าย]
(จากรายการที่บันทึกในระบบ ถึง 26 ส.ค. 14:30)
```

ห้าม: โชว์รายการยาวเป็นสิบบรรทัดใน LINE, คำว่า "READY_FOR_CONFIRMATION", เดายอดที่ tool ไม่ได้คืน

### Q2 — สรุปรายการเดือนนี้ (family F2: `accounting.get_summary::list`)

วิธีที่คนจริงพิมพ์:

```text
สรุปรายการเดือนนี้ / เดือนนี้มีรายการอะไรบ้าง / สรุปเอกสารเดือนนี้ / มีบิลกี่ใบเดือนนี้
รายการเดือนนี้ / สรุปให้หน่อยเดือนนี้ / เดือนนี้มีอะไรเข้ามาบ้าง / เอกสารเดือนนี้กี่รายการ
monthly summary / documents this month
```

คำตอบที่อยากเห็น (นับ+ยอดต่อประเภท เป็นภาษาคน):

```text
เดือน ส.ค. 69 มีเอกสารในระบบ 214 รายการ
• ใบเสร็จ/บิลค่าใช้จ่าย 191 รายการ — 113,447.60 บาท
• ใบแจ้งหนี้ 15 รายการ — 42,800.00 บาท
• ใบเสนอราคา 8 รายการ — 96,500.00 บาท
ดูทั้งหมด → [ลิงก์หน้าบัญชี]
(จากรายการที่บันทึกในระบบ ถึง 26 ส.ค. 14:30)
```

กติกาพิเศษ: ถ้าระบบรวมยอดได้ไม่ครบ (ช่วงใหญ่เกิน bound หรือ self-check ไม่ผ่าน) **ห้ามโชว์ตัวเลขบางส่วน** — บอกตรง ๆ ว่า "ช่วงนี้รายการเยอะมาก ขอให้ดูในหน้าเว็บแทน" พร้อมลิงก์ (ตรง G1/terminal rule ใน spec)

### Q3 — ค่าใช้จ่ายวันนี้ (F3 นิยามใหม่ตามการตัดสินใจ Owner 2026-08-26: รายงานฝั่งจ่ายก่อน ยังไม่แตะรายรับ)

Family: `expense.get_daily_closing` — **tool มีอยู่แล้ว** (สรุปค่าใช้จ่ายหนึ่งวัน: เกิดขึ้น จ่ายแล้ว ค้างจ่าย ครบกำหนด เกินกำหนด รอตรวจ) จึงไม่ต้องสร้าง tool ใหม่ ไม่ต้องรอนิยามเงินเข้า; คำถามฝั่ง "เงินเข้าวันนี้" จะกลับมาเป็น family ใหม่เมื่อฝั่งรายรับเปิด (หลัง P26)

วิธีที่คนจริงพิมพ์:

```text
วันนี้ใช้เงินไปเท่าไหร่ / ค่าใช้จ่ายวันนี้ / วันนี้จ่ายอะไรไปบ้าง / วันนี้จ่ายไปกี่บาท
สรุปวันนี้ / วันนี้มีบิลอะไรบ้าง / รายจ่ายวันนี้ / today expenses
เมื่อวานจ่ายไปเท่าไหร่ (ระบุวันได้)
```

คำตอบที่อยากเห็น:

```text
วันนี้ (26 ส.ค.) มีค่าใช้จ่าย 3 รายการ รวม 2,450.00 บาท
จ่ายแล้ว 1,200.00 บาท · ยังไม่ได้จ่าย 1,250.00 บาท
มี 1 รายการรอตรวจหลักฐาน
ดูของวันนี้ → [ลิงก์]
(จากรายการที่บันทึกในระบบ ถึง 14:30 — ไม่ใช่ยอดเงินเข้าออกธนาคาร)
```

บรรทัดสุดท้ายสำคัญ: ผู้ใช้บางคนจะเข้าใจว่า "วันนี้ใช้เงิน" = เงินออกจากบัญชีธนาคาร — ต้องบอกแหล่งชัดว่าเป็นรายการที่บันทึก (กติกา G5 เดิม ใช้กับฝั่งจ่ายเหมือนกัน)

### คำถามที่ระบบยังตอบไม่ได้ — ต้องปฏิเสธแบบมีทางไป

"เงินเข้าวันนี้เท่าไร / ขายได้เท่าไรวันนี้ (ฝั่งรับ) / กำไรเดือนนี้เท่าไร / เดือนหน้าจะพอไหม" → ตอบตามแบบ: บอกว่ายังไม่รองรับ + บอกสิ่งที่ทำได้ใกล้เคียง 1 อย่าง + ไม่เดาตัวเลขเด็ดขาด เช่น "ตอนนี้มั่งมียังสรุปฝั่งเงินเข้าไม่ได้ค่ะ แต่ดูยอดขายช่วงนี้ได้นะคะ ลองพิมพ์ 'ยอดขายเดือนนี้'"

## 3. พิมพ์เขียว Golden set หมวดรายจ่าย 30 ใบ (ให้ Owner เก็บใบจริงตามช่อง)

หลัก: กระจายตามหมวดที่ SME ไทยเจอบ่อยจริง + เอกสารหลากชนิด (ใบกำกับเต็ม/ย่อ, สลิป POS, บิลเงินสดเขียนมือ) + มีช่อง "ต้อง omit" เพื่อวัดว่าระบบไม่เดา; เฉลยทุกใบ Owner/นักบัญชียืนยัน (spec §10.3); ข้อความ OCR ต้อง sanitize ตาม G7

| ช่อง | หมวดเฉลย | ตัวอย่างใบจริงที่หาได้ | จุดที่ทดสอบ |
|---|---|---|---|
| 1–4 | ค่าอาหารและเครื่องดื่ม | ร้านกาแฟ (สลิป POS), ร้านอาหารเลี้ยงลูกค้า (ใบกำกับย่อ), 7-Eleven ซื้อน้ำ/ขนม, ร้านข้าวแกงบิลเงินสดเขียนมือ | สลิปสั้น, ลายมือ, ร้านสะดวกซื้อที่ item ปนหลายหมวด |
| 5–8 | ค่าเดินทาง | ปตท./บางจาก เติมน้ำมัน (ใบกำกับย่อ), Grab/แท็กซี่, ทางด่วน Easy Pass, ตั๋วเครื่องบิน/รถทัวร์ | ชื่อผู้ขายเป็นแบรนด์, ใบสั้นมาก, e-receipt |
| 9–11 | ค่าสาธารณูปโภค | การไฟฟ้า (MEA/PEA), การประปา, ค่าเน็ต/มือถือ (True/AIS) | เอกสาร format ราชการ/บริษัทใหญ่, เลขอ้างอิงเยอะ |
| 12–14 | วัสดุ/อุปกรณ์สำนักงาน | Makro/Lotus ซื้อของใช้ร้าน, ร้านเครื่องเขียน, Shopee/Lazada ใบกำกับอิเล็กทรอนิกส์ | ใบยาวหลาย item, e-tax invoice |
| 15–16 | ค่าซอฟต์แวร์/บริการ | ค่าบริการรายเดือน (เช่น โปรแกรมบัญชี/POS), Google/Meta invoice ภาษาอังกฤษ | ภาษาอังกฤษล้วน, service ไม่มี VAT ไทย |
| 17–18 | ค่าโฆษณาและการตลาด | Facebook Ads receipt, ค่าทำป้าย/สื่อสิ่งพิมพ์ | ใบ FB (อังกฤษ, USD/THB), ร้านป้ายบิลเงินสด |
| 19–20 | ค่าซ่อมแซม | อู่ซ่อมรถ/เปลี่ยนยาง, ช่างซ่อมแอร์/ประปา บิลเงินสด | ลายมือ + รายการอะไหล่ปน ค่าแรง |
| 21–22 | ค่าเช่า | ใบเสร็จค่าเช่าร้าน/ออฟฟิศรายเดือน | เอกสารซ้ำทุกเดือน, ผู้ให้เช่าบุคคลธรรมดา (ไม่มี VAT) |
| 23–24 | ค่าวิชาชีพ | บิลสำนักงานบัญชี, ค่าทนาย/ที่ปรึกษา | หัก ณ ที่จ่าย 3% ปรากฏบนใบ |
| 25–26 | ค่าขนส่ง | Kerry/Flash/ไปรษณีย์ไทย ส่งของให้ลูกค้า | ใบเสร็จหลายรายการย่อย, COD ปน |
| 27 | หมวดผสมในใบเดียว | Makro: ของใช้ร้าน + อาหาร ในใบเดียว | ทดสอบกติกา "เลือก 1 หมวดทั้งเอกสารจาก item เด่น" ของ prompt |
| 28 | **expected omit** | ใบเสร็จที่หมวดกำกวมจริง (เช่น ร้านของชำ ซื้อปนทุกอย่าง ไม่มี item ชัด) | ระบบต้องไม่เดา → omit + missingFields "category" |
| 29 | **expected omit** | catalogue บริษัทไม่มีหมวดที่ตรง (เช่น ค่าซื้อเครื่องจักร แต่ catalogue มีแต่หมวดจิปาถะ) | omit เมื่อไม่มีหมวดรองรับ |
| 30 | **expected omit** | เอกสารที่ไม่ใช่ค่าใช้จ่าย (ใบเช็กบิล/ใบแจ้งยอดที่ยังไม่จ่าย) หลุดเข้ามา | ห้ามจับหมวดมั่ว — สอดคล้อง DOC-01 ของแผนหลัก |

การกระจายนี้สะท้อน distribution จริง (อาหาร/เดินทาง/ของใช้ = ก้อนใหญ่ของ SME) และบังคับ edge ครบ: ลายมือ, อังกฤษ, e-tax, WHT บนใบ, ร้านหมวดปน, 3 ช่อง omit (10% — วัดความไม่เดา)

วิธีใช้กับ harness ที่มีแล้ว: เก็บใบจริงตามช่อง → ใช้ข้อความ OCR (ไม่ต้องใช้รูป) → mask เลขภาษี/เบอร์/ชื่อลูกค้า → วางเป็น fixture ใน `scripts/expense-category.golden.ts` พร้อม `expectedCategoryId` จาก catalogue จริงของบริษัทนำร่อง → Owner/นักบัญชีติ๊ก `ownerConfirmed: true` → ครบ 30 = `baselineReady` เปิดวัด baseline อัตโนมัติ

## 4. เกณฑ์ "คำตอบดี" ที่ใช้ตรวจงานทุก family (สำหรับ blind eval)

ผู้ให้คะแนน (ไม่ใช่คนเขียนโค้ด) ตอบ 4 ข้อต่อคำตอบ: (1) อ่านบรรทัดแรกแล้วได้คำตอบเลยไหม (2) มีคำที่คนไม่ใช้เทคโนโลยีไม่เข้าใจไหม (3) รู้ไหมว่าตัวเลขนี้ของช่วงไหน/มาจากไหน (4) รู้ไหมว่าต้องทำอะไรต่อ — ผ่านเมื่อ yes/no/yes/yes ครบ
