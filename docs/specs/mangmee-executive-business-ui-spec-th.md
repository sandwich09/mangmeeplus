## แก้ไขหลังการตรวจทานอิสระ 2026-10-01

เอกสารนี้แก้ตามข้อค้นพบ RU-01–RU-30 เพื่อให้เอกสารฝั่งหน้าจอทุกฉบับพูดตรงกัน รอบนี้แก้เอกสารเท่านั้น ไม่แก้โค้ดแอปและไม่แก้ต้นแบบ
ต้นแบบยังเป็นรุ่นก่อนแก้ จุดที่ต้นแบบไม่ตรงกับเอกสารนี้อยู่ในรายการข้อบกพร่องของต้นแบบ (PD) และห้ามใช้ต้นแบบเป็นเกณฑ์แทนเอกสาร

### ข้อเสนอที่รอเจ้าของยืนยัน

เอกสารฝั่งหน้าจอทุกฉบับเขียนตามคอลัมน์ “เอกสารเขียนตามนี้” ทุกจุดที่ใช้ข้อเสนอจะมีคำว่า **ข้อเสนอ รอเจ้าของยืนยัน** พร้อมรหัส D กำกับ ถ้าเจ้าของเลือกอีกทาง ให้แก้เฉพาะจุดที่มีรหัส D นั้น

| รหัส | คำถามถึงเจ้าของ | เอกสารเขียนตามนี้ (ข้อเสนอ) | ถ้าเลือกอีกทาง |
|---|---|---|---|
| D1 (RU-03) | ระบบยังไม่มีรหัสลูกค้าแบบสั้นที่อ่านได้ มีแต่รหัสภายในยาว 25 ตัวอักษร จะให้แสดงรหัสหรือไม่ | ไม่แสดงรหัสเลย ทั้งหน้าจอและไฟล์ แยกชื่อซ้ำด้วยชื่อจดทะเบียน จังหวัด และวันที่สมัคร | สร้างรหัสลูกค้าแบบสั้น: ต้องเพิ่มช่องในข้อมูลบริษัท ออกรหัสให้บริษัทเดิมทุกราย แล้วเพิ่มกลับใน §4, §6, §8 และไฟล์ Excel |
| D2 (RU-06) | ใช้เมนูใหม่หกรายการแทนหน้า “วิเคราะห์” หน้าเดียว และตัดกล่อง “บริษัทที่ควรติดตาม” ใช่ไหม | ใช่ ตาม §3, §5, §7 | กลับไปหน้าเดียว: แก้ §3, §5, §7 และเอกสารโครงหน้าทั้งฉบับ และกลับไปเลื่อนยาวแบบที่เจ้าของทักไว้ |
| D3 (RU-12) | เปิดหน้ารายงานครั้งแรกให้แสดงเดือนไหน | เดือนปัจจุบัน พร้อมป้าย “เดือนนี้ยังไม่จบ” และปุ่ม “ดูเดือนที่แล้ว” (§4.1) | เดือนล่าสุดที่จบแล้ว: แก้ค่าเริ่มต้นหนึ่งบรรทัดใน §4.1 แต่ต้องเลือกเดือนเองทุกครั้งที่จะดูเดือนปัจจุบัน |
| D4 (RU-15) | “ลูกค้าที่สร้างรายรับสูง” นับเงินช่วงไหน และเมื่อหลายบริษัทจ่ายเท่ากันตรงขอบกลุ่มทำอย่างไร | นับเฉพาะเดือนที่เลือกและเขียน “ในเดือน” ให้เห็น; คงจำนวนตาม 20% แล้วบอกว่ามีรายอื่นจ่ายเท่ากัน (เอกสารกราฟและอันดับ §5) | นับ 12 เดือนล่าสุด: ต้องมีเงินรับรายเดือนย้อนหลังครบ 12 เดือนก่อนเปิดหน้านี้ (RB-02) / รวมทุกรายที่จ่ายเท่ากัน: กลุ่มอาจใหญ่กว่า 20% ต้องเปลี่ยนคำเรียกกลุ่ม |
| D5 (RU-19) | ผู้บริหารที่ดูรายงานได้ทุกคนควรเห็นอีเมลและเบอร์โทรเจ้าของร้านไหม | เห็นเฉพาะผู้ที่ได้รับสิทธิ์ “ส่งออก Excel และดูข้อมูลติดต่อเจ้าของร้าน” (§8.1, §9.2) | ทุกคนเห็น: ลบเงื่อนไขสิทธิ์ใน §8.1 หนึ่งจุด แต่ข้อมูลส่วนบุคคลจะเปิดให้ผู้ดูรายงานทุกคน (RB-10) / แยกเป็นสองสิทธิ์: เพิ่มช่องติ๊กอีกหนึ่งช่องและสิทธิ์อีกหนึ่งตัวในสเปกหลังบ้าน |
| D6 (RU-20) | ผู้บริหารที่ดูรายงานได้ ส่งออก Excel ได้ทุกคนเลย หรือเปิดเป็นรายคน | เปิดเป็นรายคน ค่าเริ่มต้นปิด ตั้งที่หน้าบัญชีผู้บริหาร (§9.2) | ทุกคนส่งออกได้: ลบช่องติ๊กใน §9.2 และถือว่าผู้ดูรายงานทุกคนมีสิทธิ์นี้ |
| D7 (RU-27) | หน้าผู้บริหารต้องมีภาษาอังกฤษด้วยไหม | รุ่นแรกไทยอย่างเดียว เหมือนหน้าผู้ดูแลระบบเดิม (§11.4) | สองภาษา: ต้องเขียนข้อความอังกฤษของทุกจุดลงเอกสารคำบนหน้าจอก่อน และทำข้อความทุกจุดสองชุด |

|---|---|---|---|

| RB-06 | สร้างบัญชีผู้บริหารแบบเดียวกับบัญชีเซลล์ คือกำหนดชื่อผู้ใช้ ระบบออกรหัสผ่านชั่วคราวให้ส่งต่อ และผู้บริหารตั้งรหัสใหม่ตอนเข้าครั้งแรก ใช่ไหม | ใช่ (§9.2) | เชิญทางอีเมล: เปลี่ยนช่องกรอกเป็นชื่อกับอีเมล เพิ่มสถานะ “รอเปิดใช้งาน” และต้องมีระบบส่งอีเมลที่พร้อมใช้ก่อน |
| RB-07 | ผู้บริหารแต่ละคนใช้บัญชีแยกสำหรับดูรายงาน ไม่ใช้บัญชีเดียวกับร้านของตัวเอง ได้ไหม | ได้ (§3.1, §9.2) | ใช้บัญชีเดิม: ต้องมีตัวเลือกสลับบริบทใน shell และกติกาเมื่อชื่อผู้ใช้หรืออีเมลเป็นบัญชีที่มีอยู่ ซึ่งกระทบระบบเข้าสู่ระบบของผู้ใช้ทุกคน |

## 1. เป้าหมายและขอบเขตที่ผู้ใช้ยืนยัน

ผู้บริหารของ **แพลตฟอร์มมั่งมี** ต้องดูภาพรวมธุรกิจ ดูบริษัทลูกค้าแยกเป็นรายบริษัท
และเปรียบเทียบกลุ่มบริษัทได้ โดยต้องเห็นทั้ง **รู้จักมั่งมีจากไหน** และ **เซลล์ผู้แนะนำ**
ฟีเจอร์คำขอลบข้อมูลพักไว้และซ่อนทั้งหมดตามมติล่าสุด

เส้นทางหลัก: ภาพรวม → เลือกกลุ่มธุรกิจ/ช่องทาง/เซลล์ → รายชื่อบริษัท → รายละเอียดบริษัท
→ ประวัติบริษัท โดยกลับมาที่ตัวกรองเดิมได้

ข้อกำหนดเพิ่มเติมจากผู้ใช้: **ใช้ธีมเดิมทั้งหน้า โดยเฉพาะ dropdown และ input ทุกชนิดห้ามหลุดธีม**
รอบนี้ส่งมอบเอกสารและต้นแบบ โดย reuse controls/theme ของ repo ไม่เปลี่ยน application code
ผู้ใช้ปัจจุบันคือ Owner และผู้บริหารรวม 4 คน ต้องมีหน้าสร้างบัญชีใน admin console
จำนวน 4 คนไม่ใช่เพดานบัญชี และไม่ใช่การให้สิทธิ์ System Admin แก่ทุกคน

- บัญชีที่ไม่ใช่ผู้ดูแลระบบไม่เห็นกลุ่ม “ลูกค้า”, “คำขอและการติดต่อ” (รวม “คำขอเกี่ยวกับข้อมูล”) และรายการอื่นของ “ตั้งค่าระบบ” และไม่เรียกตัวนับคำขอความช่วยเหลือ
- เมนูสร้างจากความสามารถที่หลังบ้านคืนให้บัญชีนั้น (ดูรายงาน จัดการบัญชี) ไม่เดาจากชื่อบทบาท
- มือถือใช้ปุ่ม “เมนู” แบบพับได้เดิมของ shell ไม่ทำเมนูเป็น dropdown และไม่ทำแถบเมนูแนวนอนยาว (ตามที่ Owner ยืนยันไว้ใน [System UI Alignment](mangmee-system-ui-alignment-spec.md))
- ผู้ที่ไม่มีสิทธิ์เข้าส่วนใดของ `/system` เห็นหน้า `SystemAccessDenied` เดิม ผู้ที่เข้า shell ได้แต่ไม่มีสิทธิ์หน้านั้นเห็น `ForbiddenState` ภายใน shell
- ลิงก์จากรายละเอียดบริษัทไปหน้า `/system/partners/[companyId]` แสดงเฉพาะผู้ดูแลระบบ
- เมนู “คำขอเกี่ยวกับข้อมูล” เดิมยังแสดงให้ผู้ดูแลระบบตามเดิม เพราะการซ่อนรอบนี้ไม่แตะโมดูลเดิม
- ประตูเข้า หน้าแรกหลังเข้าระบบ และคำถามว่าผู้ดูแลระบบได้สิทธิ์ดูรายงานโดยอัตโนมัติหรือไม่ ขึ้นกับสเปกหลังบ้าน (RU-07 → RB-24, RB-07, RB-05)
- **ข้อเสนอของฝั่งหลังบ้าน รอเจ้าของยืนยัน — RB-05:** รุ่นแรกไม่มีบทบาท “ผู้จัดการบัญชีผู้บริหาร” แยก ผู้ดูแลระบบคนเดียวเป็นผู้สร้างและระงับบัญชี และดูรายงานกับส่งออกได้ ถ้ายืนยัน แถวที่สองและสามของตารางข้างบนไม่เกิดขึ้นในรุ่นแรก เหลือสามแบบ: ผู้บริหาร ผู้ดูแลระบบ และผู้ถือสิทธิ์การชำระเงินอย่างเดียว กติกา “เมนูสร้างจากความสามารถ” ทำให้ไม่ต้องแก้หน้าจอไม่ว่าคำตอบเป็นทางใด
- บัญชีผู้บริหารเป็นบัญชีแยกที่อยู่กับฝั่งแพลตฟอร์มเท่านั้น ไม่มีร้านของตัวเอง จึงไม่มีตัวเลือกสลับบริษัทใน shell (**ข้อเสนอของฝั่งหลังบ้าน รอเจ้าของยืนยัน — RB-07**)

### 3.2 สถานะของหน้าใน URL

ทุกอย่างที่ทำให้หน้าแสดงต่างกันอยู่ใน URL โหลดใหม่ เปิดลิงก์ตรง และปุ่ม Back ของเบราว์เซอร์ต้องได้หน้าเดิม ไม่เก็บสถานะรายงานใน localStorage
ใช้รูปแบบพารามิเตอร์ของตัวช่วยเดิม `apps/web/src/common/functions/list-query.ts` (`page`, `sortBy`, `sortDir`, `filter_<ชื่อ>`)

| กลุ่ม | พารามิเตอร์ | หน้าที่ใช้ |
|---|---|---|
| บริบทรายงาน | `month` (ค.ศ. เช่น `2026-09`), `filter_industry`, `filter_discovery`, `filter_sales` | ทุกหน้ารายงาน EX-01 ถึง EX-04 เก็บไว้ใน URL เสมอ |
| แท็บและมุมมอง | `view` (ชื่อแท็บ), `rank` (ใบเสร็จ / วันใช้งาน / ใช้ผู้ช่วย), `group` (ธุรกิจ / รูปแบบกิจการ), `seller` (ผู้แนะนำ / ยอดขายครั้งแรก) | EX-03A, EX-03B, EX-03C |
| เปรียบเทียบ | `by` (มิติ), `a`, `b` | EX-03D |
| เฉพาะรายชื่อ | `filter_entity`, `filter_companyStatus`, `filter_serviceStatus`, `filter_usage`, `filter_receipt`, `filter_spend`, `sortBy`, `sortDir`, `page`, `pick`, `from` | EX-02 |
| รายละเอียด | บริษัทอยู่ใน path; `tab` | EX-04 |
| แผงส่งออก | `export=1` | ทุกหน้าที่ส่งออกได้ |

- ค่าใน URL เป็นค่าคงที่ที่ระบบกำหนด ไม่ใช่ข้อความที่แสดง ค่าที่ไม่รู้จักหรือไม่มี ให้ใช้ค่าเริ่มต้นของหน้านั้นโดยไม่ขึ้นข้อผิดพลาด
- ลิงก์เมนูทุกรายการในกลุ่ม “รายงานผู้บริหาร” พา **บริบทรายงาน** ไปด้วยเสมอ และไม่พาพารามิเตอร์กลุ่มอื่น ตัวกรองร่วมของผู้ใช้จึงไม่หายเมื่อเปลี่ยนหน้า
- หน้าที่ไม่ใช้ตัวกรองร่วม (EX-03D ใช้เฉพาะ `month`; EX-04 ใช้เฉพาะ `month`) ยังเก็บบริบทรายงานไว้ใน URL และบอกบนจอว่าหน้านี้ไม่ใช้ตัวกรอง
- คำค้นบริษัทไม่ใส่ใน URL เพราะชื่อร้านของบุคคลธรรมดาเป็นข้อมูลส่วนบุคคล ให้เก็บไว้กับประวัติหน้าของเบราว์เซอร์เพื่อให้ Back คืนคำค้นเดิมได้ คำค้นตัดช่องว่างหัวท้าย ยาวไม่เกิน 120 ตัวอักษร และส่งค้นเมื่อหยุดพิมพ์ 300 มิลลิวินาที
- การแบ่งหน้าใช้เลขหน้า (`page` เริ่มที่ 1) หน้าละ 25 รายการ ด้วย component `Pagination` เดิม เลขหน้าที่เกินให้แสดงหน้าสุดท้าย เปลี่ยนตัวกรอง การเรียง หรือกลุ่มแล้วกลับไปหน้า 1
- ชื่อและค่าของพารามิเตอร์ที่ส่งถึงหลังบ้านยึดตารางพารามิเตอร์ของสเปกหลังบ้านเมื่อรวมเป็นตารางเดียวแล้ว (RU-05 → RB-18) ตารางข้างบนกำหนดว่าหน้าจอต้องมีสถานะใดบ้าง

### 3.3 การกดเจาะและการกลับ

- การกดจากกราฟ ตาราง หรือการ์ดไปหน้ารายชื่อ เป็นการไปหน้าใหม่ **ไม่เขียนทับตัวกรองของหน้าต้นทาง**
- รายชื่อที่เปิดจากการกดใช้: บริบทรายงานเดิม + เงื่อนไขของสิ่งที่กด + `from` (หน้าต้นทาง)
  - กดกลุ่มของมิติที่เป็นตัวกรองร่วม (ธุรกิจ ช่องทาง เซลล์) เงื่อนไขอยู่ใน `pick` เช่น `pick=discovery:FACEBOOK` ไม่เปลี่ยน `filter_discovery`
  - กดกลุ่มอื่น (รูปแบบกิจการ การชำระและใช้งาน ประวัติเพิ่มใบเสร็จ กลุ่มลูกค้าตามยอดจ่าย อันดับ) เงื่อนไขอยู่ในตัวกรองเฉพาะรายชื่อของกลุ่มนั้น และตัวกรองเฉพาะรายชื่ออื่นเริ่มจากค่าเริ่มต้น
  - กดจากหน้าเปรียบเทียบ (`from=compare`) รายชื่อใช้เฉพาะ `month` กับ `pick` ของฝั่งนั้น ไม่ใช้ตัวกรองร่วม และบอกบนจอว่า “รายชื่อนี้มาจากหน้าเปรียบเทียบ ไม่ใช้ตัวกรองของรายงาน”
- รายชื่อแสดงเงื่อนไขที่กดมาเป็นป้ายที่ลบได้ และแสดงจำนวนของฐานที่ใช้คำนวณ
- ปุ่ม “← กลับ<ชื่อหน้าต้นทาง>” ใช้ประวัติหน้าของเบราว์เซอร์ จึงได้หน้าต้นทางพร้อมเดือน ตัวกรอง แท็บ และตำแหน่งเดิมทุกค่า ถ้าเปิดรายชื่อจากลิงก์ตรงและไม่มีประวัติ ปุ่มนี้พาไปหน้าตาม `from` พร้อมบริบทรายงานเดิม
- จากรายละเอียดบริษัท ปุ่มกลับคืนรายชื่อหน้าเดิม ทั้งเลขหน้า การเรียง ตัวกรอง และคำค้น
- เกณฑ์ตรวจ: จำนวนแถวและค่าการ์ดของหน้าต้นทางก่อนกดกับหลังกลับต้องเท่ากัน โดยไม่ต้องกด “ล้างตัวกรอง” และตัวกรองร่วมที่ผู้ใช้ตั้งไว้ต้องยังอยู่หลังไปหน้าเปรียบเทียบ ดูรายชื่อฝั่งใดฝั่งหนึ่ง แล้วไปหน้าอื่นทางเมนู

- “ล้างตัวกรอง” แสดงเมื่อมีเงื่อนไขอย่างน้อยหนึ่งข้อ; เก็บเดือนที่เลือกไว้ และล้างกลุ่ม/ช่องทาง/เซลล์/ตัวกรองเฉพาะรายชื่อ/คำค้น
- หัวตาราง กราฟ การ์ดตัวเลข และจำนวนรายการต้องสื่อขอบเขตเดียวกัน จำนวนรวมไม่ใช่จำนวนเฉพาะหน้าของ pagination

### 4.1 เวลาของข้อมูล และเดือนที่ยังไม่จบ

- เดือนที่แสดงเมื่อเปิดครั้งแรกคือเดือนปัจจุบันตามเวลาไทย (**ข้อเสนอ รอเจ้าของยืนยัน — D3**)
- แถวเวลาแสดงวันและเวลาไทยถึงนาที เช่น “ข้อมูลถึง 30 ก.ย. 2569 12:00 น.” โดยใช้เวลาที่เก่าที่สุดของแหล่งข้อมูลที่หน้านั้นใช้ ไม่ใช่เวลาที่เปิดหน้า
- ถ้าแหล่งใดช้ากว่าแหล่งอื่นเกิน 24 ชั่วโมง ให้มีป้ายที่การ์ดของแหล่งนั้น เช่น “ข้อมูลเงินถึง 28 ก.ย. 2569”
- เดือนที่ยังไม่จบมีป้าย “เดือนนี้ยังไม่จบ” ข้างชื่อเดือน และที่แท่งสุดท้ายของกราฟแนวโน้มด้วยลายหรือป้าย ไม่ใช่สีอย่างเดียว พร้อมปุ่ม “ดูเดือนที่แล้ว”
- ข้อมูลบริษัท สถานะบริษัท สถานะบริการ แพ็กเกจ และข้อมูลติดต่อ เป็นค่าปัจจุบัน ไม่ใช่ค่าของเดือนที่เลือก ต้องมีคำว่า “ปัจจุบัน” ที่หัวคอลัมน์หรือหัวกล่อง
- วันที่สมัครแยกจากตัวเลขตามเดือน เดือนก่อนวันที่สมัครเป็นไปตาม §8.2 และ §11
- เมื่อชุดข้อมูลของรายงานที่หน้าจอใช้อยู่ถูกแทนด้วยชุดใหม่หรือใช้ไม่ได้แล้ว ให้โหลดการ์ดและตารางของหน้านั้นใหม่พร้อมกันหนึ่งครั้งโดยคงเดือน ตัวกรอง แท็บ และเลขหน้าเดิม พร้อมข้อความ “อัปเดตข้อมูลแล้ว ตัวเลขอาจเปลี่ยน” ห้ามแสดงการ์ดจากชุดหนึ่งกับตารางจากอีกชุด ยกเว้นการส่งออก ซึ่งให้ผู้ใช้กลับไปดูรายงานที่โหลดใหม่ก่อนสร้างไฟล์ (เอกสารส่งออก Excel §5)
- กติกาข้อก่อนหน้าไม่ขึ้นกับกลไกของหลังบ้าน ใช้ได้ทั้งแบบชุดข้อมูลที่มีอายุ (สเปกหลังบ้านฉบับเดิม) และแบบรอบสร้างข้อมูลตามเวลา (ข้อเสนอ RB-08) ถ้าเป็นแบบหลัง “ข้อมูลถึง” คือเวลาที่รอบล่าสุดสร้างสำเร็จ และแหล่งที่รอบนั้นอ่านไม่สำเร็จต้องมีป้ายเวลาของตัวเองแบบเดียวกับแหล่งที่ช้ากว่า
- เดือนที่จบแล้วซึ่งถูกคำนวณใหม่แล้วตัวเลขเปลี่ยน เช่น มีคืนเงินย้อนหลัง แสดงป้าย “ปรับปรุงเมื่อ <วันเวลา>” ข้างชื่อเดือน (**ข้อเสนอของฝั่งหลังบ้าน รอเจ้าของยืนยัน — RB-08**; ทางเลือกคือไม่เปลี่ยนตัวเลขของเดือนที่จบแล้ว ซึ่งไม่ต้องมีป้ายนี้ แต่ยอดคืนเงินย้อนหลังจะไม่ปรากฏในเดือนเดิม)

### 4.3 เงิน วันที่ ค่าที่ไม่มี และการปัดเศษ

- เงินทุกจุดแสดงเป็น “1,234.50 บาท”: คั่นหลักพัน ทศนิยม 2 ตำแหน่งเสมอ เว้นวรรคแล้วตามด้วยคำว่า บาท ห้ามใช้ ฿ หรือ THB
- ยอดติดลบแสดง “-1,234.50 บาท” พร้อมคำกำกับ เช่น “คืนเงินมากกว่าเงินรับ” ไม่ใช้สีอย่างเดียว
- ใช้ตัวจัดรูปแบบเงินตัวเดียวทั้งชุดหน้า รับจำนวนสตางค์เป็นจำนวนเต็ม แนวเดียวกับ `money()` ใน `apps/web/src/features/reimbursements/reimbursements.logic.ts` ไม่เขียนซ้ำรายหน้า และไม่ใช้ `formatBaht` ของหน้าทีมขายซึ่งคืน ฿
- วันที่ใช้ `formatThaiDate`, `formatThaiDateTime`, `formatThaiMonth` ใน `apps/web/src/common/i18n/thai-date.ts` ไม่แสดงเดือนแบบ `2026-09` หรือวันที่แบบ ISO
- ค่าที่ไม่มีข้อมูลแสดง — พร้อมเหตุผล ไม่ใช่ 0 หรือ 0.00 บาท ศูนย์ใช้เมื่อรู้ว่าเป็นศูนย์จริงเท่านั้น
- จำนวนนับที่ข้อมูลไม่ครบแสดง “อย่างน้อย N” เงินที่ข้อมูลไม่ครบแสดง “ยอดเฉพาะรายการที่ยืนยันแล้ว” ไม่ใช้คำว่า “อย่างน้อย” เพราะเงินคืนทำให้ยอดลดได้
- ค่าเฉลี่ยและเปอร์เซ็นต์คำนวณจากจำนวนเต็ม (สตางค์ และจำนวนบริษัท) แล้วปัดครึ่งขึ้น เปอร์เซ็นต์แสดงทศนิยม 1 ตำแหน่ง ใช้วิธีเดียวกันทั้งหน้าจอและไฟล์ Excel ถ้าเปอร์เซ็นต์ของกลุ่มที่รวมกันเป็นทั้งหมดรวมแล้วไม่ได้ 100.0 ให้มีหมายเหตุว่าเกิดจากการปัดเศษ
- ยอดเงินรวมภาษีมูลค่าเพิ่มหรือไม่ ต้องมีคำกำกับบนจอเมื่อสเปกหลังบ้านตัดสินข้อ Q04 แล้ว ก่อนนั้นใช้คำว่า “เงินที่ลูกค้าจ่ายให้มั่งมี” โดยไม่อ้างว่าเป็นรายได้ทางบัญชี

## 5. EX-01 — ภาพรวมธุรกิจ

หน้าภาพรวมเป็นจุดเริ่มสั้น ๆ ไม่มีตารางยาว กราฟแนวโน้ม หรือรายชื่อ 10 อันดับ (**ข้อเสนอ รอเจ้าของยืนยัน — D2**)

1. ชื่อ “ภาพรวมธุรกิจมั่งมี” และปุ่ม “ดูบริษัททั้งหมด”
2. แถวเวลาและตัวกรองร่วมตาม §4 และ §4.1
3. การ์ดตัวเลข 4 ใบ: บริษัทลูกค้า (N01), ใช้งานในเดือน (N02), ชำระในเดือน (N03), ยอดรับสุทธิในเดือน (N06) แต่ละใบมีบรรทัดอธิบายสั้นใต้ตัวเลข และกดเปิดรายชื่อที่มีจำนวนเท่ากันได้
4. กราฟสรุป “การเริ่มใช้ใบเสร็จ” (N08) พร้อมทางไปแท็บ “อันดับการใช้”
5. กล่อง “เรื่องที่ควรดูต่อ” 3 รายการ: จ่ายแล้ว ยังไม่เริ่มใช้ (จำนวน → รายชื่อ), เคยใช้ แต่ไม่ใช้ในเดือน (จำนวน → รายชื่อ), ลูกค้ากลุ่มไหนสร้างรายรับมาก (สัดส่วนของ N12 → แท็บ “ลูกค้าที่สร้างรายรับสูง”)

กล่อง “บริษัทที่ควรติดตาม” ของฉบับก่อนตัดออก เพราะยังไม่มีนิยามเหตุผลที่ตกลงกัน (D2) กราฟแนวโน้มย้ายไป EX-03B และตารางแยกประเภทธุรกิจย้ายไป EX-03C
การ์ดตัวเลขต้องมีคำอธิบายสั้นว่าเป็นจำนวนสะสมหรือกิจกรรมในเดือน สูตรและขอบเขตของแต่ละตัวใช้มติ B2–B4:
รวมบริษัทจริงทุกสถานะ แยกกรองได้ ไม่รวมทดสอบ/ภายใน; หนึ่งพื้นที่บริษัทนับหนึ่งบริษัท
การใช้งานนับการใช้ระบบจริง แยกจากการเข้าสู่ระบบ; ยอดรับคือเงินรับจากแพ็กเกจ ต่ออายุ และส่วนเสริมหักคืนเงิน
ค่าธรรมเนียม/ต้นทุนแสดงแยก ไม่ใช้ยอดขาย/กำไรของบริษัทลูกค้ามาแสดงเป็นรายได้ของมั่งมี
รายละเอียด event, cutoff, refund และแหล่งยืนยัน test/internal ยังรอ backend contract
ไม่สร้างคะแนนสุขภาพหรือเกณฑ์น้อย/กลาง/มากขึ้นเอง
ถ้าจำนวนบริษัทลูกค้ายังนับไม่ครบเพราะมีบริษัทที่ยังไม่ได้จัดประเภท การ์ดแรกแสดง “อย่างน้อย N” และบรรทัด “ยังไม่ได้จัดประเภท M บริษัท”

## 6. EX-02 — บริษัทลูกค้า

ข้อมูลของแต่ละบริษัทในรายชื่อ:

| ข้อมูล | รายละเอียด |
|---|---|
| บริษัท | ชื่อร้านหรือชื่อบริษัทเป็นลิงก์เปิด EX-04, ชื่อจดทะเบียนเมื่อไม่เหมือนกัน, จังหวัด, กลุ่มธุรกิจและรูปแบบกิจการ; ไม่แสดงรหัสภายใน ชื่อซ้ำแยกด้วยชื่อจดทะเบียน จังหวัด และวันที่สมัคร (**ข้อเสนอ รอเจ้าของยืนยัน — D1**) |
| ที่มา | ช่องทางที่รู้จัก และเซลล์ผู้แนะนำ (ชื่อ · รหัสเซลล์) หรือ “ไม่มีเซลล์ผู้แนะนำ” / “ไม่ระบุ” |
| บริการ (ปัจจุบัน) | ชื่อแพ็กเกจจริงที่อ่านได้ ไม่ตีความข้อมูลที่ขาดเป็นแพ็กเกจฟรี, ป้ายสถานะบริการพร้อมข้อความ ไม่ใช้สีอย่างเดียว, “เคยชำระเงิน” หรือ “ยังไม่เคยชำระเงิน” (N04) |
| การใช้งานในเดือน | ป้ายกลุ่มการชำระและใช้งาน (N05); ใบเสร็จในเดือน (N09) และประวัติเพิ่มใบเสร็จ (N08); วันใช้งาน ผู้ใช้ที่ใช้งาน เอกสาร (N10); ใช้ระบบล่าสุด; ข้อมูลไม่ครบแสดง “ยังประเมินไม่ได้” พร้อมเหตุผล ไม่กลายเป็นไม่ใช้ |
| ยอดรับสุทธิในเดือน | N06 จัดชิดขวา รูปแบบเงินตาม §4.3 |

- รูปแบบบนจอแต่ละขนาดเป็นไปตาม §11.2: ต่ำกว่า 768 px เป็นรายการแบบการ์ด ตั้งแต่ 768 px เป็นตารางความกว้างคงที่ และคอลัมน์ “ที่มา” แสดงตั้งแต่ 1024 px
- บรรทัดสรุปเหนือรายการ: “พบ N บริษัท · ยอดรับสุทธิในเดือน X บาท · เรียงตาม …” เป็นค่าของผลกรองทั้งหมด ไม่ใช่เฉพาะหน้าที่เห็น
- แบ่งหน้าด้วยเลขหน้า หน้าละ 25 รายการ ด้วย `Pagination` เดิม (§3.2) รายงานรวมต้องไม่เปลี่ยนเพียงเพราะเปลี่ยนหน้า
- ตัวเลือกเรียง: ใบเสร็จในเดือน มาก → น้อย (ค่าเริ่มต้น), วันใช้งาน มาก → น้อย, ใช้ผู้ช่วย มาก → น้อย, ยอดรับสุทธิในเดือน มาก → น้อย, ชื่อบริษัท ก → ฮ, สมัครล่าสุดก่อน ค่าที่ไม่มีอยู่ท้ายเสมอ ค่าเท่ากันเรียงตามวันที่สมัครก่อน
- ตัวกรองเฉพาะรายชื่อตามตาราง §4 อยู่ในแผงที่พับได้ เงื่อนไขที่ใช้อยู่และเงื่อนไขที่กดเจาะมา (§3.3) แสดงเป็นป้ายแม้แผงพับ
- แยกสถานะบริการออกจากกิจกรรมใช้งาน เช่น หมดอายุแต่เคยมีการใช้งานในเดือนนั้น; ไม่แทนการเคยชำระด้วยยอดรับเฉพาะเดือน
- เมื่อเรียงตามยอดรับสุทธิในเดือน รายชื่อแสดงสัดส่วนสะสมของยอดที่ใช้คำนวณสัดส่วนด้วย เพื่อให้ตรวจกลุ่ม 80% จากหน้าจอได้ (เอกสารกราฟและอันดับ §5)
- ไม่เพิ่มปุ่มลบข้อมูลในแต่ละแถวหรือ bulk delete
- ข้อมูลติดต่อเจ้าของบัญชีไม่แสดงในรายชื่อ แสดงเฉพาะในรายละเอียดตามสิทธิ์ (§8.1)

## 8. EX-04 — รายละเอียดบริษัท

ส่วนหัวแสดงชื่อ ชื่อจดทะเบียนเมื่อไม่เหมือนกัน กลุ่มธุรกิจ จังหวัด และปุ่มกลับรายการ; ไม่แสดงรหัสภายใน (D1)
การ์ดตัวเลขตามเดือน: ยอดรับสุทธิในเดือน (N06), ใบเสร็จในเดือน (N09), วันใช้งานในเดือน และใช้ผู้ช่วยในเดือน (N10)
ชื่อบริษัทยาวต้องตัดบรรทัดได้ ไม่ล้นจอ (§11.3)

### 8.1 แท็บข้อมูลบริษัท

เรียงกล่องตามนี้:

1. **รู้จักมั่งมีจากไหน**: ช่องทางที่รู้จัก, รายละเอียดที่ลูกค้าระบุเมื่อเลือก “อื่น ๆ”,
   เซลล์ผู้แนะนำชื่อ · รหัสเซลล์,
   และเซลล์ที่ได้รับยอดขายครั้งแรก พร้อมยอดชำระครั้งแรกและวันที่นับยอดให้เซลล์ แยกอีกช่องตามข้อมูลจริง
2. **ข้อมูลบริษัท**: ชื่อ, ชื่อจดทะเบียน, รูปแบบกิจการ, กลุ่มธุรกิจ, ประเภทกิจการ, จังหวัด, วันที่สมัคร
   และสำหรับผู้มีสิทธิ์ “ส่งออก Excel และดูข้อมูลติดต่อเจ้าของร้าน” เท่านั้น: อีเมลเจ้าของบัญชี, เบอร์โทรเจ้าของบัญชี และ “ข้อมูลบัญชี ณ …” (**ข้อเสนอ รอเจ้าของยืนยัน — D5**)
   ผู้ที่ไม่มีสิทธิ์นี้ไม่เห็นสามช่องดังกล่าว และเห็นข้อความ “ไม่มีสิทธิ์ดูข้อมูลติดต่อ” แทน ช่องที่ว่างต้องมีเหตุผล เช่น “มีเจ้าของหลายบัญชี”, “ไม่พบบัญชีเจ้าของปัจจุบัน”, “ยังไม่มีข้อมูล”, “ระบบยังอ่านข้อมูลส่วนนี้ไม่ได้” (เอกสารส่งออก Excel §9.2 ข้อ 8)
   รุ่นแรก **ไม่แสดงชื่อเจ้าของบัญชี** เพราะรายการช่องที่อนุญาตของสัญญาข้อมูลมีเฉพาะอีเมลและเบอร์โทร (RB-33)
3. **การใช้บริการมั่งมี (ปัจจุบัน)**: แพ็กเกจ, สถานะบริการ, วันสิ้นสุดบริการ และใช้ระบบล่าสุด

ช่องต่อไปนี้ **ไม่อยู่ในรุ่นแรก** เพราะสัญญาข้อมูลยังไม่มีช่องให้ (RU-08): จำนวนสาขา, จำนวนสมาชิก, วิธีสมัคร, ทีมดูแลปัจจุบัน, หลักฐานหรืออ้างอิงการแนะนำ, แคมเปญ และกล่อง “ข้อมูลที่ควรติดตาม”
ช่อง “จำนวนคำร้องที่เกี่ยวข้อง” ของฉบับก่อนลบออกตามมติซ่อนคำขอลบข้อมูล หน้านี้ไม่อ่านข้อมูลคำร้อง

ความหมายที่ต้องแยกชัดเจน:

- **รู้จักจากไหน**: ใช้ตัวเลือก/label จาก `SIGNUP_DISCOVERY_SOURCE_OPTIONS` เดิม:
  Website, IG, TikTok, Facebook, เซลล์ของมั่งมี, อื่น ๆ; ค่าที่ขาดแสดง “ไม่ระบุ” ตาม `signupDiscoveryLabel` เดิม
  รายละเอียดเช่น Google/LINE/อีเวนต์/ลูกค้าแนะนำแสดงใต้ “อื่น ๆ” เมื่อมีข้อมูลจริง
  ไม่เพิ่มเป็น enum ช่องทางใหม่หรือเดาจากวิธีสมัคร
- **เซลล์ผู้แนะนำ**: บุคคลที่ระบบรับรองว่าแนะนำบริษัทนี้; ชื่อซ้ำต้องแยกด้วยรหัสเซลล์
- **วิธีสมัคร** และ **ผู้ดูแลปัจจุบัน**: เป็นคนละเรื่องกับช่องทางที่รู้จักและผู้แนะนำ ห้ามใช้แทนกัน แม้ยังไม่แสดงในรุ่นแรก
- **ไม่มีเซลล์ผู้แนะนำ**: มีข้อมูลยืนยันว่าไม่มี; **ไม่ระบุ**: ข้อมูลขาด/ยังไม่ทราบ; **เซลล์ที่ไม่พบข้อมูลแล้ว**: มีผู้แนะนำแต่ไม่พบตัวตนในระบบแล้ว ทั้งสามแบบต้องแสดงเป็นข้อความ ไม่ใช้ — แทน

ตามมติ B6 แสดงที่มาตาม flow เดิม เช่น “เซลล์ของมั่งมี / คุณฟ้า · S003” หรือ “Facebook”
ไม่เพิ่มการกรอกรหัสเซลล์คู่กับช่องทางอื่น; “อื่น ๆ” ยังระบุรายละเอียดได้ตามเดิม
ชื่อผู้ได้รับยอดขายครั้งแรกเป็นอีกความหมายตาม B5 ไม่ใช้เปลี่ยนที่มาของลูกค้า
เดโม v2 แก้ตัวอย่าง Facebook คู่กับเซลล์ของ v1 แล้ว; ไม่ใช้การแก้ fixture นี้เป็นคำสั่งแก้ข้อมูลลูกค้าเก่า
หน้านี้เป็นการอ่าน ไม่เพิ่มแบบฟอร์มแก้ attribution หรือเลือกเซลล์ย้อนหลังในรอบ UI นี้

### 8.2 แท็บการใช้งานและรายรับ

แสดงกลุ่มการชำระและใช้งาน (N05), ใบเสร็จในเดือนและประวัติเพิ่มใบเสร็จ (N09, N08), วันใช้งาน ผู้ใช้ที่ใช้งาน เอกสาร และใช้ผู้ช่วย (N10) พร้อมหน่วย
ใช้ระบบครั้งแรก ใช้ระบบล่าสุด และเข้าสู่ระบบล่าสุดแยกกัน
เงินรับในเดือน คืนเงินในเดือน ยอดรับสุทธิในเดือน (N07, N06), ค่าธรรมเนียมการรับชำระในเดือน (N14) และต้นทุนผู้ช่วยและการอ่านใบเสร็จที่วัดได้ (N15) แสดงแยก ไม่หักออกจากยอดรับสุทธิ
ไม่เปิดเอกสาร/บทสนทนา/ข้อมูลธุรกรรมของ tenant ผ่านรายงานนี้
แยกเคยชำระเงิน / ชำระในเดือน / สถานะบริการปัจจุบัน ไม่ใช้แทนกัน
ค่าธรรมเนียมและต้นทุนที่ไม่มีข้อมูลหรือข้อมูลไม่ครบแสดง — พร้อมเหตุผล ไม่ใช่ 0.00 บาท และห้ามคิดจากเปอร์เซ็นต์ของยอดรับ
แนวโน้มยอดรับรายบริษัท วันชำระ และวันพร้อมใช้บริการ **ไม่อยู่ในรุ่นแรก** เพราะสัญญาข้อมูลยังไม่มีช่องให้ (RU-08)
ถ้าไม่มีข้อมูลกิจกรรมย้อนหลังเพียงพอ ให้บอกว่า “ยังประเมินไม่ได้” พร้อมเหตุผล (“ข้อมูลการใช้งานไม่ครบ” หรือ “ข้อมูลการชำระไม่ครบ”) ไม่จัดเป็น “จ่ายแล้วไม่ใช้”
เดือนก่อนวันที่สมัครแสดง “บริษัทนี้ยังไม่สมัครในช่วงรายงานนี้” พร้อมปุ่มกลับรายการ ไม่สร้างกิจกรรมเป็นศูนย์ที่ชวนให้เข้าใจผิด

### 8.3 แท็บประวัติบริษัท

แสดง timeline การสมัครและเหตุการณ์บริการที่ได้รับอนุญาต
ชนิดเหตุการณ์ที่แสดงได้คือรายการปิด: สมัคร, เปิดใช้งาน, ระงับชั่วคราว, ปิดใช้งาน, เก็บถาวร, ซื้อแพ็กเกจ, ต่ออายุแพ็กเกจ และแพ็กเกจหมดอายุ (RU-08 → RB-33) ข้อความไทยของแต่ละชนิดอยู่ในเอกสารคำบนหน้าจอ ชนิดอื่นที่หลังบ้านส่งมาไม่แสดง
แต่ละรายการแสดงวันที่ ชื่อเหตุการณ์ และชื่อแพ็กเกจเมื่อเกี่ยวข้อง ไม่แสดงชื่อผู้กระทำหรือเหตุผลที่เป็นข้อความอิสระ
ซ่อนรายการคำร้อง เลขเคส ลิงก์รายละเอียด และปุ่มสร้างคำขอ; ไม่ query ข้อมูลคำร้องในรุ่นนี้
การเปิดแท็บหรือดูประวัติต้องไม่สร้าง mutation ใด ๆ

## 9. EX-05/06 — คำขอเกี่ยวกับข้อมูล (DEFERRED ถึงก่อน §9.2)

- ใช้เคสเดิมของ `system-data-rights` ไม่สร้างทะเบียนคำร้องคู่ขนาน
- แสดงบริษัทด้วยชื่อ+รหัส ขอบเขตที่ขอ วันที่รับ ผู้รับผิดชอบถ้ามี และสถานะที่มาจากระบบจริง
- การรับคำร้องทางอีเมลต้องมีผู้ร้อง/อ้างอิง เป้าหมาย ขอบเขต และข้อมูลที่ contract เดิมกำหนด
  ฟอร์มสั้นในเดโมไม่ใช่การอนุมัติให้ตัด required fields หรือ validation เดิม
- ถ้ามีบริษัทจากหน้าต้นทาง ให้แสดงบริบทและตรวจเป้าหมายอีกครั้งก่อนส่ง; ไม่ใช้ URL เป็นหลักฐานสิทธิ์
- แยก “บันทึกคำร้อง”, “อนุมัติคำร้อง” และ “ดำเนินการลบ” เป็นคนละขั้น ห้ามแสดงว่าลบแล้วหลังรับคำร้อง
- หน้ารายงานไม่ให้สิทธิ์ `system.data_rights.manage`; แสดง action เฉพาะเมื่อมีสิทธิ์และสถานะรองรับจริง
- ยึดมติใหม่ B8 และ P31 ฉบับปรับปรุง: สร้างคำขอ → อนุมัติ → คงข้อมูลทั้งหมด 14 วัน → ลบจริง
  หลังลบเหลือเฉพาะข้อมูลที่มีฐานเก็บรักษาตามกฎหมายที่ผ่านการพิจารณา

### 9.1 โครงรายการและรายละเอียดคำขอลบ (DEFERRED)

- รายการแสดงเลขคำร้อง บริษัท ผู้ร้อง วันที่รับ สถานะ วันที่อนุมัติ และกำหนดครบช่วงรอเมื่อคำนวณได้
- รายละเอียดเรียง: บริษัท/ผู้ร้อง → ขอบเขต → ผลตรวจสอบ/อนุมัติ → ช่วงคงข้อมูล → ผลดำเนินการ/หลักฐาน
- ช่วงคงข้อมูลแสดงข้อความ “ข้อมูลทั้งหมดอยู่ระหว่างคงไว้ 14 วันก่อนลบจริง” พร้อมวันที่เริ่ม/ครบกำหนด
  และเวลาคงเหลือจาก server; ถ้ายังไม่มีกฎหรือ timestamp ที่ยืนยัน ให้แสดง “ยังไม่กำหนด” ไม่เริ่มนับจาก browser
- ครบกำหนดแสดง “ครบช่วงรอ” แยกจาก “ลบสำเร็จ”; action ดำเนินการต้องผ่านสิทธิ์และเงื่อนไขหลังบ้าน
- ผลลัพธ์แยกข้อมูลที่ลบ / ข้อมูลที่เก็บต่อพร้อมเหตุผลและกำหนด / งานที่ยังไม่สำเร็จ
  ห้ามขึ้น “ลบทั้งหมดแล้ว” หากยังมีข้อยกเว้นหรือหลักฐานไม่ครบ
- ไม่มีปุ่มลบทันทีข้าม 14 วันในโครงใหม่; การยกเลิกคำร้อง การระงับการใช้งาน และ auto/manual execution
  รอคุยรายละเอียด ไม่กำหนดจากชื่อสถานะหน้าจอ
- เก็บข้อเสนอไว้ในเอกสาร แต่ซ่อน mock states และทุกทางเข้าบนเดโม; ไม่เชื่อม executor

### 9.2 EX-07/08 — บัญชีผู้บริหารใน admin console

> หัวข้อนี้เขียนตามข้อเสนอของฝั่งหลังบ้านที่รอเจ้าของยืนยัน: สร้างบัญชีแบบเดียวกับบัญชีทีมขายเดิม (RB-06), บัญชีผู้บริหารเป็นบัญชีใหม่แยกเสมอ (RB-07), ผู้ดูแลระบบเป็นผู้สร้างและระงับ (RB-05) และการระงับคือการถอดสิทธิ์จริง (RB-25) ทางเลือกของแต่ละข้ออยู่ในตาราง “ข้อเสนอของฝั่งหลังบ้านที่หน้าจอเขียนตาม” ต้นเอกสาร

**EX-07 รายการ:** ชื่อหน้า “บัญชีผู้บริหาร” → ค้นหาชื่อหรือชื่อผู้ใช้ และกรองสถานะ → ปุ่ม “เพิ่มผู้บริหาร”
→ รายการบัญชี: ชื่อที่แสดง ชื่อผู้ใช้ สิทธิ์ สถานะ และเข้าสู่ระบบล่าสุด → เปิดรายละเอียดบัญชี
ไม่สร้างตัวเลขผู้ใช้ 4 คนเป็น fixture ใน application

- สถานะบัญชีบนจอมีสามค่า: รอเปลี่ยนรหัสผ่าน / ใช้งานได้ / ระงับ ใช้ค่าที่หลังบ้านส่งมา ไม่เดาจากการมีบัญชี (RU-21 → RB-06, RB-25)
- คอลัมน์สิทธิ์แสดง “ดูรายงาน” หรือ “ดูรายงาน ส่งออก Excel และดูข้อมูลติดต่อ”
- ไม่พบบัญชีตามคำค้นหรือสถานะ: แสดงเฉพาะข้อความ ไม่แสดงตารางเปล่า
- บนมือถือเป็นรายการแบบการ์ดตาม §11.2

**EX-08 เพิ่มผู้บริหาร:** breadcrumb → ช่องกรอก → สิทธิ์ → บันทึก/ยกเลิก ใช้ช่องและป้ายชุดเดียวกับฟอร์ม “เพิ่มบัญชีทีมขาย” เดิม (`apps/web/src/features/sales-console/SalesTeamPage.tsx`)

- ช่องกรอก: ชื่อผู้ใช้, ชื่อที่แสดง, เบอร์มือถือ (ไม่บังคับ), อีเมล (ไม่บังคับ) ด้วย `TextField`
- สิทธิ์ “ดูรายงานผู้บริหาร” ได้เสมอ แสดงเป็นข้อความ ไม่เป็น dropdown เพราะมีค่าเดียว
- ช่องติ๊ก “ส่งออก Excel และดูข้อมูลติดต่อเจ้าของร้าน” ค่าเริ่มต้นไม่ติ๊ก พร้อมคำอธิบาย “ไฟล์มีข้อมูลของทุกบริษัท และข้อมูลติดต่อเป็นข้อมูลส่วนบุคคล” (**ข้อเสนอ รอเจ้าของยืนยัน — D5, D6**)
- หลังบันทึกสำเร็จ แสดงกล่องรหัสผ่านชั่วคราวแบบเดียวกับ `SalesCredentialPanel` เดิม (`apps/web/src/features/sales-console/SalesConsoleParts.tsx`): รหัสแสดงครั้งเดียว มีปุ่มคัดลอก บอกว่าต้องส่งรหัสให้เจ้าตัวเอง และบอกวันหมดอายุของรหัส ออกจากหน้าแล้วเรียกดูอีกไม่ได้ บัญชีขึ้นสถานะ “รอเปลี่ยนรหัสผ่าน” จนกว่าเจ้าตัวจะเข้าระบบและตั้งรหัสใหม่
- รุ่นแรกไม่มีอีเมลเชิญ และไม่ผูกกับบัญชีที่มีอยู่แล้ว ชื่อผู้ใช้ที่ซ้ำกับบัญชีใดในระบบให้ขึ้นข้อผิดพลาดที่ช่องนั้น ไม่สร้างหรือแก้บัญชีเดิมเงียบ ๆ
- ฟอร์มรองรับค่าว่าง รูปแบบผิด ชื่อผู้ใช้ซ้ำ สิทธิ์ไม่พอ pending และ error โดยรักษาค่าที่กรอก
- ฟอร์มนี้สั้น จึงไม่มีกล่องถามยืนยันเมื่อออกจากฟอร์มที่กรอกค้าง (แอปไม่มีแบบแผนนี้) กด “ยกเลิก” หรือ Back แล้วไม่มีคำสั่งถูกส่ง

**EX-08 รายละเอียด:** ข้อมูลบัญชีและสิทธิ์ → สถานะ → การกระทำ: เปิดหรือปิดสิทธิ์ส่งออก, ออกรหัสผ่านใหม่, ระงับบัญชี, เปิดใช้อีกครั้ง

- ระงับบัญชีและปิดสิทธิ์ส่งออกต้องมีกล่องยืนยันที่แสดงชื่อที่แสดงและชื่อผู้ใช้ และช่องเหตุผลที่บังคับกรอก ใช้ `use-confirm` / `use-input-prompt` เดิมใน `apps/web/src/common/components/modal`
- ออกรหัสผ่านใหม่ต้องยืนยันก่อน และบอกว่าการเข้าระบบที่ค้างอยู่ของบัญชีนั้นจะถูกยกเลิก แล้วแสดงกล่องรหัสผ่านชั่วคราวแบบเดียวกับตอนสร้าง
- หลังระงับ ผู้ใช้นั้นต้องถูกปฏิเสธตั้งแต่คำขอถัดไป และเข้าระบบใหม่ก็ยังดูรายงานไม่ได้ (RB-25)
- ระงับตัวเองไม่ได้ ให้แสดงเหตุผลแทนปุ่ม กติกานี้ตรวจที่หลังบ้านด้วย
- รุ่นแรกไม่มีการแก้ชื่อ ชื่อผู้ใช้ เบอร์ หรืออีเมล และไม่มีประวัติการเปลี่ยนบนหน้าจอ เพราะสัญญาข้อมูลยังไม่มีคำสั่งและข้อมูลส่วนนี้ (RU-08)

- ผู้ดูรายงานทั่วไปไม่เห็น action จัดการบัญชี; API ต้องตรวจสิทธิ์ซ้ำเมื่อเชื่อมจริง
- ไม่เพิ่มสมาชิกในบริษัทลูกค้าทุกแห่ง และไม่ให้สิทธิ์อนุมัติ/ลบข้อมูลติดมากับบทบาทผู้บริหาร
- ฟิลด์ ปุ่ม dropdown รวมรายการสิทธิ์ ใช้ theme contract §10 เช่นเดียวกับรายงาน

## 10. Theme contract — เกณฑ์บังคับ

### 10.1 Source และ component mapping

| ส่วนหน้าจอ | แหล่งที่ต้องใช้ |
|---|---|
| สี ฟอนต์ radius shadow | `packages/design-tokens/tokens.json` → generated theme → `apps/web/src/common/styles/theme.css` |
| ฟอนต์ | `--font-family-sans` ของระบบ: Outfit / IBM Plex Sans Thai และ fallback ที่มีอยู่ |
| Shell | `SystemHeader` + system layout เดิม; ไม่ทำ sidebar/header ชุดใหม่จากเดโม |
| Page / card / KPI / badge | `MangmeePage`, `MangmeeCard`, `MangmeeStatCard`, `MangmeeBadge` |
| ปุ่ม / สถานะกำลังทำงาน | `Button` และ loading prop; ลิงก์/action/tab ใช้ Mangmee brand |
| ช่องข้อความ / ค้นหา / หลายบรรทัด | `TextField`, `TextareaField`, `FieldError` |
| Dropdown | `SelectField` ซึ่งใช้ `ThemedSelect`; ใช้ `ThemedSelect` โดยตรงเมื่อ wrapper ไม่เหมาะกับโครงเดิม |
| เดือน / วันที่ | `ThemedDate` โดยมี label และ ARIA; ฟอร์มที่ต้องใช้เวลาให้ reuse pattern ที่รองรับเวลาจริง |
| ตารางและรายการ | รูปแบบตาม §11.2: รายการแบบการ์ดเมื่อจอแคบกว่า 768 px และตารางความกว้างคงที่ตั้งแต่ 768 px แบบหน้า `PartnerListPage` เดิม; `Pagination` เดิม; ไม่ใช้ `mangmee-table-scroll` กับตารางที่มีคอลัมน์ข้อความอิสระ |
| Popover / modal | `PopoverPanel`, shared `Modal` และ hook ปิดเมนูเดิม |
| Loading / empty / error / denied | `CoverLoader`, `LoadingState`, `EmptyState`, `ErrorState`, `ForbiddenState` |

ใช้ธีม light ตามระบบปัจจุบัน แม้อุปกรณ์ตั้ง dark mode; ไม่มี dark theme ใหม่ใน scope นี้
สีตัวเลข กราฟ และ legend ใช้ design tokens; ไม่เพิ่ม blue/indigo/sky เป็นสีหลักของ interaction
feature CSS ใช้เฉพาะ layout และ token ไม่ประกาศ palette/font/reset สำหรับหน้าเอง
สีและความต่างของกราฟเป็นไปตาม §10.5

### 10.2 Dropdown ต้องเข้าธีมทั้งปิดและเปิด

- **ห้าม rendered native `<select>` ใหม่ในหน้าชุดนี้**; การตกแต่งกรอบ select อย่างเดียวไม่ทำให้ popup ของ OS เข้าธีม
- ใช้ `SelectField`/`ThemedSelect` ทั้ง filter toolbar ตัวเลือกกลุ่มของหน้าเปรียบเทียบ และฟอร์มบัญชี (ฟอร์มคำร้องพักไว้ ไม่อยู่ในงานรอบนี้)
- ชุดเมนูที่เปิดต้องคุมพื้นหลัง ขอบ shadow สีข้อความ hover focus selected checkmark และ disabled option
  รวมถึงช่องค้นหาภายในเมนู ไม่มีส่วนใดกลับไปใช้ฟอนต์หรือสี browser default
- ใช้ portal ของ `PopoverPanel` เดิม ไม่แก้ด้วย z-index สูงเฉพาะหน้า หรือย้าย popover กลับเข้า container ที่ clip
- เมนูไม่ถูก table/card/modal ตัด ไม่ล้นขอบจอ เลื่อนตาม anchor ถูก และวางเหนือ/ใต้ตามพื้นที่
- คลิกเลือกแล้วปิด, กด trigger ซ้ำแล้วปิด, กดนอกเมนูแล้วปิด, Escape แล้วปิด
  กดอีก dropdown ต้องใช้งานต่อได้โดยไม่ต้องกดซ้ำ
- Keyboard ใช้งานได้: เปิดด้วยคีย์บอร์ด เลื่อนตัวเลือก เลือก กลับ focus ที่ trigger;
  ค้นหาแล้วไม่พบแสดงข้อความในเมนู และรายการ disabled เลือกไม่ได้
- label ยาวไม่ชน chevron; ชื่อเซลล์/บริษัทยาวต้องยังตรวจตัวตนได้ในรายการที่เปิด

### 10.3 Text input และ textarea ทุกตำแหน่ง

- ห้าม visible `<input>`/`<textarea>` ที่เขียน style เฉพาะหน้าแทน shared fields;
  hidden inputs และ internal search ของ shared components ใช้ implementation กลางต่อได้
- default, hover, focus, filled, placeholder, disabled, readonly, error และ browser autofill ต้องยังอ่านได้และใช้ธีมระบบ
- label อยู่เหนือช่อง; hint/error ผูก `aria-describedby`; error มีข้อความและ `aria-invalid` ไม่พึ่งสีอย่างเดียว
- readonly ยังเลือก/คัดลอกได้เมื่อเหมาะสม; disabled ต้องดูและทำงานเป็น disabled ไม่สว่างเหมือนคลิกได้
- ป้องกันข้อความชนไอคอนโดยใช้ spacing ของ component; กรณี raw shared `.mangmee-input`
  ที่มีไอคอนท้ายใช้ `.mangmee-input-icon-end` ตาม implementation เดิม
- ใช้ขนาดจาก shared fields: controls หลักอย่างน้อย 44px บน mobile, 40px desktop ตาม breakpoint เดิม;
  ข้อความกรอกบนมือถืออย่างน้อย 16px ตาม global rule เพื่อไม่ให้ iOS ซูมเมื่อ focus
- ไม่ใช้ inline hex/font/ring override เพื่อแก้เพียงบางช่อง ไม่ใช้ native date/month popup เป็นทางลัด
- ถ้า component กลางมีปัญหา ให้แก้ที่ common layer แบบ scoped พร้อม check ไม่ทำสำเนา component เฉพาะรายงาน

### 10.4 ข้อสังเกตจาก code audit ณ วันที่เขียน

`SelectField` มี `ThemedSelect` และ searchable menu อยู่แล้ว; `ThemedDate` รองรับเดือน
จึงไม่ต้องสร้าง dropdown/date picker ใหม่หรือเพิ่ม dependency
`TextField`/`TextareaField` และ `.mangmee-input` มีรายละเอียด CSS คนละทางบางส่วน
ต้องเลือก wrapper ให้สอดคล้องใน form เดียวกัน และตรวจ computed style จริง โดยไม่เติม class ทับแบบเดา

(พักไว้ — หน้าคำร้องไม่อยู่ในงานรอบนี้ เก็บข้อสังเกตนี้ไว้ใช้เมื่อกลับมาทำ) หน้า `DataRightsNewPage.tsx` เดิมยังมี local `inputClass`, native datetime และสีบางค่าที่กำหนดเอง
การ reuse flow นี้ **ไม่ได้แปลว่ารับรอง style เดิมทั้งหมด**; หากปรับหน้าคำร้องในงานนี้ต้องนำ controls ที่แตะ
เข้าสู่ theme contract ข้างต้น โดยรักษา field semantics/validation/permission เดิม
ไม่ขยายงานเป็นการเปลี่ยนธีมทั้งระบบ

### 10.5 กราฟและสี

- สีกำหนดตามบทบาท และบทบาทหนึ่งมีความหมายเดียวทั้งชุดหน้าและในไฟล์ Excel:

  | บทบาท | สี | ใช้กับ |
  |---|---|---|
  | กลุ่มที่เป็นประเด็นของกราฟ | สีหลัก เขียวเข้ม | เคยเพิ่มใบเสร็จ; กลุ่มที่จ่ายสูงสุด; แถบของกราฟกลุ่ม |
  | กลุ่มที่ต้องตามต่อ | สีเตือน ทองเข้ม หรือทองมีขอบสีเข้ม | ยังไม่เคยเพิ่มใบเสร็จ |
  | ข้อมูลไม่พอ | เทามีลายขีด | ยังประเมินไม่ได้ เท่านั้น |
  | อยู่นอกประเด็น | เทาอ่อนมีขอบ | ลูกค้านอกกลุ่มที่จ่ายสูงสุด; ไม่มีในแพ็กเกจ |

  รายละเอียดอยู่ในเอกสารกราฟและอันดับ §4
- ไม่ใช้สีน้ำเงินกับส่วนของกราฟที่กดได้
- ส่วนของกราฟที่อยู่ติดกันต้องต่างกันด้านความสว่างอย่างน้อย 3:1 และทุกสีต่างจากพื้นอย่างน้อย 3:1 ถ้าสีจาก token ไม่ผ่าน ให้เพิ่มขอบหรือลายโดยใช้ token เดิม ไม่ประกาศสีใหม่
- ชื่อกลุ่ม จำนวน และเปอร์เซ็นต์ อยู่ในหรือติดกับส่วนของกราฟเสมอ กราฟต้องอ่านได้เมื่อมองเป็นขาวดำ
- ส่วนของกราฟที่แคบกว่า 44 px ให้แตะผ่านรายการคำอธิบายใต้กราฟ ซึ่งแต่ละรายการสูงอย่างน้อย 44 px
- กราฟกลุ่ม (ธุรกิจ ช่องทาง เซลล์) ใช้สีเดียว ไม่ใช้สีแยกหมวด เพราะจำนวนหมวดไม่จำกัด
- กราฟทุกตัวมีข้อความทางเลือกสำหรับโปรแกรมอ่านหน้าจอ และมีตัวเลขเดียวกันเป็นข้อความบนหน้าเดียวกัน

## 11. สถานะและ responsive behavior

| สถานะ | สิ่งที่ผู้ใช้ต้องเห็น |
|---|---|
| Initial loading | loading ของ shell/page ที่เกี่ยวข้อง ไม่มีเลข 0 ชั่วคราว |
| เปลี่ยน filter / หน้า / refresh | `CoverLoader` คลุม scope ที่อ่านใหม่; ป้องกันกดซ้ำและข้อมูล response เก่าทับตัวกรองใหม่ |
| ไม่มีข้อมูลจริง | empty state ของช่วง/กลุ่มนั้น; จำนวนศูนย์ใช้ได้เฉพาะที่ทราบว่าศูนย์ |
| ไม่พบจากตัวกรอง | แสดงเงื่อนไขและทางล้างตัวกรอง |
| ข้อมูลขาด | `—` พร้อมคำอธิบาย “ยังไม่มีข้อมูล”/“ไม่ระบุ”; ไม่แทนด้วย 0 |
| ยังประเมินไม่ได้ | ข้อความ “ยังประเมินไม่ได้” พร้อมเหตุผลหนึ่งในสองแบบ: “ข้อมูลการใช้งานไม่ครบ” หรือ “ข้อมูลการชำระไม่ครบ” |
| Partial error | แจ้งส่วนที่อ่านไม่ได้ ไม่ทำให้ส่วนที่สำเร็จกลายเป็นศูนย์; ข้อมูลเก่าที่คงไว้ต้องติดเวลา/สถานะ |
| ไม่มีสิทธิ์ / สิทธิ์ถูกถอน | `ForbiddenState` ใน shell หรือ `SystemAccessDenied` ตาม §3.1 และล้างข้อมูลที่ไม่ควรเห็น; ไม่ใช้ข้อมูลเก่าค้าง |
| บริษัทไม่พบ | not-found state พร้อมกลับรายชื่อ; ไม่เผยข้อมูลบริษัทอื่น |
| เดือนก่อนสมัคร | ข้อความเฉพาะเหตุผล พร้อมปุ่มกลับรายชื่อ ไม่แสดงกิจกรรมที่แต่งขึ้น |
| เดือนที่ยังไม่มีข้อมูล | บอกว่าเดือนนั้นยังไม่มีข้อมูล ไม่แสดงศูนย์ และเลือกเดือนนั้นจากตัวเลือกเดือนไม่ได้ |
| เดือนที่ยังไม่จบ | ป้าย “เดือนนี้ยังไม่จบ” ตาม §4.1 |
| หมดเวลาเข้าระบบ | พาไปหน้าเข้าสู่ระบบแล้วกลับมาหน้าเดิมพร้อมเดือนและตัวกรองเดิม (พฤติกรรมเดิมของ shell) |
| ชุดข้อมูลของรายงานเปลี่ยนระหว่างใช้งาน | โหลดการ์ดและตารางใหม่พร้อมกันหนึ่งครั้งโดยคงหน้าเดิม พร้อม “อัปเดตข้อมูลแล้ว ตัวเลขอาจเปลี่ยน” (§4.1) |
| เรียกดูถี่เกินไป | “เรียกดูถี่เกินไป กรุณารอ N วินาทีแล้วลองใหม่” ปุ่มลองใหม่ใช้ได้เมื่อครบเวลา |
| ระบบปิดปรับปรุงหรือแหล่งข้อมูลไม่พร้อม | แยกจาก “ไม่มีข้อมูล” บอกว่าส่วนใดอ่านไม่ได้ และมีปุ่มลองใหม่ |
| ไม่มีสัญญาณ | คงข้อมูลที่แสดงอยู่พร้อมเวลา และบอกว่ายังไม่ได้อัปเดต |
| ปุ่มที่ใช้ไม่ได้ | แสดงเหตุผลเป็นข้อความใกล้ปุ่ม เช่น ปุ่มส่งออกเมื่อยังไม่มีข้อมูลเดือนนี้ |
| ส่งคำร้อง (พักไว้ ไม่อยู่ในงานรอบนี้) | pending บนฟอร์ม ป้องกันส่งซ้ำ; error แล้วข้อมูลที่กรอกยังอยู่; success หลังผลยืนยันจริง |

ทุกสถานะใช้ component กลาง (`LoadingState`, `EmptyState`, `ErrorState`, `ForbiddenState`, `CoverLoader`) ไม่ทำกล่องข้อความเฉพาะหน้า
รหัสข้อผิดพลาดและรหัสเหตุผลทุกตัวต้องมีข้อความไทยใน `apps/web/src/common/api/api-error-message.ts` ก่อนใช้งาน ห้ามแสดง `code` หรือ `message` จากหลังบ้านโดยตรง ข้อความอยู่ในเอกสารคำบนหน้าจอ

### 11.1 มือถือเป็นหลัก

ออกแบบและตรวจที่ 390×844 ก่อน แล้วจึง 320, 768, 1024 และ 1440 px เกณฑ์ที่ 390×844:

- ทั้งหน้าไม่เลื่อนแนวนอน และไม่มีองค์ประกอบใดกว้างเกินกรอบของตัวเอง (`scrollWidth` ไม่เกิน `clientWidth`) รวมถึงกรอบตาราง
- หน้าภาพรวมเห็นการ์ดตัวเลขครบ 4 ใบในจอแรกโดยไม่เลื่อน
- ทุกสิ่งที่แตะได้สูงและกว้างอย่างน้อย 44 px ห้ามใช้ `Button size="sm"` กับสิ่งที่แตะบนมือถือ แถบพับ/กางตัวกรองสูงอย่างน้อย 44 px และปุ่มของ `Pagination` ต้องได้ขนาดนี้เมื่อใช้ในหน้าชุดนี้
- คำอธิบายตัวเลขไม่เล็กกว่า 14 px ข้อความในช่องกรอกไม่เล็กกว่า 16 px
- ปุ่มหลักของแผง (เช่น สร้างไฟล์ Excel) อยู่ในจอแรกหรือยึดไว้ด้านล่างจอ
- เมื่อกำหนดความสูงตามจอใช้ `dvh` ไม่ใช้ `vh`
- คำบอกวิธีใช้เขียนว่า “แตะ” หรือ “กด” ไม่ใช้ “คลิก”
- ตัวกรอง wrap/stack ได้ การ์ดตัวเลขลดคอลัมน์ตามพื้นที่ modal/popover ไม่ซ่อน action

ทดสอบ browser zoom 200%, keyboard-only และอุปกรณ์ที่ตั้ง dark mode ด้วย

### 11.2 ตารางและรายการ

ตารางที่มีคอลัมน์ข้อความอิสระ (ชื่อบริษัท ชื่อจดทะเบียน รายละเอียด “อื่น ๆ” ชื่อเซลล์ อีเมล) **ห้ามอยู่ใน `mangmee-table-scroll`** เพราะคลาสนี้ทำให้ตารางกว้างตามเนื้อหา (`min-width: max-content`) ใช้สองรูปแบบนี้แทน โดยแบ่งที่ 768 px (`md` ของระบบ):

- **ต่ำกว่า 768 px — รายการแบบการ์ด:** แต่ละแถวเป็นหนึ่งบล็อก (`MangmeeCard` หรือรายการที่มีเส้นคั่น แบบรายการ “อันดับการใช้” ของต้นแบบ) ข้อความตัดบรรทัดได้ ค่าแต่ละค่ามีชื่อกำกับ ตัวเลขชิดขวา ทั้งบล็อกหรือชื่อเป็นลิงก์สูงอย่างน้อย 44 px
- **ตั้งแต่ 768 px — ตารางความกว้างคงที่:** `table-fixed` ความกว้างคอลัมน์เป็นสัดส่วน ข้อความในช่องตัดบรรทัดได้ (`break-words`) ซ่อนคอลัมน์รองตามความกว้าง มี `caption` และ `scope` แบบหน้า “บริษัทและผู้ใช้งาน” เดิม (`PartnerListPage.tsx`)

| ตาราง | ต่ำกว่า 768 px (เรียงจากบนลงล่างในแต่ละบล็อก) | ตั้งแต่ 768 px |
|---|---|---|
| รายชื่อบริษัท (EX-02) | ชื่อ (ลิงก์) และชื่อจดทะเบียน → จังหวัด · กลุ่มธุรกิจ → ป้ายการชำระและใช้งาน และใบเสร็จในเดือน → แพ็กเกจ · สถานะบริการ → ยอดรับสุทธิในเดือน | 4 คอลัมน์: บริษัท / บริการ / การใช้งานในเดือน / ยอดรับสุทธิในเดือน; คอลัมน์ “ที่มา” เพิ่มตั้งแต่ 1024 px |
| ตารางกลุ่ม (ธุรกิจ ช่องทาง เซลล์) | ชื่อกลุ่ม (ลิงก์) → จำนวนบริษัทและสัดส่วนพร้อมแถบ → ชำระในเดือน → ยอดรับสุทธิในเดือน (และค่าอื่นของตารางนั้น แต่ละค่าหนึ่งบรรทัดพร้อมชื่อ) | ตารางตาม §7 |
| ยอดขายครั้งแรกของเซลล์ | ชื่อเซลล์ → จำนวนบริษัท → ยอดชำระครั้งแรกสะสม | ตาราง 3 คอลัมน์ |
| เปรียบเทียบ (EX-03D) | ทีละรายการเป็นบล็อก: ชื่อรายการ → ฝั่ง A → ฝั่ง B → ต่างกัน (A ลบ B) | ตาราง 4 คอลัมน์ |
| บัญชีผู้บริหาร (EX-07) | ชื่อที่แสดง (ลิงก์) → ชื่อผู้ใช้ (ตัดบรรทัดได้) → สิทธิ์ · สถานะ → เข้าสู่ระบบล่าสุด | ตาราง 4 คอลัมน์ |
| รูปแบบกิจการ | ตาราง 3 คอลัมน์ได้ทุกขนาดจอ เพราะทุกช่องเป็นค่าสั้นจากรายการที่ระบบกำหนด ถ้าล้นให้ใช้แบบบล็อก | ตาราง 3 คอลัมน์ |

แผงเตรียมไฟล์ Excel ไม่มีตารางตัวอย่างข้อมูล แสดงรายการชีต จำนวนบริษัท เงื่อนไข และรายชื่อหัวคอลัมน์เป็นข้อความ (เอกสารส่งออก Excel §2)

### 11.3 ค่ายาว ค่ามาก ค่าติดลบ และกลุ่มเล็ก

- ชื่อบริษัท ชื่อจดทะเบียน และรายละเอียด “อื่น ๆ” ตัดบรรทัดได้ทุกที่ รวมหัวหน้าของ EX-04 (`overflow-wrap: anywhere`) ไม่ตัดทิ้งโดยไม่มีทางอ่านเต็ม ชื่อในรายชื่อเป็นลิงก์ ไม่ใช่ปุ่มความสูงคงที่
- ยอดรับสุทธิติดลบแสดงได้ทั้งการ์ด ตาราง รายชื่อ และกราฟ กราฟแนวโน้มมีเส้นฐานที่ 0 และวาดค่าติดลบใต้เส้นฐาน
- ชุดตรวจต้องมี: ชื่อ 120 ตัวอักษรไม่มีช่องว่างทั้งไทยและอังกฤษ, “อื่น ๆ” 200 ตัวอักษร, ยอด 9 หลัก, ยอดรับสุทธิติดลบ, เดือนที่ทุกบริษัทเป็น 0, บริษัทเดียว, ไม่มีบริษัท
- กลุ่มที่มีบริษัทน้อยกว่า 10 รายใช้กติกากลุ่มเล็กของเอกสารกราฟและอันดับ §5

### 11.4 ภาษา

รุ่นแรกข้อความเป็นภาษาไทยอย่างเดียว เหมือนหน้าผู้ดูแลระบบเดิม (**ข้อเสนอ รอเจ้าของยืนยัน — D7**) ข้อความทุกจุดยึดเอกสารคำบนหน้าจอ และรวมไว้ที่เดียวในโค้ด ไม่ฝัง string กระจายใน JSX เพื่อให้เพิ่มภาษาอื่นภายหลังได้โดยไม่แก้หน้าจอ
