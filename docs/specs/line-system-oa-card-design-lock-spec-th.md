# LINE ระบบมั่งมี — ดีไซน์การ์ดที่ล็อกแล้ว

สถานะ: **DESIGN LOCKED — 2026-10-04**

2026-10-05: เจ้าของสั่ง **“ทำเลย”** จึงอนุญาตให้นำดีไซน์นี้ไปใช้ในโค้ดตาม [แผนดำเนินการ](../plans/line-system-oa-card-design-implementation-plan-th.md) โดยไม่เปลี่ยนแบบที่ล็อก ยังไม่ได้สั่งเผยแพร่ UAT/Production ข้อความด้านล่างที่กล่าวถึงการไม่อนุญาต runtime เป็นสถานะ ณ วันที่ล็อกและถูกแทนที่เฉพาะส่วนการลงมือทำนี้

คำสั่งเจ้าของ: **“โอเค lock design นี้ไว้ ต้องเป็นตามนี้เท่านั้น”**

ไฟล์นี้และสำเนาที่ล็อกเป็นข้อกำหนดการแสดงผลสำหรับการ์ดทั้ง 8 บริบทของ LINE **ระบบมั่งมี** ไม่ใช่ OA Official ฝั่งการตลาด การอนุมัตินี้ล็อกดีไซน์เท่านั้น ยังไม่ได้อนุญาตให้แก้ runtime หรือเผยแพร่ระบบ การอนุมัติเปลี่ยนสี/ขนาดของ OA Official ก่อนหน้านี้ไม่ใช้กับงานนี้

## สิ่งที่ต้องตรงกับแบบ

1. ใช้สี สัดส่วนตัวอักษร ระยะห่าง มุมโค้ง การจัดแถว และปุ่มตามสำเนาที่อนุมัติ ห้ามออกแบบใหม่ เพิ่มองค์ประกอบ หรือปรับให้ต่างเอง ค่าที่ใช้ล็อกคือค่าเริ่มต้นใน manifest; ตัวปรับในตัวอย่างเป็นเครื่องมือสำรวจ ไม่ใช่อนุญาตให้เปลี่ยน baseline
2. หัวเขียวไล่เฉด `#174e37` → `#167c52` ขนาดกระชับ มีข้อความ 2 บรรทัด ไม่มี `MANGMEE PLUS` ไม่มีข้อความมุมขวาบน และไม่มี `คำสั่งมั่งมี`
3. พื้นข้อมูลสีขาวซ้อนขึ้นบนหัวเขียว มาสคอตพื้นโปร่งใสอยู่ด้านขวาและยื่นข้ามรอยต่อ เก็บมิติและลำดับชั้นตามแบบ: หัวเริ่มต้นสูง 80–81px, มาสคอตกว้าง 112px, ยื่นข้ามรอยต่อ 16px ในตัวอย่างที่ตรวจแล้ว ห้ามขยายหัวหรือเว้นพื้นที่ว่างเพิ่ม
4. ใช้รูป POS/เงินเป็นมาสคอตทั่วไปทุกบริบทและสถานะ ยกเว้นกำลังอ่านใบเสร็จใช้รูปสแกน และรอตรวจสอบใบเสร็จใช้รูปตรวจสอบ รูปทั้งสามที่ล็อกอยู่ในชุดหลักฐาน ห้ามเปลี่ยนเป็นภาพใหม่เอง
5. ข้อมูลแบบแถวจัดเป็น **ชื่อข้อมูล / `:` / ค่า** ให้เครื่องหมาย `:` อยู่ในคอลัมน์เดียวกัน ค่าที่ยาวขึ้นบรรทัดได้โดยไม่ตัดข้อมูลหรือชนภาพ
6. เน้นยอดรวมด้วยพื้นครีม `#f3f0df` ตามบริบทที่มีอยู่ในแบบ ใช้สีปุ่มและแถบสถานะเฉพาะที่มีอยู่แล้ว ห้ามเพิ่มแถบสีเหลือง “รอตรวจสอบ” ที่เจ้าของตัดออก
7. คำตอบทั่วไปไม่เพิ่มชุดคำซ้ำ `คำตอบจากน้องมั่งมี`, `ถามตอบทั่วไป`, `น้องมั่งมีตอบให้นะคะ`, `คำถามของคุณ` ภายในตัวการ์ด หัวบอกเรื่องที่ตอบตามบริบท ไม่บังคับทวนคำถามผู้ใช้ทุกครั้ง
8. การ์ดกำลังสแกนไม่มีสองแถวที่ตัดออก: `เอกสารที่รับ : รูปภาพ` และ `สถานะ : กำลังอ่านข้อมูล` ห้ามใส่เปอร์เซ็นต์หรือเวลาที่ไม่ทราบจริง
9. ชื่อข้อมูลและปุ่มเป็นภาษาที่ผู้ใช้เข้าใจ ห้ามคืนแถว `ระดับแจ้งเตือน` หรือ `ขอบเขต` ในการ์ดงานค้าง
10. คำอธิบาย “ตัวอย่างดีไซน์”, carousel, ตัวปรับดีไซน์, เวลาแชต และพื้นแชตสีน้ำเงินเป็นส่วนแสดงตัวอย่าง ไม่ใช่ข้อมูลที่จะส่งอยู่ภายใน Flex card

## บริบทที่ครอบคลุม

| การ์ด | หัวและข้อมูลที่ใช้ |
| --- | --- |
| สรุปค่าใช้จ่าย | หัวเรื่อง + ช่วงเวลา; ยอดรวม จำนวนรายการ ช่วงวันที่ ที่มา ข้อมูล ณ และหมายเหตุยกเว้นรายการเมื่อมีข้อมูลรองรับ |
| งานค้าง | หัวตามชนิดงานและผลที่พบ; กรณีใบเบิกใช้ `ใบเบิกรออนุมัติ / พบ … รายการ`, `เลขที่ใบเบิก`, `ต้องทำ : ตรวจสอบและอนุมัติใบเบิก`, `ข้อมูล ณ` และปุ่ม `เปิดใบเบิกเพื่ออนุมัติ` |
| ถามตอบทั่วไป | หัว 2 บรรทัดตามเรื่องที่ตอบ แล้วแสดงคำตอบโดยตรงตามโค้ด/ข้อมูลจริง ไม่มีกรอบทวนคำถามซ้ำ |
| คำสั่งแก้ไข | บริบทแก้ไขค่าใช้จ่าย + ขั้นที่เกิดจริง; ตัวอย่างก่อนยืนยัน ผลสำเร็จ ยกเลิก หรือขอข้อมูลเพิ่มตามแบบ |
| รายการทั่วไป | บริบทรายการค่าใช้จ่าย + สถานะจริง; แยกสถานะเอกสารออกจากการชำระเงิน |
| รอตรวจสอบ | บริบทใบเสร็จ + รอตรวจสอบ; รูปตรวจสอบ แถวข้อมูล และปุ่มตามแบบ ไม่มีแถบรอตรวจสอบซ้ำ |
| ชำระเงิน | บริบทการชำระ + สถานะจริง; ยอดที่ต้องจ่าย จ่ายแล้ว คงค้าง และรายละเอียดที่มีข้อมูลรองรับตามแบบ |
| กำลังสแกน | บริบทเอกสารที่ส่งมา + กำลังสแกน; รูปสแกนและข้อความกระชับตามแบบ ไม่มีแถวที่เจ้าของตัดออก |

ข้อความหัวและข้อมูลเปลี่ยนตามเรื่อง/สถานะ/ช่วงเวลา/สิทธิ์ที่มีจริงได้ภายใน pattern นี้ ตัวเลข วันที่ รายชื่อ เลขเอกสาร และจำนวนรายการในสำเนาเป็นข้อมูลตัวอย่างจาก fixture ไม่ใช่ข้อกำหนดให้ตอบค่าคงที่หรือข้อมูล Production หากข้อมูลหายให้ละหรือระบุว่าไม่ทราบตาม contract เดิม ห้ามแต่งเติมเพื่อให้ครบแถว

ผลอ่านไฟล์ที่เป็นร่างรอตรวจสอบส่งการ์ดด้วยตัวสร้างเดียวกับรูปภาพ และส่งข้อความเดิมหนึ่งครั้งเมื่อเนื้อหาการ์ดถูกปฏิเสธ โดยใช้คีย์ส่งซ้ำแยกจากการ์ด; ผลอื่นคงข้อความเดิม

งานค้างที่ไม่พบรายการต้องระบุด้วยข้อความสั้นว่าตรวจเฉพาะอะไร: งานที่มอบหมายให้ผู้ใช้และยังไม่เสร็จ หรือแจ้งเตือนที่ยังไม่ปิดตามสิทธิ์ ห้ามนำจำนวนแจ้งเตือนที่อ่านได้บางหน้ามาอ้างว่าเป็นงานทั้งหมดของบริษัท

## ปลายทางปุ่มใบเบิก

แบบที่ล็อกต้องพาไป **ใบเบิกใบนั้นโดยตรง** ที่ `/companies/{companyId}/reimbursements/{requestId}` แล้วตรวจ session/สิทธิ์/สถานะตามเส้นทางเว็บเดิม ปุ่มนี้เปิดเอกสารเพื่อให้ผู้ใช้ตรวจและอนุมัติบนเว็บ ไม่ใช่อนุมัติทันทีใน LINE

ช่องว่างที่ตรวจพบแต่ยังไม่ได้แก้: `NotificationsListOpenAlertsTool` ปัจจุบันให้ลิงก์หน้า `/notifications` และไม่ส่ง request ID/detail link มาด้วย ลิงก์เก่าใน fixture ใช้ hub + `tab=approvals&focus=…`; hub ปัจจุบันเปิด journey แยกและไม่อ่าน focus แล้ว ตอนทำจริงต้องส่ง reference ของใบเบิกที่ตรวจสิทธิ์แล้วมาให้ตัวการ์ด ห้ามเดา request ID จากเลขใบเบิก หรือเรียกปุ่มว่าเปิดใบเบิกแต่พาไปหน้ารวมแจ้งเตือน

## การตรวจรับและการเปลี่ยนแบบ

- ใช้สำเนา รูป และ screenshots ในชุดหลักฐานเป็น baseline เปรียบเทียบที่ความกว้าง 320px และ 736px รวมกรณีข้อความยาว ไม่พบรายการ และการเปลี่ยนสถานะที่ล็อกแล้ว
- คง canonical answer, permission/tenant checks และขอบเขตการยืนยัน/อนุมัติเดิม การล็อกดีไซน์ไม่เปลี่ยนกฎธุรกิจหรือสิทธิ์
- เมื่อลง native LINE Flex ต้องตรวจบน LINE จริงว่าหัว มาสคอตที่ยื่น ชั้นพื้นขาว สี แถวและปุ่มตรงตามแบบ ผลตรวจ HTML 40 กรณีเป็นหลักฐานดีไซน์ ไม่ใช่การรับรอง native rendering หรือการเผยแพร่
- หากแพลตฟอร์มทำองค์ประกอบใดให้ตรงไม่ได้ ให้รายงานจุดนั้น ห้ามเลือกดีไซน์อื่นแทนเอง การเปลี่ยน baseline ทำได้เมื่อมีคำสั่งใหม่จากเจ้าของเท่านั้น และต้องบันทึก revision ใหม่โดยรักษาสำเนาที่ล็อกนี้ไว้
