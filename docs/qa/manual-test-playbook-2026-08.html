1. ภาพรวมระบบ + แผนที่เมนูจริงของ release นี้

ระบบมี 3 โลก: คอนโซลแอดมินแพลตฟอร์ม (/system), เว็บบริษัท (/companies/{id}), และ LINE (2 OA) — เข้าใจแผนที่นี้ก่อน จะได้รู้ว่าจุดไหน "หายไป" คือบัค จุดไหนคือตั้งใจซ่อน

ภาพที่ 1 — สามโลกของระบบ และเส้นทางข้อมูลเข้า API เดียวกัน

1.1 กติกาที่ต้องเข้าใจก่อนเล่น: เมนูโผล่/หาย เพราะ 2 ระนาบคูณกัน

ระนาบใครตั้งเมื่อไม่ผ่าน จะเห็นอะไร
สิทธิ์ (permission) — บทบาทของพนักงานOwner/Admin ตั้งใน "พนักงานและสิทธิ์"เมนูหาย · เข้าตรงถูกเด้งไปหน้าแรกที่เปิดได้ · ถ้ายิง API: 403 คุณไม่มีสิทธิ์ทำรายการนี้ กรุณาติดต่อเจ้าของร้าน
ฟีเจอร์ (entitlement) — แพ็กเกจของบริษัทSYSTEM_ADMIN ตั้งใน /system/partners/{id}ระบบ "ริบ permission" ของฟีเจอร์นั้นทุกคนทั้งบริษัท → เมนูหาย + API ตอบ 403 code feature_not_enabled → เว็บแปลเป็น ยังไม่ได้เปิดฟีเจอร์นี้
⚠ สำคัญ: ฟีเจอร์ปิดแล้ว "เมนูหายเงียบๆ" ไม่มีหน้า fallback ยกเว้น รายงาน ตัวเดียวที่มีหน้า "ประวัติรายงาน" (ดาวน์โหลดไฟล์เดิมได้) — ข้อความ fallback สวยๆ ต่อฟีเจอร์อย่าง "ยังไม่ได้เปิดระบบสต๊อก" ไม่มีอยู่ในระบบ อย่าตามหา

4กด บันทึกฉบับร่างเด้งไปหน้ารายละเอียด สถานะ "ฉบับร่าง" · เคสสำคัญ: ถ้า draft สำเร็จแต่แนบไฟล์ล้ม → บันทึกฉบับร่างแล้ว แต่แนบใบเสร็จไม่สำเร็จ: … และปุ่มเปลี่ยนเป็น เปิดรายการที่บันทึกไว้ — กดซ้ำต้องไม่สร้างใบที่สอง

5.4 หน้ารายละเอียด — ตรวจ 3 ขั้น แล้วยืนยัน (/expenses/{expenseId})

ซ้าย = ตัวดูเอกสาร (เลื่อนหน้า ‹1/3›, เปิดเต็มจอ, โหลดไฟล์ใหม่ — ลิงก์ไฟล์หมดอายุ 15 นาที) · ขวา = ฟอร์ม 3 ขั้น: ตรวจข้อมูล → ภาษีและเอกสาร → ตรวจก่อนส่ง

#ขั้นตอนผลที่คาดหวัง☑
1ขั้น 1 ตรวจข้อมูล: เช็คแถบ AI (AI อ่านข้อมูลได้ครบแล้ว — ตรวจทานให้ตรงกับใบเสร็จ หรือชิปเหลือง ต้องกรอกเอง: {ช่อง} + ปุ่ม อ่านเอกสารอีกครั้ง) แล้วกรอก: ชื่อผู้ขาย* · เลขผู้เสียภาษีผู้ขาย (13 หลัก auto-format) · เลขที่เอกสาร · วันที่ค่าใช้จ่าย* · รูปแบบ VAT (5 แบบ) · รายการสินค้า (จำนวน/ราคา/ส่วนลด/หัก ณ ที่จ่าย/อัตรา VAT ต่อบรรทัด)วันที่อนาคต → วันที่ในใบเสร็จต้องไม่เกินวันนี้ · เลขภาษีไม่ครบ → เลขประจำตัวผู้เสียภาษีต้องมี 13 หลัก · ปุ่ม ถัดไป disable พร้อม tooltip ยังมีข้อมูลที่ต้องแก้ {n} รายการ · กดถัดไป = บันทึกอัตโนมัติ (บันทึกข้อมูลและคำนวณยอดใหม่แล้ว) — ไม่มีปุ่ม Save แยก
2การ์ดยอดเงิน: ตรวจ ฐานภาษี → VAT → ยอดรวมทั้งสิ้น → หัก ณ ที่จ่าย → ยอดที่ต้องชำระจริง (หลังหัก ณ ที่จ่าย)ใส่หัก ณ ที่จ่าย 0.03 ในบรรทัด → ระบบโชว์ = 3% และช่อง ประเภทผู้รับเงิน (หัก ณ ที่จ่าย) โผล่ (บุคคลธรรมดา ภ.ง.ด.3 / นิติบุคคล ภ.ง.ด.53) — ไม่เลือกแล้วยืนยันไม่ได้
3ขั้น 2 ภาษีและเอกสาร: เลือก ประเภทเอกสาร (ใบเสร็จรับเงิน / ใบกำกับภาษีเต็มรูป / อย่างย่อ / สลิปโอน / บิลเขียนมือ / สกรีนช็อตคำสั่งซื้อ ฯลฯ) + สถานะหลักฐานภาษี + หมวดหมู่ค่าใช้จ่าย แล้วกด บันทึกการตรวจเลือก "ใบกำกับภาษีอย่างย่อ" → สถานะหลักฐานเปลี่ยนเป็น หลักฐานประกอบเท่านั้น อัตโนมัติ + Tax Code บนบรรทัดถูกล้าง (ขอคืน VAT ไม่ได้) · toast บันทึกการตรวจเอกสารเรียบร้อยแล้ว
4ขั้น 3 ตรวจก่อนส่ง: ดู สรุปการตรวจ (ผ่าน n รายการ · ต้องตรวจ m รายการ) แล้วกด ส่งตรวจสอบสถานะเปลี่ยนเป็น "พร้อมยืนยัน" · toast ส่งตรวจสอบเรียบร้อยแล้ว
5login เป็นคนมีสิทธิ์ยืนยัน (qa.finance / qa.owner) เปิดใบเดิม กด ยืนยันเอกสาร (ปุ่มเขียว)ได้เลข EXP-YYYYMM-##### · toast ยืนยันและลงบัญชีเรียบร้อยแล้ว · เอกสารล็อคแก้ไม่ได้ มีบรรทัด เอกสารยืนยันแล้ว แก้ไขข้อมูลไม่ได้ · หากข้อมูลไม่ถูกต้อง ให้ยกเลิกเอกสารแล้วบันทึกใหม่ + การ์ด สถานะบัญชี ขึ้น (รอ JV / JV-... / ไม่ต้องลงสมุด)
6เช็คเงื่อนไขที่ปุ่มยืนยันต้อง disable (hover อ่าน tooltip)มี 5 เหตุ: รายการซ้ำค้าง / ไม่มีใบเสร็จหรือใบรับรองแทน (ต้องแนบใบเสร็จ หรือจัดทำใบรับรองแทนใบเสร็จรับเงินให้เสร็จก่อนยืนยัน) / ยอด AI ไม่ตรง / ยอดรวมเป็นศูนย์ (ยอดรวมเป็นศูนย์ — กรุณาตรวจสอบรายละเอียดก่อนยืนยันเอกสาร) / ใบรับรองแทนยังไม่ออกฉบับสมบูรณ์
7บันทึกการจ่าย: ในใบที่ยืนยันแล้ว การ์ด การชำระเงิน ใส่ยอด + วิธี (เงินสด/โอนเงิน/บัตรเครดิต/เช็ค/อื่นๆ) กด บันทึกชำระtoast บันทึกการจ่ายเรียบร้อยแล้ว · ประวัติการจ่าย append ต่อท้าย จ่ายเกินยอดคงค้างไม่ได้ · จ่ายครบ → badge เปลี่ยนเป็น "ชำระแล้ว"
8ยกเลิกเอกสาร (void): ใบ CONFIRMED กด ยกเลิกเอกสาร ใส่ เหตุผลยกเลิก (ต้อง ≥3 ตัวอักษร)toast ยกเลิกเอกสารเรียบร้อยแล้ว · ถ้าเคยลงบัญชี JV จะถูกกลับรายการ (reversal) อัตโนมัติ · สถานะจบที่ VOIDED ถาวร
9ตีกลับ (reject → เริ่มใหม่): ใบที่ยังไม่ยืนยัน กด ยกเลิกรายการ + เหตุผล → แล้วกด เริ่มตรวจใหม่REJECTED โชว์เหตุผลสีแดง → เริ่มตรวจใหม่แล้วกลับมาที่ "รอตรวจสอบ" (ไม่กระโดดไปพร้อมยืนยันทันที) · หมายเหตุ: การ "ตีกลับใบที่ CONFIRMED ไปแก้" ไม่มีในระบบ (spec มีแต่ยังไม่ทำ) — ทางเดียวคือ void

5.5 ระบบตรวจใบซ้ำ (duplicate detection)

#ขั้นตอนผลที่คาดหวัง☑
1อัปโหลดไฟล์เดียวกันซ้ำ 2 รอบใบที่สองขึ้นการ์ดเหลือง ⚠ คำเตือน: อาจซ้ำกับรายการอื่น ระบุคู่ซ้ำ + คะแนน + เหตุผล ไฟล์เอกสารเป็นไฟล์เดียวกัน (คะแนน 40)
2ถ่ายรูปใบเสร็จใบเดิมมุมใหม่ (คนละไฟล์)ยังจับได้ด้วย perceptual hash → เหตุผล ภาพเอกสารเหมือนกัน (คะแนน 35)
3คีย์มือ 2 ใบ: ผู้ขายเดียวกัน + วันเดียวกัน + ยอดเท่ากัน แล้วกดปุ่ม ตรวจหารายการซ้ำtoast พบรายการที่อาจซ้ำ {n} รายการ (เกณฑ์ 25 คะแนน) หรือ ไม่มีรายการซ้ำ
4กด ยืนยันว่าเป็นรายการซ้ำ (ใส่เหตุผล ≥3 ตัว)ใบนี้กลายเป็น CONFIRMED_DUPLICATE — จะไม่ลงบัญชีตลอดไป (สถานะบัญชีขึ้น "-") + คู่เทียบที่เหลือถูกปิดอัตโนมัติ · กด ไม่ใช่รายการซ้ำ = ปลดล็อคยืนยันได้
5คู่ซ้ำอยู่คนละสาขา (ผู้ตรวจไม่มีสิทธิ์เห็นอีกสาขา)เห็นข้อความ พบรายการที่อาจซ้ำ แต่ต้องให้ผู้ตรวจสอบที่มีสิทธิ์เข้าถึงรายการคู่ซ้ำเป็นผู้ตัดสิน และไม่มีปุ่มตัดสิน

5.6 หน้ารายการ / หมวดหมู่ / หลักฐานทางบัญชี

#จุดตรวจผลที่คาดหวัง☑
1รายการค่าใช้จ่าย (/expenses): ตัวกรอง รายวัน/รายเดือน + ปุ่มวันนี้ · ชิปสถานะ (ทั้งหมด/ฉบับร่าง/รอตรวจสอบ/ยืนยันแล้ว/ปฏิเสธ) · ช่องค้นหา · KPI 5 ใบ (ค่าใช้จ่ายรวม / รอตรวจสอบ / ค้างจ่าย / เกินกำหนดชำระ / ภาษีซื้อ VAT)เปิดใบแล้วกด back — ตัวกรองเดิมต้องคงอยู่ · reload หรือสลับเมนู — ตัวกรอง reset (ตั้งใจ) · แถวที่ยกเลิกไม่ถูกนับใน KPI
2ปุ่ม ส่งออก Excel + ชุดคอลัมน์ แบบย่อ (อ่านง่าย) / แบบเต็ม (สำนักงานบัญชี)ช่วงที่ไม่มีใบยืนยัน → toast เหลือง ไม่มีรายการที่ยืนยันแล้วในช่วงนี้ จึงยังส่งออกไม่ได้
3ปุ่มลบ (ถังขยะ) ในแถวModal ลบรายการ “…” อย่างถาวร? → ลบถาวร ทำได้เฉพาะ DRAFT/REJECTED (หรือใบ 0 บาทที่ยังไม่จ่าย) · ใบที่มีข้อมูลเชื่อม (จ่ายแล้ว/ลง JV/มีภาษี) → ลบรายการนี้ไม่ได้ เนื่องจากมีข้อมูลเชื่อมโยง: {อะไร}
4หมวดหมู่ (/expenses/categories): ปุ่ม + เพิ่มหมวดหมู่ใหม่ · rename ด้วยดินสอ · เลือก Tax Code เริ่มต้น ต่อแถว · toggle เก็บถาวรหมวด ค่าเริ่มต้นระบบ (12 หมวด seed) แก้/ลบไม่ได้ · Modal เก็บถาวรอธิบาย หมวดหมู่ที่เก็บถาวรจะไม่แสดงให้ AI หรือผู้ใช้เลือกอีก แต่รายการเดิมที่ใช้หมวดนี้ยังอยู่ครบ · Tax Code เริ่มต้นมีผลแค่ "แนะนำ" ตอนบรรทัดยังไม่เลือกเอง
5หลักฐานทางบัญชี (/expenses/evidence): มุมมองส่งงานสำนักงานบัญชี — โฟลเดอร์ปี/เดือน + ชิป ⚠ ต้องตรวจ / ไม่มีไฟล์ / ยังไม่ตรวจภาษี / ไม่มีผู้ขาย / ยังไม่จัดหมวดโชว์เฉพาะใบยืนยันแล้ว (กับยกเลิก) · ปุ่ม ส่งออกชุดเอกสารให้บัญชี → ได้ XLSX + ดาวน์โหลดรายการหลักฐาน (JSON) ที่มีลิงก์ไฟล์หมดอายุ · ปุ่ม ตรวจรายการเก่าก่อน Auto-post เปิด modal ลงบัญชีย้อนหลัง (สูงสุด 50 ใบ/ครั้ง)

5.7 Checklist หาบัคเพิ่ม (VAT / AI / ความพร้อมกัน)

  • VAT ไม่ระบุ ≠ 0%: ตั้งรูปแบบ "VAT รวมในราคา" แต่ปล่อยอัตรา ยังไม่ระบุ → ต้องโดนบล็อค เอกสารนี้ระบุว่ามี VAT — กรุณาเลือกอัตรา หรือกรอกยอด VAT ตามใบเสร็จ · ส่วนเลือก 0% จริงๆ (ส่งออก) ต้องยืนยันผ่านและไม่เด้งกลับเป็น 7%
  • กรอกยอด VAT ตามใบเสร็จ: เลือก "อัตราอื่น" แล้วใส่ยอดบาท (เช่น 11.78) → ระบบคำนวณอัตราย้อนกลับให้เอง — เทียบกับใบจริงต้องเป๊ะ ±0.05
  • ยอด AI ไม่ตรง: แก้ยอดให้ต่างจากที่ AI อ่าน > ฿0.05 → การ์ดเหลืองบังคับใส่เหตุผล + ปุ่ม รับรองว่ายอด ฿X ถูกต้อง · รับรองแล้วแก้ยอดอีกครั้ง → บล็อคต้องกลับมาใหม่ (การรับรองผูกกับยอดเป๊ะๆ)
  • 2 แท็บชนกัน: เปิดใบเดียวกัน 2 แท็บ บันทึกแท็บแรก แล้วบันทึกแท็บสอง → ต้องเจอ error ให้ reload ไม่ใช่เขียนทับเงียบๆ
  • อักขระพิเศษ: พิมพ์ <script> หรือ & ในชื่อผู้ขาย → ห้ามใช้อักขระพิเศษ: …
  • ใบเสร็จเที่ยงคืน: สร้างใบเวลา ~23:50 → ตัวกรอง "รายวัน" ของวันนั้นต้องยังหาเจอ (วันที่เก็บแบบ date-only)
  • ลิงก์ไฟล์หมดอายุ: เปิดหน้ารายละเอียดทิ้งไว้ 20 นาที รูปจะโหลดไม่ขึ้น → ปุ่ม โหลดไฟล์ใหม่ ต้องกู้กลับมาได้ (กดถี่สุด 1 ครั้ง/20 วิ)
  • ส่วนลดเกินยอด: ใส่ส่วนลดมากกว่าจำนวน×ราคา → ส่วนลดมากกว่ายอดของรายการนี้
  • บริษัทไม่จด VAT (SIMPLE mode): ทั้งหน้า manual/review/evidence ต้องไม่มีส่วนภาษีเลย — แต่ใบเก่าที่เคยมี VAT ต้องยังโชว์ส่วนภาษีของมันได้

6.2 Hub + เริ่ม wizard

#ขั้นตอนผลที่คาดหวัง☑
1เปิดเมนู ใบรับรองแทนใบเสร็จหัว ใบรับรองแทนใบเสร็จรับเงิน + ปุ่ม + สร้างใบรับรองฉบับใหม่ · KPI 4 ใบ (ออกเอกสารแล้วเดือนนี้ / มูลค่ารวม / รอลงนาม-รออนุมัติ / ยกเลิกแล้ว) · ถ้ามีงานค้างของเรา จะมีการ์ด รอคุณลงนาม (n) / รอคุณอนุมัติ (n) กดแล้วกระโดดเข้าใบแรก · ตัวกรองสถานะ + เดือนที่จ่ายเงิน
2กดสร้าง — ดูแถบเส้นทาง เส้นทางการจัดทำเอกสาร4 สถานี: รายการค่าใช้จ่าย → ข้อมูลและหลักฐาน → ลงนามและอนุมัติ → รับเอกสาร + ขั้นตอน {n} จาก 4 · มีแถบเตือนภาษีทุกครั้ง: เอกสารนี้ไม่ใช่ใบกำกับภาษี จึงใช้ขอคืน VAT ไม่ได้ และไม่ยกเว้นหน้าที่ภาษีหัก ณ ที่จ่าย
3ขั้น 1: ตอบคำถาม รายการนี้ถูกบันทึกในระบบแล้วหรือยัง?① บันทึกรายการไว้แล้ว (badge แนะนำ) → ตัวเลือกโชว์เฉพาะใบที่เข้าเกณฑ์: ยังไม่ยืนยัน + ไม่มีไฟล์ใบเสร็จหลัก + สกุล THB + ยอด > 0 + ทุกบรรทัดมีรายละเอียด ② ยังไม่ได้บันทึกรายการ → ฟอร์มย่อสร้าง draft สดในหน้านี้ (สูงสุด 8 บรรทัด) พร้อมคำอธิบาย สิ่งที่จะเกิดขึ้น: ระบบจะสร้างรายการค่าใช้จ่าย "ฉบับร่าง" และเลือกให้โดยอัตโนมัติ...
4เลือกใบแล้วต้องติ๊ก consentกล่องเหลืองบังคับติ๊ก ข้าพเจ้ารับทราบและยืนยันการดำเนินการ * · rail ขวา ผู้ช่วยตรวจความพร้อม ต้องขึ้น ข้อมูลส่วนนี้ครบแล้ว พร้อมไปต่อ ก่อนกด ยืนยันรายการนี้และกรอกข้อมูลต่อ

6.3 ขั้น 2 — ผู้รับเงินและเหตุผล + ขั้น 3 — แนบหลักฐาน

#ขั้นตอนผลที่คาดหวัง☑
1กรอกส่วน ผู้รับเงินคือใคร: ชื่อผู้รับเงิน* (≤200) · ที่อยู่ (ไม่บังคับ ≤300) · เลขบัตร ปชช./ผู้เสียภาษี (ถ้ากรอกต้อง 13 หลัก มี counter กรอกแล้ว {n} จาก 13 หลัก)ผิดเงื่อนไขขึ้น error รายช่อง เช่น เลขประจำตัวต้องมี 13 หลัก
2ส่วน ทำไมจึงไม่มีใบเสร็จ: เลือกประเภทเหตุผล (4 แบบ: ผู้รับเงินไม่สามารถออกใบเสร็จ / ไม่ได้ออกให้ / หลักฐานไม่ครบถ้วน / อื่น) + เหตุผล* + วัตถุประสงค์ทางธุรกิจ *มีคำเตือน หากเคยได้รับใบเสร็จแล้วแต่เอกสารสูญหาย ควรขอสำเนาหรือใบแทนจากผู้ออกก่อน...
3ส่วน ใครจ่าย และจ่ายอย่างไร: เลือก ผู้จ่ายเงินจริง * (dropdown สมาชิกในสาขา) + วิธีชำระ (เงินสด/โอนเงิน/บัตรเครดิต/เช็ค/วิธีอื่น) + วันที่ชำระเงิน*ผู้จ่ายเงินจริงคือคนที่ต้องลงนามเอง ในขั้นถัดไป — เลือกคนอื่นเพื่อทดสอบ flow 2 คน
4ขั้น 3 แนบหลักฐาน — 2 การ์ด: หลักฐานประกอบรายการ * (บังคับ ≥1 เสมอ) และ หลักฐานการชำระเงิน (บังคับเมื่อไม่ใช่เงินสด หรือเงินสด+นโยบายเข้ม)เลือกไฟล์เดิมของ expense หรืออัปใหม่ (รองรับไฟล์รูปภาพและ PDF) · รวมทุกไฟล์ได้สูงสุด 8 ไฟล์ — เกิน → ใบรับรอง 1 ใบรองรับหลักฐานรวมได้สูงสุด 8 ไฟล์ กรุณานำไฟล์ที่ไม่จำเป็นออก · จ่ายเงินสดมีปุ่มพิเศษ พิมพ์แบบฟอร์มใบสำคัญรับเงิน (ดาวน์โหลด PDF ไปให้ผู้รับเงินเซ็น แล้วถ่ายรูปกลับมาแนบ)
5กด จัดทำเอกสารเพื่อให้ผู้จ่ายเงินลงลายมือชื่อได้เลข SRC-YYYYMM-##### · สถานะ PREPARED · แจ้งเตือนวิ่งไปหาผู้เกี่ยวข้อง (ใบรับรองแทนใบเสร็จรอการลงลายมือชื่อ เลขที่ SRC-…) · ผลข้างเคียงที่ต้องรู้: expense ต้นทางถูกปรับ tax evidence เป็น "หลักฐานประกอบเท่านั้น" + ภาษีซื้อขอคืนไม่ได้ ทันที

6.4 ขั้น 4 — ลงนาม 2 คน แล้วรับเอกสาร

#ขั้นตอนผลที่คาดหวัง☑
1ถ้าเราไม่ใช่ผู้จ่าย: ดูหน้าจอรอรอผู้จ่ายเงิน ({ชื่อ}) ลงลายมือชื่อด้วยตนเอง + ปุ่ม คัดลอกลิงก์สำหรับส่งให้ผู้ลงนาม (→ คัดลอกลิงก์แล้ว)
2login เป็นผู้จ่ายเงินจริง เปิดลิงก์ — ทำ 4 บล็อค: ① ตำแหน่งของผู้จ่ายเงิน * ② ตรวจสอบเอกสารฉบับเต็ม * (ต้องเปิด preview จนโหลดเสร็จถึงได้ badge ตรวจแล้ว) ③ ลายมือชื่อ — วาดบนจอ หรืออัปโหลดรูปแล้วกด ลบพื้นหลังสีอ่อนและตรวจสอบลายมือชื่อ ④ ติ๊กคำรับรอง ข้าพเจ้าขอรับรองว่ารายจ่ายนี้เกิดขึ้นจริงเพื่อกิจการ...ข้ามการ preview → กรุณาเปิดและตรวจสอบเอกสารฉบับเต็มก่อนลงลายมือชื่อ · รูปลายเซ็นต้อง PNG/JPEG ≤2MB · กด ลงลายมือชื่อรับรอง → toast ผู้จ่ายเงินลงลายมือชื่อรับรองแล้ว → สถานะ PAYER_CERTIFIED
3login เป็นผู้อนุมัติ — ขั้นตอนเหมือนกัน: เปิดฉบับที่ผู้จ่ายลงนามแล้ว* → ตำแหน่ง* → ลายมือชื่อ* → ติ๊ก ข้าพเจ้าได้ตรวจสอบเอกสารและหลักฐานแล้ว และอนุมัติ... → กด อนุมัติและออกเอกสารสถานะ ISSUED · หน้าจบมี ✓ ใหญ่ จัดทำใบรับรองแทนใบเสร็จรับเงินเสร็จสิ้น + ปุ่ม ดาวน์โหลด PDF / เปิดดูเอกสาร / ไปยืนยันรายการเพื่อบันทึกบัญชี
4ตรวจ PDF ที่ได้หัว ใบรับรองแทนใบเสร็จรับเงิน + เลขที่ + ข้อมูลบริษัท/สาขา/เลขภาษี + ตารางรายการ + รวมเป็นตัวอักษร: …บาทถ้วน + เหตุผล + วัตถุประสงค์ + กล่องคำรับรอง + ลายเซ็น 2 ช่อง + footer เอกสารนี้เป็นหลักฐานประกอบรายจ่ายภายใน มิใช่ใบกำกับภาษี และไม่ก่อสิทธิภาษีซื้อโดยลำพัง · ชื่อไฟล์ = เลขเอกสาร.pdf
5กลับไปดู expense ต้นทางระบบตั้งเป็นชำระแล้วให้อัตโนมัติ (ยอดค้าง 0, มีรายการจ่ายตามวิธี/วันที่ในใบรับรอง) → เหลือแค่กด ยืนยันเอกสาร ปิดจบ
6ยกเลิก/ฉบับแก้ไข: ใน panel ประวัติและการจัดทำฉบับแก้ไข ใส่เหตุผล* แล้วกด ยกเลิกฉบับนี้และเก็บประวัติ → แล้วกด จัดทำฉบับแก้ไขฉบับเดิมกลายเป็น SUPERSEDED (PDF จะมีตราประทับแดง SUPERSEDED ชื่อไฟล์ต่อท้าย -SUPERSEDED) · ฉบับใหม่เริ่มที่ขั้นข้อมูลโดย prefill ผู้จ่ายเดิม · void expense ที่มีใบ ISSUED → ใบรับรองโดนประทับ VOID อัตโนมัติ

6.5 Checklist หาบัค — จุดที่ระบบต้องกันให้ได้

  • กติกาผู้อนุมัติ (อัปเดต 2026-08-10): โหมด OWNER_SELF — OWNER/ADMIN/MANAGER ที่เป็นผู้จ่ายเอง อนุมัติใบตัวเองได้ (role exemption เดียวกับเบิกจ่าย) · role อื่น (เช่น FINANCE ล้วน) ที่เป็นผู้จ่าย พยายามอนุมัติใบตัวเอง → ต้องโดนปฏิเสธ · โหมดกำหนดผู้อนุมัติยังเข้มเหมือนเดิม (คนละคนเสมอ)
  • โหมดกำหนดผู้อนุมัติ: ตั้งผู้อนุมัติคนเดียว = คนเดียวกับผู้จ่าย → กด "จัดทำเอกสาร" ต้องล้มตั้งแต่ต้น (ไม่มีผู้อนุมัติที่ valid)
  • แก้ใบระหว่างทาง: เตรียมเอกสารแล้ว (PREPARED) → ไปแก้ยอด expense → กลับมาลงนาม → ต้องโดนบล็อคให้เตรียมฉบับใหม่ (ข้อมูลบนเอกสารต้องตรงกับ expense เป๊ะ)
  • กดสร้างรัวๆ: ดับเบิลคลิกปุ่มจัดทำเอกสาร → ต้องได้เลข SRC เดียว ไม่เผาเลข 2 เบอร์
  • ไฟล์ซ้ำสองช่อง: เลือกไฟล์เดียวกันเป็นทั้ง "หลักฐานประกอบ" และ "หลักฐานการชำระเงิน" → server ต้องปฏิเสธ
  • เปลี่ยนวิธีชำระกลางทาง: เงินสด→โอนเงิน หลังผ่านขั้น 2 → การ์ดหลักฐานการชำระเงินต้องเปลี่ยนจาก "ไม่บังคับ" เป็น จำเป็น สดๆ
  • เปลี่ยนนโยบายกลางทาง: เตรียม+ลงนามใบเงินสดไว้ (ไม่มีไฟล์หลักฐานจ่าย นโยบายผ่อน) → admin เปลี่ยนนโยบายเป็นเข้ม → ผู้อนุมัติกดอนุมัติ → ต้องโดนบล็อคให้ทำฉบับใหม่
  • STAFF ที่เป็นผู้จ่าย: พนักงานสิทธิ์ต่ำสุดที่ถูกระบุเป็นผู้จ่าย เปิดลิงก์จากแจ้งเตือน → ต้องดู+ลงนามใบของตัวเองได้ (ไม่ต้องมีสิทธิ์ expense.review)
  • ข้ามเดือน: ออกใบวันสิ้นเดือน แล้วอีกใบวันที่ 1 → เลขต้องรีเซ็ต SRC-202608-xxxxx → SRC-202609-00001
  • ✔ แก้แล้ว (2026-08-10) — ทดสอบการ revert: ออกใบจน ISSUED (expense กลายเป็น "ชำระแล้ว") → กดยกเลิกฉบับ (supersede) → expense ต้องกลับเป็น "ยังไม่ชำระ" ยอดค้างกลับมาเต็ม รายการจ่ายที่ระบบสร้างตอนออกเอกสารถูก void และวิธีจ่าย/วันที่จ่ายถูกล้าง
  • มือถือ: วาดลายเซ็นด้วยนิ้วบนจอมือถือ — เส้นต้องไม่ขาด ปุ่ม ล้างลายมือชื่อ ทำงาน

8.4 Checklist หาบัค — การป้องกันที่ต้องมีจริง

  • ป้องกัน OWNER: ระงับ/ลบ/เปลี่ยนตำแหน่ง/เปลี่ยนสาขา OWNER — ทุกทางต้องทำไม่ได้ (ทั้งปุ่มหายและ API ปฏิเสธ)
  • กันยกระดับสิทธิ์: MANAGER (ไม่มี access.role.manage) พยายามตั้งใครเป็น role ที่จัดการคนได้ / ระงับคนที่ถือ role นั้น → ถูกกัน · การมอบ role FINANCE/ACCOUNTANT ต้องเป็น owner เท่านั้น
  • สร้าง role เกินตัว: คนที่ไม่มีสิทธิ์ X สร้าง role ที่มีสิทธิ์ X → ต้องโดนตัด เกินสิทธิ์ที่คุณมี (มอบให้ไม่ได้) (ยกเว้น OWNER)
  • 🐞 ตำแหน่งชื่อไทยล้วน: สร้าง role พิมพ์ชื่อไทยเองโดยไม่กด preset (เช่น "หัวหน้าร้าน") → ระบบสร้าง key เป็น ROLE → คนใน role นี้จะไม่โผล่ในคิวอนุมัติเบิกจ่ายที่ route หา MANAGER — ทดสอบต่อเนื่องกับ §7 แล้วจดถ้าจริง
  • Wizard ค้างกลางทาง: ปิด browser ก่อนกดเสร็จสิ้น → รายชื่อมีแถว Draft ค้าง → เข้า wizard ใหม่ด้วยเลขบัตรเดิม → ต้อง resume draft เดิม (รหัสผ่านใหม่ + QR ใหม่) ไม่ใช่ error ซ้ำ
  • ข้อมูลซ้ำ: เลขบัตร/เบอร์/อีเมลซ้ำกับพนักงาน active คนอื่น → ต้องแจ้ง conflict ชัดเจน ไม่ใช่ error 500
  • รีเซ็ตรหัสของคนข้ามบริษัท (attach): ต้องถูกปฏิเสธ — บัญชีเป็นของอีกบริษัท ("...cannot be regenerated here")
  • 🐞 ข้อความเก่าขัดกับพฤติกรรมจริง: ถ้าเจอหน้าจอที่บอกว่า "ไม่ต้องเปลี่ยนรหัสผ่านตอนเข้าสู่ระบบครั้งแรก" — อันนี้เป็น copy ตกค้าง โค้ดจริงบังคับเปลี่ยนเสมอ — จดที่พบ

#ขั้นตอนผลที่คาดหวัง☑

11. Flow เสริมที่เปิดใน release นี้

ทุกตัวในหมวดนี้ทำงานจริงแล้ว — บางตัวมีเมนู บางตัวต้องเข้าทาง URL ตรง (ดูตาราง §1.2) · แต่ละหัวข้อคือ happy path + จุดหาบัคแบบกระชับ

11.1 เอกสารขายและรับชำระ (/sales-documents) — ใบเสร็จ/บิลฝั่ง "ขาย"

เอกสาร 7 ประเภท: ใบเสนอราคา (QT-) · ใบแจ้งหนี้ (INV-) · ใบวางบิล (BN-) · ใบเสร็จรับเงิน (REC-) · ใบกำกับภาษี (TAX-) · ใบลดหนี้ (CN-) · ใบเพิ่มหนี้ (DN-) — เลขจริงออกตอนกด Issue

#ขั้นตอนผลที่คาดหวัง☑
1ฟอร์มซ้าย "New document": เลือกประเภท + วันที่ + VAT mode + หัก ณ ที่จ่ายที่ลูกค้าจะหัก (%) + บริบทธุรกรรม (ขายในประเทศ/ส่งออก) + บรรทัดสินค้า + Tax Code → Save drafttoast บันทึกร่างเอกสารเรียบร้อยแล้ว · ใบกำกับภาษีบังคับมี Tax Code ทุกบรรทัด
2เลือกใบ → ปุ่ม action ตามสถานะ: แก้ไข Draft → (QT: Submit approval → Approve/Reject) → Issue → Convert to invoice → Create tax invoice → Create credit/debit note → VoidIssue ได้เลขจริง + toast ออกเอกสารเรียบร้อยแล้ว · Void ต้องใส่เหตุผล และกลับรายการบัญชีแบบ true reversal · ไม่มีปุ่มพิมพ์ PDF เอกสารขาย (ยังไม่ทำ — อย่าตามหา)
3Record payment (ใบ INV/BN/DN ที่ Issue แล้ว): เงินสดที่ได้รับ + ถูกหัก ณ ที่จ่าย + เลขที่หนังสือรับรองหัก ณ ที่จ่าย (50 ทวิ) + วิธีชำระเงินสด+WHT รวมเกินยอดค้างไม่ได้ · จ่ายครบ → payment status ชำระแล้ว · การรับเงินไปโผล่เป็น candidate ฝั่งกระทบยอดธนาคาร (§11.5)
4สลับสถานะเอกสารครบวงจร: QT → approve → issue → convert → INV → issue → payment → REC/TAX → CNสถานะไล่: ร่าง → รอการอนุมัติ → อนุมัติแล้ว → ออกแล้ว → ชำระแล้ว/ออกใบลดหนี้แล้ว · ตัวเลขเอกสารรันตามเดือน ไม่ข้ามเบอร์

2เจ้าหนี้ แท็บ ใบวางบิล: ฟอร์ม บันทึกบิลผู้ขาย — เลือก ผู้ขาย และ ประเภทการซื้อ · กรอก วันที่เอกสาร, วันที่ครบกำหนดชำระ, รายละเอียดสินค้า/บริการ, จำนวน, ราคาต่อหน่วย (บาท) และ เลขที่เอกสารผู้ขาย (ถ้ามี) (ไม่แทนเลขใบกำกับภาษี) + Tax Code → บันทึกฉบับร่าง → แนบ หลักฐานภาษีซื้อ (เลขที่/วันที่ใบกำกับ + ไฟล์) → ยืนยันหลักฐาน → ส่งขออนุมัติ → อนุมัติชื่อผู้ขายต้องมองเห็นและตรงกับรายการที่บันทึก · เลขเอกสารผู้ขายเว้นว่างได้; เลขซ้ำของผู้ขายเดิมต้องแจ้งเป็นไทย เก็บค่าที่กรอก และเลื่อน/focus ข้อความให้เห็นใต้ header แม้ใช้มือถือ · หลักฐานไม่ครบ → รายการ blocking โชว์เป็นไทย (เช่น ผู้ขายยังไม่มีเลขประจำตัวผู้เสียภาษี) และปุ่มส่ง/อนุมัติ disable · นโยบาย maker-checker ตั้งได้ (ยอดเกิน N ต้องอนุมัติ 2 คน)
3แท็บ การชำระเงิน: บันทึกจ่ายเจ้าหนี้ — เลือกบิล + ยอดจ่าย (จ่ายบางส่วนได้!) + วิธี + fieldset หัก ณ ที่จ่าย (หมวดเงินได้ต้องเปิดใช้ที่หน้า /tax ก่อน + อัตรา% + ยอดหัก)ยอดโอนสุทธิ = ยอด − WHT · จ่ายครบ → บิล ชำระแล้ว · dropdown หมวดเงินได้ว่างเปล่า = ยังไม่ได้เปิดหมวดที่ /tax แท็บ WHT (จุดเชื่อม tax→AP ที่คนมักตกม้า)
4แท็บ หนังสือรับรองหัก ณ ที่จ่าย: กด ดูข้อมูลสำหรับออกเอกสาร → คัดลอกข้อมูลไปออก 50 ทวิภายนอก → กลับมา แนบเอกสาร (เลขที่+วันที่ออก)สถานะไล่ รอออกเอกสารภายนอก → แนบเอกสารแล้ว — ระบบไม่พิมพ์ 50 ทวิเอง (มีแบนเนอร์บอกตรงๆ)
5แท็บ AP AgingBucket ยังไม่ถึงกำหนด / 0–30 / 31–60 / 61–90 / 91+ วัน — ยอดรวมต้องตรงกับบิลค้างจ่ายจริง

#ขั้นตอนผลที่คาดหวัง☑
1กด ซิงค์แหล่งข้อมูลแบนเนอร์ ซิงค์สำเร็จ: ภาษีขาย n · ภาษีซื้อ n · WHT n · ปัญหา n · ล็อก n — งวดภาษีโผล่ซ้าย (ภ.พ.30 / ภ.พ.36 / ภ.ง.ด.3 / ภ.ง.ด.53 / ภ.ง.ด.50 / ภ.ง.ด.51)
2เลือกงวด → คำนวณรายงาน → ตรวจ ปัญหาที่ต้องตรวจสอบ + ตาราง รายการภาษี → Export (JSON/CSV/XLSX/PDF) → ยื่นแบบแล้ว → ชำระแล้วค่าใช้จ่ายที่ยืนยัน (มี VAT claimable) จาก §5 ต้องมาเป็นแถว "ภาษีซื้อ" · WHT ที่กรอกใน §5 มาเป็นแถว ภ.ง.ด.3/53 · งวดที่ยื่นแล้ว → ล็อกแล้ว (ไม่สามารถแก้ไข)
3แท็บ WHT: panel หมวดเงินได้ หัก ณ ที่จ่าย — กด เปิดใช้งาน หมวดที่ใช้ (seed มา 15 หมวดเป็น DRAFT ทั้งหมด)ก่อนเปิด: มีแบนเนอร์เหลืองเตือน + dropdown WHT ฝั่ง AP ว่าง · หลังเปิด: AP เลือกหมวดได้ (จุดเชื่อม tax→AP)
4Reconciliation (/tax/reconciliation): เลือกแบบ ภ.พ.30 + เดือน → สร้าง Reconciliation → ดู box 1–9 + ตารางไล่ Source→Event→Journal→Report → ยืนยันตรวจแล้วมี blocking issue → ปุ่มยืนยัน disable (ต้องแก้ blocking issues ที่ source/config ก่อน) · แถว delta คลิกย้อนกลับไปเอกสารต้นทางได้

13. บัคที่รู้อยู่แล้ว vs จุดต้องสงสัย

อ่านก่อนแจ้งบัค — ครึ่งแรกคือพฤติกรรมที่โค้ด "ตั้งใจหรือรู้ตัวอยู่แล้ว" (แจ้งซ้ำ = เสียเวลา dev) · ครึ่งหลังคือจุดที่วิเคราะห์โค้ดแล้วน่าจะเป็นบัคจริง รอคนกดยืนยัน

✅ รอบแก้บัค 2026-08-10 — สิ่งที่เปลี่ยนและควรเทสซ้ำ แก้แล้ว: ① supersede ใบทดแทน revert การจ่าย (§6.5) ② ใบเบิก REJECTED กดแก้ไขและยื่นใหม่ได้เลขเดิม (§7) ③ ปิดฟีเจอร์เบิกจ่าย = block เฉพาะใบใหม่ งานค้างไหลต่อ (§2.4) ④ self-approval exemption OWNER/ADMIN/MANAGER ใช้ทุก workflow รวมใบทดแทนโหมด OWNER_SELF (§6.5, §7.3) ⑤ QR ผูก LINE เจ้าของอายุ 72 ชม. (§2.2) ⑥ LINE fallback เป็นไทย ⑦ error สำนักงานใหญ่เป็นไทย ⑧ toggle กฎแจ้งเตือนแจ้ง error + สอง URL หน้ากฎใช้ guard เดียวกัน (notification.rule.manage) + กระดิ่งกรอง origin ของ deep link ⑨ แก้ตำแหน่งฝั่งผู้อนุมัติใบทดแทนแล้ว badge ตรวจแล้วถูก reset ⑩ FAQ เลขเอกสารในคู่มือในแอปอธิบายถูกแล้ว (SRC- รายเดือน) · ที่เหลือใน §13.2 (PO approval, ส่วนลด, ISO timestamp, role ชื่อไทย, ปุ่มเก็บถาวร catalog, เวลาเงียบ) ยังคงเดิมตามที่ระบุ — ไม่อยู่ในขอบเขต release นี้
✅ รอบแก้บัค #2 (2026-08-10 ค่ำ) — รอยต่อเบิกจ่าย → ค่าใช้จ่าย (จากผลเทส UAT) ใบ EXP ที่ระบบสร้างจากใบเบิก ("เบิกคืนพนักงาน: …") เปลี่ยนพฤติกรรมทั้งชุด: ① เกิดมาตรวจครบตั้งแต่ต้น — ประเภทเอกสาร เอกสารค่าใช้จ่ายอื่น, หลักฐานภาษี หลักฐานประกอบเท่านั้น, ไม่มี VAT/ขอคืนไม่ได้, เลขที่เอกสารอ้างอิง = เลขใบเบิก RB-… (หลายบรรทัดต่อท้าย -1, -2 กันชนตัวตรวจใบซ้ำ) → หน้าหลักฐานทางบัญชีต้องขึ้น ✓ ครบถ้วน ไม่มีธงแดงค้าง ② การเงินบันทึกจ่ายใบเบิก → ใบ EXP เปลี่ยนเป็น ชำระแล้ว อัตโนมัติ (void การจ่าย → ถอยกลับเป็นยังไม่ชำระ) ③ ฟอร์ม "บันทึกชำระ" บนใบ claim ถูกแทนด้วยข้อความ รายการนี้มาจากการเบิกคืนพนักงาน (ใบเบิก RB-…) และ API ปฏิเสธการจ่ายมือ (กันจ่ายซ้ำ) ④ บรรทัดเบิกที่ไม่มีใบเสร็จ: ลงบัญชีอัตโนมัติไม่ติด blocker แล้ว (ถือใบเบิกที่ลงนามเป็นหลักฐาน) และหน้าหลักฐานขึ้นชิปข้อมูล ใช้ใบเบิกที่ลงนามเป็นหลักฐาน แทนธงแดงไม่มีไฟล์ · ข้อมูลเก่าที่สร้างก่อน fix (เช่น EXP-202608-00002 บน UAT) ค้างสถานะเดิม — ใช้ใบใหม่ทดสอบ
✅ รอบแก้บัค #3 (2026-08-10) — OCR อ่านใบเสร็จ: เลขผู้เสียภาษี / เลขที่เอกสาร / สาขา (จากผลเทส UAT ใบเสร็จโรงพยาบาล) สเปก §19j + research รูปแบบเอกสารไทย (docs/specs/expense-receipt-upload-spec.md, docs/research/thai-receipt-field-format-conventions.md): ① AI ถูกสอนนิยาม 3 ฟิลด์ — เลขผู้เสียภาษี 13 หลัก (มองหัวและท้ายใบ รูปแบบมีขีด/เว้นวรรคได้ ใบกำกับเต็มรูปหยิบฝั่งผู้ขาย) · เลขที่เอกสาร ห้ามเป็นวันที่ / ห้าม HN·AN·VN / ห้ามเลขคิว·TID·เลขอนุมัติบัตร (เล่มที่ X เลขที่ Y รวมเป็น X/Y) · สาขา → 00000/5 หลัก ② มีด่านตรวจ deterministic: ค่าที่รอดต้องมีจริงในตัวหนังสือที่ OCR อ่านได้ — เลขภาษีต้อง 13 หลักเป๊ะ, เลขเอกสารที่ทั้งก้อนอ่านเป็นวันที่ได้ (เช่น 10/08/2569) จะถูกทิ้งลง "ข้อมูลที่ขาด" → ใบเสร็จจะขึ้น หลักฐานประกอบ (ไม่มีเลขเอกสาร) อย่างซื่อสัตย์แทนที่จะเขียวด้วยเลขปลอม (เลขรันจริงอย่าง 123/2569 ไม่โดนลูกหลง) ③ กู้เลขภาษีอัตโนมัติ: ถ้า AI ไม่หยิบมาแต่ในใบพิมพ์เลข 13 หลักไว้ตัวเดียว ระบบเติมให้เอง (สองตัวขึ้นไป = ไม่เดา ให้คนตรวจ) · วิธีเทสซ้ำ: ส่งรูปใบเสร็จโรงพยาบาลเดิมผ่าน LINE อีกครั้ง (หรือกด อ่านเอกสารอีกครั้ง บนใบเดิมในหน้ารีวิว) — คาดหวัง: เลขผู้เสียภาษี 0994000… โผล่, ช่องเลขที่เอกสารไม่ใช่วันที่ (ถ้าอ่านเลขจริงไม่ได้จะเว้นว่างพร้อมชวนกรอก) · ใบที่สร้างไว้ก่อน fix ค้างค่าเดิมจนกว่าจะอ่านซ้ำ/แก้มือ

13.1 ตั้งใจ / รู้อยู่แล้ว — อย่าแจ้งเป็นบัคใหม่

อาการสถานะ
เมนู คลังสินค้า / จัดซื้อ / เจ้าหนี้ / ธนาคาร / เวิร์กโฟลว์ / AI แนะนำ / CRM hub ไม่อยู่ใน sidebarตั้งใจของ release นี้ — เข้าทาง URL ตรง
สมุดรายวัน + ปิดงวด เข้าไม่ได้เลย แต่ JV เกิดเบื้องหลังตั้งใจ (ACCOUNTING_UI_HIDDEN)
ปิดฟีเจอร์แล้วเมนูหายเงียบ ไม่มีคำอธิบาย (ยกเว้นรายงาน)พฤติกรรมปัจจุบัน — จดเป็น UX improvement ได้
ปุ่มรีเฟรช dashboard ของ role อื่นที่ไม่ใช่ OWNER ได้ค่าแคช ≤15 นาทีตั้งใจ
ศูนย์แจ้งเตือนไม่มีเมนู sidebar — เข้าจากกระดิ่งเท่านั้น · โชว์สูงสุด 50 แถวไม่มีเพจรู้อยู่แล้ว
เบิกจ่าย: จ่ายบางส่วนไม่ได้ (บังคับเต็มจำนวน) · ปุ่ม void การจ่ายไม่มีใน UIMVP scope
LINE: ส่งเสียงแล้วบอทเงียบ · error ทุกชนิดตอบ "⏳ ขออภัย เกิดข้อผิดพลาดชั่วคราว..." เหมือนกันหมด · /system/line-settings save ไม่ได้รู้อยู่แล้ว (voice ยังไม่ทำ / ตั้งใจซ่อน)
เอกสารขายไม่มีปุ่มพิมพ์/PDF · จัดซื้อไม่มีฟอร์มสร้าง PR/PO ใน UI · ผังบัญชีแก้รายบัญชีไม่ได้ยังไม่ทำใน release นี้
ADMIN เข้า "บทบาทและสิทธิ์" ไม่ได้ (ต้อง OWNER หรือ role ที่มี access.role.manage)ตั้งใจ (ตัดสินใจทีม 2026-07-28)
ไม่มีอีเมลเชิญพนักงาน/ส่งรหัสผ่าน — ส่งมือ + LINE เท่านั้นตั้งใจ (non-goal)

#จุดสงสัย (วิธีเจออยู่ใน section ที่อ้าง)ความแรง
1ใบรับรองแทนใบเสร็จ: supersede ฉบับ ISSUED แล้วสถานะ "ชำระแล้ว" ของ expense ไม่ถูก reset (§6.5) — ✔ แก้แล้ว 2026-08-10 (ตอนนี้ revert เป็นยังไม่ชำระ + void รายการจ่าย)สูง — ข้อมูลการเงินค้างผิด
2เบิกจ่าย: ใบ REJECTED เป็นทางตัน (§7.6) — ✔ แก้แล้ว 2026-08-10: เพิ่มปุ่ม แก้ไขและยื่นใหม่ กลับเป็นร่าง แก้ ส่งใหม่ด้วยเลข RB- เดิม ตรงตามคู่มือในแอปสูง — เอกสารหลอกผู้ใช้
3ตั้งค่า PO approval: วงเงิน/ขั้นอนุมัติที่ตั้ง ไม่ถูกบังคับใช้ตอนอนุมัติ PO จริง + ปุ่มเลือกผู้อนุมัติกดไม่ได้ (§9.4)สูง — นโยบายไม่มีผล
4นโยบายส่วนลด: บันทึกได้แต่ไม่มีโมดูลไหนอ่านค่าไปใช้ ทั้งที่หน้าจอบอก "มีผลทันที" (§9.4)กลาง
5Dashboard: "การเคลื่อนไหวล่าสุด" การ์ดคลังโชว์เวลาดิบ ISO (§4.3)กลาง — เห็นง่าย
6แจ้งเตือน: toggle กฎล้มเหลวแบบเงียบ · หน้า "กฎ" 2 URL คนละ guard · กระดิ่งไม่กรอง origin ของ deep link — ✔ แก้แล้วทั้งสามจุด 2026-08-10 (toggle ล้มต้องขึ้น toast แดง …ไม่สำเร็จ กรุณาลองใหม่)กลาง
7Role ชื่อไทยล้วน: key กลายเป็น ROLE ทำให้ routing อนุมัติเบิกจ่ายไม่เจอคน (§8.4)สูง — ใบค้างเงียบ
8CRM catalog: ตัวกรอง "เก็บถาวร" มี แต่ปุ่มเก็บถาวรไม่มีใน UI (§9.4)ต่ำ
9Role exemption อนุมัติใบตัวเอง — ✔ ยืนยันว่าตั้งใจ (owner decision 2026-08-10) และขยายให้ครอบใบทดแทนแล้ว (OWNER_SELF mode) — ไม่ใช่บัคต้องถามทีม
10LINE fallback ภาษาอังกฤษ — ✔ แก้แล้ว 2026-08-10: แหล่งข้อมูล: … / เปิดดู: …ต่ำ — UX
11สาขา: error สำนักงานใหญ่ — ✔ แก้แล้ว: ต้องขึ้น เก็บถาวรสาขานี้ไม่ได้ — บริษัทต้องมีสำนักงานใหญ่ที่ใช้งานอยู่อย่างน้อย 1 สาขา · ส่วน "ลบเบอร์โทร/อีเมลให้ว่างไม่ได้" ยังไม่แก้ (นอกรอบนี้)ต่ำ
12ช่องเวลาเงียบแจ้งเตือน: ไม่มี validation หน้าจอ พิมพ์อะไรก็ส่ง (§4.4)ต่ำ
✔ ส่งผลทดสอบกลับมาได้เลย — ติ๊กหมวดไหนครบแล้วเจออะไร จดเลข section + ข้อ กำกับ เดี๋ยวผมช่วยไล่แก้เป็นรายตัวต่อได้ทันที
