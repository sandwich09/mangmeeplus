# LINE-first Signup — Support Playbook (P10-L)

สถานะ: ปรับตามงาน recovery/resolution 2026-09-07 — ใช้เมื่อ release ที่รวม [spec รอบนี้](../specs/line-signup-recovery-and-resolution-spec-th.md) ผ่านการ deploy/acceptance แล้ว การ merge Git อย่างเดียวไม่ใช่หลักฐานว่า prod มีปุ่มใหม่
ผู้อ่าน: ทีมงานที่รับสายและตอบลูกค้า (ไม่ต้องรู้โค้ด)

ลูกค้ากรอกอีเมลตอนสมัคร แต่ **ไม่ต้องยืนยันอีเมลหรือตั้งรหัสผ่านก่อนใช้งาน** ตัวตนที่พิสูจน์แล้วคือ LINE
อีเมลติดต่อที่กรอกถูกแบบไม่ได้พิสูจน์ว่าถือกล่องเมล และอาจยังใช้ล็อกอินไม่ได้ ให้ดูสถานะบัญชีจริงก่อนแนะนำ

## สมัครใหม่หลังถูกปฏิเสธ (แก้ไข 2026-09-08)

เมื่อเวอร์ชันนี้ขึ้น environment ที่ใช้งานแล้ว ลูกค้าเลือก **สมัครใหม่** ได้จากหน้าสมัครเดิม ไม่ต้องให้เจ้าหน้าที่ปลดคำขอเก่าก่อน คำขอใหม่เข้าคิวตรวจเสมอ แม้เปลี่ยนอีเมล การปฏิเสธเดิมยังอยู่ในประวัติ และไม่ได้ให้สิทธิ์ทดลองใช้ฟรีเพิ่มเอง

แอดมินดูป้าย **สมัครใหม่หลังถูกปฏิเสธ** ในคิวสมัคร เปิดตรวจประวัติคำขอเดิม แล้วใช้ตัวเลือกเดิม: เปิดร้านใหม่ / กลับร้านเดิม / ขอข้อมูลเพิ่ม / รอจัดแพ็กเกจ ตามผลตรวจ ห้ามแก้คำขอเก่าเป็นอนุมัติเพื่อข้ามประวัติ และแยกการระงับบัญชีจริงออกจากการปฏิเสธใบสมัคร

ปุ่ม **ติดต่อเจ้าหน้าที่** บนหน้าสมัครบันทึกเรื่องเข้าหน้า **คำขอคุยกับเจ้าหน้าที่** โดยตรง แม้หน้าต่าง LINE ส่งข้อความแทนลูกค้าไม่ได้ หากรับเรื่องสำเร็จแล้วให้ตามจากคิวนี้ ไม่ต้องให้ลูกค้าสมัครหรือกดซ้ำ ถ้าระบบรับเรื่องไม่ได้ หน้าจอแสดงเบอร์ติดต่อจริงแทนการอ้างว่าส่งแล้ว

ที่ระบบไม่ตอบลูกค้า ณ ตอนนี้ตรงๆ — ระงับ / หมดอายุ / ยังไม่ผูก LINE / โควตาอ่านรูปหมด / งบ AI หมด

## 4 เรื่องที่คาดว่าจะโทรเข้ามา

### 1. "กดปุ่มแล้วไม่เข้า" (กดลิงก์ในไลน์แล้วไม่เข้าเว็บ)

สาเหตุที่พบบ่อย: เปิดในเบราว์เซอร์ในแอป LINE ซึ่งคุกกี้แยกจาก Safari/Chrome หรือ handoff token
หมดอายุ (15 นาที) เพราะกดค้างไว้นาน

1. ให้ลูกค้า**กดปุ่มใหม่อีกครั้ง**จากข้อความล่าสุด — token ถูกสร้างตอนแตะ ไม่ใช่ตอนส่ง จึงได้อันใหม่เสมอ
2. ถ้ายังไม่เข้า ให้กลับไปหน้าสมัครเพื่อดูผลล่าสุด แล้วกดปุ่ม **"เริ่มใช้งาน"** เมื่อร้านพร้อมใช้ หรือใช้ปุ่มเข้าเว็บจากเมนู LINE ที่เปิดใช้อยู่
3. ดู **ประวัติร้าน** ว่ามี "เข้าหน้าเว็บครั้งแรก" หรือยัง — ถ้าเคยมี แปลว่าเส้นทางใช้ได้และเป็นปัญหาเฉพาะครั้ง
4. ถ้ายังไม่เคยเข้าเลยและร้านเปิดแล้ว ใช้ **ส่งข้อความถึงร้าน** ส่งลิงก์เว็บของเราให้กดอีกที
   (กล่องนี้รับเฉพาะลิงก์เว็บของเราและ LIFF เท่านั้น)

### 2. "เปลี่ยนมือถือ / LINE หาย" — เข้าไม่ได้เลย

ตรวจว่าลูกค้ายังเข้า LINE เดิมหรือบัญชีเดิมได้หรือไม่ บางคนตั้งรหัสสำรองแล้ว บางคนมีแค่อีเมลติดต่อ
อย่าสรุปว่าต้องเปิดร้านใหม่ ใช้ขั้นตอนตรวจหลักฐานด้านล่างและเก็บเป็นเคสที่มีผู้รับผิดชอบ
**ห้ามข้ามข้อ 1**

### 3. "ส่งใบเสร็จแล้วไม่ตอบ"

1. เปิด **ประวัติร้าน** → อ่านบรรทัด "ตอนนี้ AI จะไม่ตอบ"
   - *ให้ AI อ่านรูปครบ N ครั้งของเดือนนี้แล้ว* → เสนอเปลี่ยนแพ็กเกจ (ลูกค้ากด "ขอเปลี่ยนแพ็กเกจ" ในไลน์
     แล้วแถวจะโผล่ในแท็บ **คำขอเปลี่ยนแพ็กเกจ**) หรือถ้าเป็นร้านใหม่ที่ยังติดโควตาอุ่นเครื่อง
     ให้ตรวจแล้วกด **ตรวจแล้ว** ในหน้าพาร์ทเนอร์เพื่อปลดเพดาน 7 วันแรก
   - *ใช้งบ AI ของเดือนนี้ครบแล้ว* → ปรับงบในกล่อง **AI Usage & Budget** ถ้าเห็นควร
   - *แพ็กเกจหมดอายุแล้ว* → กด **ต่ออายุ** (ปุ่มนี้เปิดร้านที่ระบบปิดเองกลับมาให้ด้วย)
   - *ร้านอยู่สถานะ DISABLED/SUSPENDED* → เปิดกลับที่ **Lifecycle** ถ้าเป็นเรื่องเข้าใจผิด
   - *ยังไม่มีสมาชิกคนไหนผูก LINE* → ไปข้อ 2
2. ถ้าไม่มีบรรทัดนี้เลย แปลว่าระบบพร้อมตอบ — ขอให้ลูกค้าส่งรูปใหม่ในแชท แล้วดู "ใช้งานล่าสุด"
   ในประวัติร้านว่าขยับไหม

### 4. "สมัครแล้วเงียบ"

1. เปิดคิว `/system/signup-requests` และดูสถานะจริง คำขอที่รับไว้แล้วแต่ตรวจไม่จบต้องตามต่อจากคำขอเดิม ไม่ให้ลูกค้าสมัครซ้ำเพื่อแก้ระบบค้าง
2. สำหรับคำขอจาก LINE ให้เลือกผลที่ตรงกับความต้องการ:
   - **กลับร้านเดิม**: เลือกได้เฉพาะร้านที่ LINE ปัจจุบันมีสิทธิ์เข้า ระบบไม่เพิ่มสิทธิ์หรือรีเซ็ตแพ็กเกจ
   - **เปิดร้านใหม่**: ตรวจข้อมูลและหมวดธุรกิจ หากอีเมลติดต่อซ้ำกับบุคคลอื่น ต้องตรวจการใช้ร่วมกันและบันทึกเหตุผล หากเคยมีร้าน ต้องแยกตัดสินสิทธิ์ทดลองซ้ำพร้อมเหตุผล
   - **ขอข้อมูลเพิ่ม**: รวมคำถามทั้งหมดในครั้งเดียว ข้อความที่กรอกจะเป็นข้อความให้ลูกค้าเห็น ระบบบันทึกและเข้าคิวส่ง LINE ไม่ได้แปลว่าส่งถึงแล้วทันที
3. หากไม่อนุญาตทดลองซ้ำ คำขออยู่ **รอจัดแพ็กเกจ** โดยยังไม่สร้างร้านเปล่าที่ใช้งานไม่ได้ ให้รับผิดชอบและติดตามเรื่องแพ็กเกจต่อ ระบบชำระเงินอัตโนมัติเป็นงานรอบถัดไป
4. คำขอที่เปิดร้านไม่สำเร็จหรือร้านถูกสร้างแล้วแต่ปิดงานไม่ครบ ให้ใช้ปุ่มทำต่อของคำขอเดิม ระบบตรวจร้านที่ผูกกับคำขอนั้นก่อน ห้ามเปิดคำขอใหม่เพื่อเลี่ยงปัญหา
5. ไม่เจอแถว ให้ค้นผู้ใช้และร้านเดิมก่อน หากมีข้อความผิดพลาด ให้เจ้าหน้าที่นำรหัสจากหน้าแอดมินและผลที่เห็นมาบันทึกในเคส support ไม่ต้องให้ลูกค้าจำหรืออ่านรหัสคำขอ

### อีเมลที่ลูกค้ากรอก หมายความว่าอย่างไร

- **อีเมลใหม่ที่รูปแบบถูก**: สมัครผ่าน LINE ต่อได้ ไม่ต้องตั้งรหัสผ่านหรือรอยืนยันเมล แต่ยังต้องผ่านเงื่อนไขอนุมัติอัตโนมัติอื่น
- **อีเมลของบัญชีเดิมที่ LINE นี้พิสูจน์ได้ว่าเป็นของตัวเอง**: ไม่ส่งเข้าคิวเพียงเพราะอีเมลตรงกัน หากต้องการเพิ่มร้าน ยังต้องตรวจสิทธิ์ทดลองซ้ำแยกต่างหาก
- **อีเมลที่บัญชีอื่นใช้อยู่ หรืออีเมลกลางที่ใช้ร่วมกัน**: ให้ทีมงานตรวจ แอดมินอนุมัติร้านใหม่ได้เมื่อบันทึกผลตรวจชัดเจน แต่ไม่ได้ย้ายบัญชีหรือร้านของเจ้าของเมลมาให้ผู้สมัคร
- **กรอกผิด**: ลูกค้าแก้อีเมลในคำขอเดิมได้ในช่วงที่ระบบอนุญาต ระบบตรวจใหม่และยกเลิกผลตรวจเก่าที่ใช้ข้อมูลเดิม ถ้าเริ่มเปิดร้านแล้วให้เจ้าหน้าที่ตามเคสแทน

ข้อยกเว้นสำหรับคำขอเก่าที่ไม่มีเบอร์โทรตั้งแต่ก่อนบังคับกรอก: ปุ่มแก้อีเมลไม่ได้เติมเบอร์โทรให้ หากตรวจแล้วว่ายังไม่สร้างร้านและแก้ผ่านหน้าปัจจุบันไม่ได้ ให้รับผิดชอบเคส บันทึกเหตุผลปฏิเสธคำขอเดิม แล้วช่วยลูกค้าเปิดแบบฟอร์มใหม่เพื่อกรอกข้อมูลครบ กรณีนี้เป็นการแทนคำขอที่ข้อมูลไม่ครบโดยตั้งใจ ไม่ใช่ให้กดสมัครซ้ำขณะคำขอเดิมยังทำงาน

อีเมลติดต่อไม่ได้เป็นหลักฐานถือครองกล่องเมล และการกรอกอีเมลไม่ได้เปิดระบบกู้บัญชีด้วยเมลให้เอง เรื่อง mail provider และการยืนยันเมลต้องตรวจตามงานรอบถัดไป

## กู้บัญชีเมื่อ LINE หาย — ตรวจหลักฐานก่อนเปลี่ยนสิทธิ์

> ชื่อร้าน อีเมล เบอร์ที่เพิ่งแจ้ง และรายการย้อนหลัง 2 รายการ **ไม่เพียงพอให้ย้าย OWNER**
> การขอความช่วยเหลือไม่ได้อนุญาตให้ unlink บัญชีคนอื่นหรือเปิด trial ใหม่

1. **รับผิดชอบเคสและถามข้อมูลทั้งหมดครั้งเดียว**: ร้านที่ต้องการกลับไปใช้ เข้า LINE/บัญชีเดิมได้หรือไม่ มีการระงับหรือหมดแพ็กเกจหรือไม่ ข้อมูลที่แจ้งเป็นเบาะแส ห้ามส่งคำขอข้อมูลทีละชิ้นโดยไม่จำเป็น
2. **ใช้การเข้าบัญชีเดิมที่พิสูจน์ได้ก่อน**: ให้เข้าผ่าน LINE/บัญชีเดิม แล้วเลือกร้านที่มีสิทธิ์จริง ระบบตรวจสมาชิก/บทบาทอีกครั้ง ไม่เปลี่ยนพนักงานเป็นเจ้าของ และไม่รีเซ็ตแพ็กเกจ
3. **ถ้าเข้าเดิมไม่ได้ ให้ส่งต่อผู้มีอำนาจตรวจ recovery**: บันทึกสิ่งที่พิสูจน์ได้และสิ่งที่ยังขาดในเคส ห้ามถือว่าอีเมลตรงหรือแอดมินเขียนโน้ตเท่ากับผ่าน proof ห้ามสัญญาว่าส่ง OTP แล้วหาก mail provider ยังไม่พร้อม เคสยังรอให้ช่วย ไม่ใช่แก้เสร็จ
4. **เครื่องมือ unlink/QR ใช้หลังมีหลักฐานและอำนาจเท่านั้น**: ปุ่มในหน้าพาร์ทเนอร์เป็นเครื่องมือเปลี่ยนการเข้าถึง ไม่ใช่เครื่องมือพิสูจน์ตัวตน ถ้ายังไม่มีข้อสรุปที่บันทึกชัด อย่ากดเพื่อทดลองให้ลูกค้าเข้าได้ก่อน
5. **ตรวจผลกับลูกค้าและบันทึก**: ให้ลูกค้าเข้าเห็นร้านถูกแห่งและสิทธิ์เดิมก่อนบันทึกผลแก้สำเร็จ audit `auth.identity.unlink` และ `access.employee.line_link.success` บอกการกระทำ ไม่ได้พิสูจน์ว่าตรวจเจ้าของอย่างถูกต้อง อย่าประดิษฐ์ชื่อ audit ที่ไม่มีในระบบแทนหลักฐาน

หลังกู้เสร็จแนะนำข้อมูลติดต่อและช่องทางสำรองในหน้าตั้งค่าตามสิ่งที่เปิดใช้จริง การกรอกอีเมลอย่างเดียวไม่ใช่การเปิดทางกู้ด้วยเมลสำเร็จ

### ลูกค้าเคยปลด LINE แล้วมาสมัครใหม่ (แก้แล้ว 2026-09-05)

ลูกค้าที่เคยผูก LINE ไว้แล้ว **ปลดออก** (หรือร้านเดิมถูกปิด) แล้วกลับมาสมัครใหม่จากการ์ดในไลน์ —
ระบบเปิดร้านใหม่ให้ได้แล้ว และจะ**ย้าย LINE เดิมมาที่บัญชีใหม่ให้เอง** ร้านเก่าไม่ถูกเปิดคืนหรือแก้ไขใดๆ
ทั้งสิ้น และแชทจะไปที่ร้านใหม่ทันที ระบบเขียน audit `auth.identity.repointed` ไว้ให้ ซึ่งบอกว่า LINE นี้
ย้ายมาจากบัญชีไหน (ก่อนหน้านี้เคสนี้ขึ้น 409 "ข้อมูลซ้ำ" และกดอนุมัติซ้ำกี่ครั้งก็พังเหมือนเดิม)

บนแถวในคิวจะมีชิปเตือน **"LINE นี้เคยมีร้าน: <ชื่อร้าน> (ปิดอยู่/หมดอายุ/ใช้งานอยู่)"** — เป็นข้อมูลให้
ตัดสินใจเท่านั้น ไม่ได้ห้ามอนุมัติ ถ้าเป็นการขอทดลองใช้ฟรี**รอบที่สอง** ระบบจะไม่อนุมัติอัตโนมัติให้
ต้องมีคนเลือกผลว่าเปิดร้านใหม่ และยืนยันอนุญาตสิทธิ์ทดลองเพิ่มพร้อมเหตุผลแยกต่างหาก หากยังไม่ให้ trial ให้คงเป็นเคสรอจัดแพ็กเกจ ไม่เปิดร้านว่างให้ลูกค้าเข้าใจว่าใช้งานได้แล้ว

> นับเฉพาะร้านที่เขาเป็น **เจ้าของ (OWNER)** เท่านั้น **พนักงาน**ที่เคยถูกผูก LINE ด้วย QR ของร้านนายจ้าง
> มาเปิดร้านของตัวเองครั้งแรก จะ**ไม่**ขึ้นชิปนี้ และยังอนุมัติอัตโนมัติได้ตามปกติ

**รหัสใหม่ 2 ตัวที่ลูกค้าจะเห็นบนหน้าสมัคร** (ขึ้นข้อความว่า "บัญชี LINE นี้เปิดร้านใหม่ไม่ได้ค่ะ กรุณาติดต่อ
ทีมงาน โทร 098-256-5628 หรืออีเมล contact@mangmeeplus.com") — กดซ้ำไม่ช่วย ต้องให้เราแก้ให้:

| รหัส | แปลว่า | ทีมซัพพอร์ตทำอะไร |
| --- | --- | --- |
| `line_signup_account_blocked` | LINE นี้ผูกกับบัญชีที่ถูก**ระงับ/ปิด**อยู่ — **รวมถึงกรณีที่ปลด LINE ออกไปแล้ว** ระบบก็ยังไม่ยอมให้เปิดบัญชีใหม่ | ยืนยันตัวตนตาม 5 ขั้นข้างบนก่อน แล้วให้แอดมินตัดสินใจว่าจะเปิดบัญชีเดิมคืน หรือปลด LINE ออกจากบัญชีเดิมก่อน การปลด LINE **ไม่ใช่**ทางเลี่ยงการระงับ |
| `line_signup_identity_disabled` | แอดมิน**ปิดใช้งาน LINE** นี้ไว้ (kill-switch) | ดูในตั๋วว่าปิดเพราะอะไร ถ้าปิดผิดหรือหมดเหตุแล้ว ให้แอดมินเปิดคืนก่อน แล้วให้ลูกค้าสมัครใหม่ |

**รหัสใหม่ 2 ตัวที่แอดมินจะเห็นบนแท็บ "มีปัญหา"** (ชิปสีแดงบนแถว และข้อความเดียวกันตอนกดอนุมัติ):

| รหัส | แปลว่า | ทีมซัพพอร์ตทำอะไร |
| --- | --- | --- |
| `line_identity_already_linked` | ตอนกดอนุมัติ LINE นี้ไปผูกกับบัญชีอื่นแล้ว | ตรวจหลักฐานและเจตนาปัจจุบันก่อน ใช้ทางกลับร้านเดิมหรือส่งต่อ recovery ตามสิทธิ์ ห้ามปลดของเดิมเพียงเพื่อให้ปุ่มอนุมัติผ่าน |
| `line_identity_disabled` | LINE นี้ถูกปิดใช้งานอยู่ | ให้แอดมินเปิดใช้งานคืนก่อน แล้วกด **ลองเปิดร้านอีกครั้ง** |

## ลูกค้ากด "ติดต่อเจ้าหน้าที่" — ทำอย่างไร (2026-09-05)

> เดิมข้อความนี้ push หาเฉพาะแอดมินที่ผูก LINE ซึ่ง**ไม่มีใครผูกเลย** ลูกค้าจึงได้ยินว่า "รับเรื่องแล้วค่ะ"
> แล้วเงียบหายไป ตอนนี้ทุกคำขอขึ้น**หน้าเว็บ**ทันที ไม่ต้องผูก LINE กับบัญชีทีมงาน
> ([spec](../specs/line-support-request-spec-th.md))

**หน้าที่ใช้: `/system/support-requests`** — เมนู "คำขอคุยกับเจ้าหน้าที่" บนแถบบน
มี**ตัวเลขสีแดง**บอกจำนวนที่ยังรอตอบ ถ้าไม่มีตัวเลข = ไม่มีใครรอ (หรือคุณไม่มีสิทธิ์ดู)

ขั้นตอน:

1. เปิดหน้า → แท็บ **รอตอบ** เรียงคนที่รอนานสุดขึ้นก่อน แต่ละแถวบอก **ผู้ขอ · รอมานาน · ข้อความล่าสุด ·
   แจ้งทีมงาน · สถานะ**
2. รับผิดชอบเคสก่อนตรวจข้อมูล หากต้องส่งต่อให้ปล่อย/ส่งต่องานอย่างชัดเจน ใช้ **เปิดหน้าร้าน** หรือ **เปิดคิวสมัคร** ดูข้อมูลประกอบตามสิทธิ์
3. ตอบจากเคสใน inbox ถึง LINE ของผู้ขอโดยตรงได้แม้ยังไม่มีร้าน รวมข้อมูลที่ต้องขอทั้งหมดในข้อความเดียว
   **ไม่ต้องใช้ LINE ส่วนตัวของคุณ** · ถ้าส่งไม่สำเร็จให้ดูสถานะและลองส่งเดิมอีกครั้ง อย่าบอกว่าลูกค้าได้รับแล้ว
4. **ตอบแล้ว** หมายถึงได้ตอบ ยังไม่ใช่หลักฐานว่าปัญหาจบ เมื่อดำเนินการสำเร็จจริงจึงบันทึกผลแก้พร้อมเหตุผล ถ้าคุยทางโทรศัพท์ให้บันทึกผลของการคุยตามจริง
5. อยากให้บอทกลับมาตอบลูกค้าคนนี้ทันที (ไม่ต้องรอครบ 24 ชม.) กด **ให้ AI ทำงานต่อ** การคืน AI ไม่เท่ากับแก้เคสสำเร็จ
   — ลูกค้ากดปุ่ม/พิมพ์ **"คุยกับน้องมั่งมี"** เองก็ได้เหมือนกัน (คำเดิม "คุยกับ AI ต่อ" ยังพิมพ์ได้)

อ่านคอลัมน์ **แจ้งทีมงาน** อย่างไร:

| เห็นอะไร | แปลว่า |
| --- | --- |
| `กำลังแจ้ง…` | เพิ่งกดมาเมื่อสักครู่ ระบบยังส่งไม่เสร็จ — รอสักครู่แล้วรีเฟรช (ไม่ใช่ความผิดพลาด) |
| `อีเมลทีมงาน` | ส่งอีเมลเข้ากล่อง contact@mangmeeplus.com แล้ว — **ปกติ** ทีมงานไม่ต้องผูก LINE |
| `อีเมลทีมงาน · LINE 2 คน` | ส่งอีเมลแล้ว และแอดมินที่ผูก LINE ไว้ 2 คนได้รับด้วย |
| **`แจ้งไม่สำเร็จ — เห็นที่หน้านี้เท่านั้น`** (สีแดง) | ไม่มีช่องทางไหนส่งสำเร็จเลย คำขอยัง**อยู่ครบ**ในหน้านี้ แต่ไม่มีใครถูกเตือน — เช็กว่า SES ใช้งานได้ไหม แล้วแจ้งทีมเทค |

ข้อควรรู้:

- **ไม่มี LINE ID ของลูกค้าในหน้านี้** (PDPA) มีแค่ **รหัสผู้ขอ** 6 ตัวอักษรไว้เทียบว่าเป็นคนเดียวกัน
- ลูกค้ากดซ้ำระหว่างที่คำขอยังเปิดอยู่จะได้ยินว่า "ยังอยู่ในคิวค่ะ" และ**ไม่**เด้งแจ้งทีมงานซ้ำ
- ผู้ที่ยังไม่ได้เปิดร้านมีข้อมูลคำขอสมัครประกอบ เจ้าหน้าที่ตอบผ่านเคส support ได้โดยตรง ไม่ต้องสร้างบริษัทก่อนเพื่อให้ส่งข้อความได้
- การขอข้อมูลเพิ่มจากคิวสมัครผูกกับเคส support ที่มีผู้รับผิดชอบแล้ว คำตอบข้อความของผู้สมัครที่ยังไม่มีร้านต้องตามต่อในเคสนี้ ไม่ต้องให้สมัครร้านก่อนจึงจะตอบเจ้าหน้าที่ได้
- ป้าย **ส่งรูปมา** เป็นเพียงข้อมูลว่าลูกค้าส่งรูป ไม่ใช่คลังรูปที่เจ้าหน้าที่เปิดตรวจได้ อย่าขอเอกสารยืนยันตัวตนผ่านช่องนี้แล้วอ้างว่าตรวจรูปได้ หากต้องกู้บัญชีด้วยหลักฐานเพิ่มเติมให้ส่งต่อกระบวนการที่มีอำนาจและช่องรับหลักฐานที่รองรับจริง
- คำขอที่ยังรอช่วยไม่ปิดเพราะลูกค้าเงียบครบ24ชั่วโมง การหมดเวลาหยุด AI เป็นคนละเรื่องกับงาน support; ตรวจงานเก่าผ่านการเลื่อนหน้าคิวและผู้รับผิดชอบ
- ลูกค้า 1 คนเปิดคำขอใหม่ได้ **3 ครั้ง/วัน** ครั้งที่ 4 ระบบตอบ "รับเรื่องไว้แล้วค่ะ" และไม่เด้งหาทีมงาน
  — ถ้าเจอเคสแบบนี้แปลว่ามีอะไรค้างอยู่จริง ให้ดูคำขอ 3 อันแรกของเขาในแท็บ **รอตอบ**
- คำขอที่ปิดแล้วเกิน **90 วัน** ระบบลบทิ้งทั้งแถว (รวมข้อความล่าสุด) ตามกติกาการเก็บข้อมูล ส่วนตอบแล้วแต่ยังไม่แก้เสร็จต้องไม่หายจากคิวเพราะอายุข้อมูล อย่าคัดลอกข้อมูลลูกค้าไปเก็บนอกระบบเพื่อเลี่ยงกติกานี้

## กติกาของกล่อง "ส่งข้อความถึงร้าน" (SEC-05)

- ยาวได้ไม่เกิน **500 ตัวอักษร**
- ใส่ลิงก์ได้เฉพาะ**เว็บของเราและ LIFF** เท่านั้น — ลิงก์อื่นระบบปฏิเสธ (OA ของเราเป็น Verified Account
  ลิงก์ที่เราส่งจึงดูน่าเชื่อถือกว่าที่ควร)
- ส่งถึง**เจ้าของร้าน**ที่ผูก LINE ไว้เท่านั้น ระบบแนบชื่อผู้ส่งให้เอง
- **บันทึกข้อความทุกครั้ง** ลง audit `system.partner.line_message_sent`
- ถ้าขึ้นว่า "ยังไม่ได้ส่ง เพราะเจ้าของร้านยังไม่ได้ผูก LINE" แปลว่า**ยังไม่มีใครได้อ่าน** ต้องโทรแทน

## ข้อจำกัดที่รู้อยู่แล้ว (ยังไม่ต้องแก้ แต่ต้องรู้)

- **ชิป "อาจซ้ำกับร้าน X" สแกนแบบไม่มี index** — ค้นจาก `Company.phone` และ `User.phoneNumber`
  ซึ่งยังไม่มี index ที่คอลัมน์เบอร์ ตอนนี้คิวโหลดครั้งละไม่เกิน 200 แถวจึงเร็วพอ ถ้าคิวโตขึ้นมาก
  ให้เพิ่ม index ที่สองคอลัมน์นี้
- **แจ้งเตือน "ข้อความ พร้อมใช้แล้ว ค้างส่งไม่ออก" จะเตือนซ้ำทุกวัน** ตราบใดที่ยังมีแถวค้างอยู่แม้แต่แถวเดียว
  (ตั้งใจให้เป็นแบบนี้ เพราะลูกค้ายังไม่ได้รับข้อความจริงๆ) วิธีเคลียร์: เปิดหน้าพาร์ทเนอร์ของร้านนั้น
  ใช้กล่อง **ส่งข้อความถึงร้าน** บอกลูกค้าด้วยตัวเองว่าร้านเปิดแล้ว แล้วแจ้งทีมเทคให้ปิดแถวค้างในคิวส่งข้อความ
  ถ้าเตือนซ้ำเกิน 1 วันแปลว่าน่าจะชนโควตาข้อความรายเดือนของ OA — ต้องอัปแผน OA ไม่ใช่แก้ทีละร้าน
- **ลิงก์ที่เป็นชื่อโดเมนภาษาไทย/ต่างประเทศแบบไม่มี `https://` นำหน้า ระบบยังไม่ปฏิเสธ** (เช่น `มังมี.ไทย/pay`)
  — เป็นการแลกที่ตั้งใจ เพราะกฎที่จับได้จะไปปฏิเสธประโยคภาษาไทยธรรมดาที่มีจุดคั่นด้วย
  ถ้าใส่ `https://` นำหน้า (ซึ่งเป็นวิธีเดียวที่กดแล้วเปิดได้จริง) ระบบปฏิเสธถูกต้อง
- **รายการเฉพาะบางชุดยังมีขอบเขต** — คิวสมัครหลักและคิว support มีการเลื่อนหน้า ส่วนแท็บอนุมัติอัตโนมัติ/คำขอเปลี่ยนแพ็กเกจยังต้องพิจารณาขอบเขตของ query ของตัวเอง อย่าใช้จำนวนที่เห็นในหน้าที่มีเพดานเป็นยอดทั้งหมด และอย่าประเมินปริมาณจริงจากข้อจำกัดของโค้ด

## หมายเหตุการตั้งค่าที่ทีมเทคต้องรู้

- **LIFF endpoint URL ต้องเป็น `https://<api>/v1/auth/line/link-page`** (ไม่ใช่ `/signup-page`)
  เพราะ `liff.login` redirect ต้องอยู่ใน scope ของ endpoint ที่จดไว้ หน้าสมัครอยู่ใต้ path นั้นเป็น
  `…/v1/auth/line/link-page/signup` (มี alias `…/v1/auth/line/signup-page` ไว้ตามชื่อในสัญญา §4)
- ปุ่ม rich menu **"เปิดร้านใหม่ ทดลองฟรี"** ชี้ไปที่ `https://liff.line.me/<LINE_LIFF_ID>/signup`
  ตั้งใน console ตาม [line-rich-menu-v2-console-setup.md](line-rich-menu-v2-console-setup.md)
- คนที่ยังไม่ผูกบัญชีจะได้ **การ์ด 3 ประตู** ตอบอัตโนมัติอยู่แล้วเมื่อทักหรือเพิ่มเพื่อน — ปุ่มแรกของการ์ด
  คือทางสมัครหลัก rich menu เป็นทางเสริม
- ถ้าลูกค้าเปิดลิงก์สมัคร**จากเบราว์เซอร์ปกติ** (ไม่ใช่ในแอป LINE) หน้าจะขึ้น "เปิดหน้าสมัครไม่สำเร็จ"
  พร้อมปุ่ม ลองอีกครั้ง และบอกให้เปิดจากแอป LINE — ไม่ใช่ข้อผิดพลาดของระบบ
- ระหว่างที่ลูกค้ากด **ติดต่อเจ้าหน้าที่** (AI หยุด 24 ชม.) คำสั่งชัดเจนอย่าง **ขอเปลี่ยนแพ็กเกจ**
  ยังทำงานตามปกติ — มีแต่ข้อความคุยทั่วไปที่ระบบจะตอบว่า "ทีมงานรับเรื่องแล้วค่ะ"
