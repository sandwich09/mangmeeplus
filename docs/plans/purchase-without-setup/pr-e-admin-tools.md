### 1.2 ทำไม `RECIPIENT_ADMIN_CHANGE` ต้องเป็น op อิสระ (A03) และวิธีกัน race

- ถ้าใส่ใน `activeEmailOperationId`: `advance` `:119-120` ค้นด้วย `type: 'UPDATE_BILLING_EMAIL'` → `findFirstOrThrow` โยน → reconciler ของบัญชีนั้นล้มทุกรอบ, ไม่มีทาง COMPLETED; แม้ branch ตาม type ก็ยังต้องข้าม `:140-142` (assert owner + account-email proof ของ initiator ซึ่งแอดมินไม่มี) → ทางนี้ต้องเขียน `advance` ใหม่ทั้งตัวและ re-check authority แอดมินใน reconciler — ไม่ทำ
- ถ้าใส่ใน `activeCollectionOperationId`: reconciler `:218-229` ไม่รู้จัก type → `collection.advance` `:226` (handler ผิด) แล้ว `return` `:228` → ต่ออายุ/apply ไม่เดิน, quote/checkout ปฏิเสธด้วย `BILLING_COLLECTION_PENDING` (`billing.service.ts:340`) — ไม่ทำ
- ทำแบบ REFUND: op ไม่มี slot; **mutual exclusion ทำสองทาง** (1) ฝั่ง op: preview/current/dispatch ปฏิเสธเมื่อ `account.activeAttemptId || activeCollectionOperationId || activeEmailOperationId || pendingRefund(...)` (เหมือน `billing-refunds.service.ts:86,127`) และเมื่อมี `RECIPIENT_ADMIN_CHANGE` อื่นค้าง; (2) ฝั่งลูกค้า: helper ใหม่ `pendingRecipientAdminChange(tx, account, excludeId?)` (ไฟล์ service เดียวกัน, export) คืน op ที่ `type='RECIPIENT_ADMIN_CHANGE'`, `companyId`, `stripeAccountId/livemode` ตรง, `state ∈ {PREVIEW, AWAITING_APPROVAL, QUEUED, RUNNING, UNKNOWN, BLOCKED}` — **PR E ต้องเรียกที่** quote `billing.service.ts:339` (โยน `BILLING_EMAIL_UPDATE_PENDING` เดิม), checkout ก่อน `:633`, resume ก่อน `:683`, `billing-repeat.ts` ก่อน `:279`, และใน preview/command ของ flow OTP ผู้รับใหม่ของ PR C (ชื่อไฟล์ตาม PR C; เงื่อนไขเดียวกับ `billing-email-recipient.ts:69`)

### 1.3 `RECIPIENT_ADMIN_CHANGE` — สเปกละเอียด

- `cancel` (ก่อน dispatch) → `CANCELLED` + resolve issue `CONTROL_OPERATION_REVIEW`
- `run` (`MANAGE` หรือ `approval.approve`, `requireProof`) → `execute` ทันที
- `drain()` → `findMany({type: RECIPIENT_TYPE, state in [QUEUED, RUNNING, UNKNOWN, BLOCKED, FAILED], scheduledFor <= now, stripeAccountId/livemode})` take 25 → `execute` ทีละแถว; รวมกับ drain ของ `CUSTOMER_PROFILE_SYNC` (§2.6) ในเมธอดเดียว คืน `{processed, failed}`
