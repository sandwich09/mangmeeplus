# แผนบัตรจ่ายครั้งเดียวและ PromptPay QR สำหรับแพ็กเกจ Mangmee

Status: LOCAL IMPLEMENTED + STRIPE SANDBOX PRIMITIVES VERIFIED 2026-09-20; app-level UAT, CI, release and gate activation pending. Spec: [billing-promptpay-qr-spec-th.md](../specs/billing-promptpay-qr-spec-th.md).

1. เพิ่ม `purchaseMode` immutable ใน quote/consent/attempt และ mode เฉพาะในสถานะสิทธิ์ปัจจุบัน; แสดงยอดและเงื่อนไขแยกบัตร auto-renew, บัตรครั้งเดียว, QR ครั้งเดียว, QR ต่ออายุ. มี gate สำหรับบัตรครั้งเดียวแยกจาก `new_sales`; ปิด QR gate จน Stripe TEST readiness ผ่าน. Reuse price/term/capacity/email checks และ original attempt reservation. ห้ามเปลี่ยนจากสมาชิกบัตรที่ยังเรียกเก็บได้ไปซื้อครั้งเดียวแบบเงียบ ๆ.
2. เพิ่ม Checkout `mode=payment` ด้วย inline one-time price ที่ผูก Product/ยอด/ภาษีของ offer snapshot สำหรับบัตร/PromptPay จ่ายครั้งเดียวและ PromptPay งวดแรก. แยก paid evidence ตาม mode; reuse ตัวตรวจ card payment ของ repeat purchase เมื่อ invoice/PaymentIntent/charge/line/amount/tax/customer/account ตรงกัน แต่ไม่ reuse ส่วน pause/schedule subscription. Apply initial และซื้อซ้ำภายใต้ lock/ledger ครั้งเดียว. สร้างบิล/Checkout ใหม่ได้เมื่อ attempt เดิม terminal ที่ตรวจแล้วเท่านั้น.
3. สำหรับ QR ต่ออายุ สร้าง `send_invoice` subscription แบบ idempotent หลังงวดแรกจ่ายและสิทธิ์ apply แล้ว โดยเริ่ม invoice ถัดไปที่ paid-through. เก็บ mapping/คำสั่งกู้คืน; ไม่ใช้ `active` ของ Stripe เป็น paid proof.
4. ขยาย reconciler/webhook/import, Checkout resume/expire, status/Admin/document/refund และ read model ให้รองรับ invoice `subscriptionId=null` ของบัตรครั้งเดียว. ตรวจ term sweep/ข้อความแจ้งเตือน/LINE link; เปิด action ซื้อซ้ำหรือเปลี่ยนแพ็กเกจเฉพาะ mode ที่ implementation รองรับ. สำหรับ QR ต่ออายุเพิ่ม hosted invoice URL, due/grace/cancel, late payment และ replay; การยกเลิกสมาชิกกับการจัดการหนี้แยกกัน.
5. ทดสอบ domain/adapter, API+PostgreSQL, browser 390/1280, web/LINE, fault injection และ Stripe TEST native: บัตรครั้งเดียวหนึ่งงวดโดยไม่มี next charge, บัตรเดิมที่ Stripe prefill, ซื้อซ้ำก่อน/หลังหมดอายุ, auto subscription เดิม, QR first paid, invoice renewal, unpaid, cancel/payment race, async completion, replay, wrong mapping, overpayment/refund. ตรวจ payment mode ที่จ่ายแล้วแต่ apply HELD และการกู้ด้วย invoice เดิม. Production ปัจจุบันให้บริการด้วย Kamal และ legacy ECS release workflows ถูกปิดตาม [cloud inventory](../runbooks/cloud-environment-operations.md); อ่าน mandatory V2 acceptance protocol และใช้ `infra/kamal/README.md` สำหรับ UAT deploy → signed receipt → `promote-prod` แบบ normal ที่ใช้ image digest เดิม → Production browser identity/OPEN/logout acceptance. บันทึก Kamal operation IDs และระบุ V2 workflow IDs ว่าไม่ได้ dispatch; ห้ามเรียก Production complete จาก local test หรือ UAT smoke อย่างเดียว.

ผลล่าสุด: Stripe Sandbox API `2026-08-26.dahlia` ยืนยัน post-payment invoice บัตรเดิม, PromptPay Checkout ที่จ่ายแล้ว, subscription `send_invoice` ที่ออก hosted invoice, PromptPay บิลรายงวดที่จ่ายแล้ว และการยกเลิกสมาชิกหลังค้างชำระโดยบิลเดิมยังเปิดอยู่ ([evidence](../evidence/billing-payment-modes-stripe-sandbox-2026-09-20.md)). PostgreSQL grace/replay 14 tests, focused domain/service 19 tests และ browser preview 1280/390 ผ่าน. รายการค้างก่อนเปิด gate: integration ของแอปจริงบน UAT สำหรับ OWNER, quote/consent/Checkout/webhook/grant/history/เอกสาร/LINE, CI, runbook release, แล้วจึง publish gate ผ่าน Admin. ไม่ใช้ native test เป็นข้ออ้างสร้าง charge บน LIVE.
