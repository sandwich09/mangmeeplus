## ลำดับงาน

owner 2026-11-06: ไม่เพิ่มเครื่องใหม่ ทุกข้อรันบนระบบจริง

1. **ป้ายเดโม่บนร้าน:** รับค่า `'DEMO'` ใน `reportClassification` ไม่ให้ร้าน DEMO ถูกนับในรายงานผู้บริหาร
   และให้ session บอกเว็บว่าร้านนี้เป็นเดโม่ เพื่อแสดงแถบระบบจำลอง
2. **ร้านตัวอย่าง:** seed ฟังก์ชันเดียวที่รับ companyId แล้วสร้างร้านอาหารตามที่ระบุใน spec ข้อ 4
   ใช้รูปแบบ `apps/api/prisma/seed-plain-shop.ts` และ `seed-expenses.ts` และนับวันจากวันที่สร้าง
3. **ลิงก์:**
   - `POST /v1/sales/demo-links` ใช้สิทธิ์เซลล์หรือแอดมิน เก็บ hash ของโทเค็น บันทึก audit แล้วคืน URL และวันหมดอายุ
   - `/d/:token` ตรวจ hash และวันหมดอายุ สร้างร้านสำเนาครั้งแรก (ใช้ id ลิงก์กันสร้างซ้ำ)
     แล้วออก handoff ไปเป็น session ที่ใช้ได้ไม่เกินวันหมดอายุ ถ้าลิงก์ใช้ไม่ได้ให้ขึ้นหน้าหมดอายุ
   - งานกลางคืน: ปิดใช้งานร้านสำเนาที่หมดอายุแล้ว
4. **ปุ่มในคอนโซลขาย:** "สร้างลิงก์เดโม่" พร้อมคัดลอก และแสดงวันหมดอายุ
5. **แชทจำลองและแถบระบบจำลอง:** component เดียวใน workspace layout แสดงเฉพาะร้าน DEMO
   บทแชทเป็นข้อมูลในโค้ด ตัวเลขอ่านจาก API ของร้านนั้น ส่วนการกระทำที่ต้องใช้ของจริงให้ขึ้นข้อความประโยคเดียว
6. **กำแพงร้าน DEMO:** ปฏิเสธที่ API สำหรับ AI, ซื้อแพ็กเกจ, อีเมล, LINE, ผูก LINE, เชิญพนักงาน และเปลี่ยนรหัสผ่าน
