# Web Access and Error Handling

Status: Deployed and production-smoked 2026-07-13
Owner: Codex harness; Claude Opus 4.8 API implementation/review
Related: [[specs/web-core-workspace-spec|Web Core Workspace Spec]], [[plans/web-session-recovery-redirect-loop-fix-plan|Web Session Recovery Plan]]

## Product outcome

Users must never mistake a disabled company, removed membership, or service outage for a missing page. Every blocking state uses the existing Mangmee green/gold theme and gives a safe next action without exposing cross-tenant details.

## Rules

- Password login selects only an active membership in an active company. Valid credentials with no usable company access receive stable `company_access_unavailable` and no session token.
- Password-reset confirmation follows the same active-company gate and never mints an unusable session.
- Unscoped session resolution ignores memberships in inactive companies; an explicit inactive company remains forbidden.
- Company bootstrap `403` renders a generic company-access state covering inactive company, removed membership, and unusable scope. It does not reveal which condition applies and is not a `404`.
- `401` returns through login recovery. Auth/network/5xx unavailability enters the retryable runtime error boundary. A true unknown route remains `404`.
- A browser navigation that reaches an unknown `/v1/*` or `/api/*` route renders the branded Next.js 404; non-HTML API clients keep the JSON 404 contract.
- Login distinguishes expired temporary password from unavailable company access by stable error code.
- App-rendered errors hide raw exception text. Pre-Next failures generated by an ALB, edge proxy, or a fully unavailable web task are infrastructure response scope and cannot be themed by a Next.js boundary.

## Smallest implementation

1. Tighten password-login and unscoped permission-resolver queries to `company.status=ACTIVE`; reject before token issuance when none exists.
2. Preserve the stable API code through the login BFF and shared `ApiError`.
3. Replace company-layout `notFound()` for forbidden access with the branded access state.
4. Add branded root and company 404 pages plus a retryable App Router error boundary using existing logo, tokens, buttons, fonts, and layout patterns.
   The existing 404 action targets `/login`, whose real-session gate sends signed-in users to their home path and leaves signed-out users on login.
5. Lock query/error-code behavior with focused tests and verify API/web suites, typecheck, build, and production smoke.

## Acceptance

- Disabled company or revoked membership never lands on stock Next 404 and never receives a new login session.
- If an older inactive membership precedes an active one, the active-company query remains eligible.
- Unknown URL shows branded 404; company access denial shows branded access guidance; auth 5xx/network render branded retry.
- Temporary-password-expired and company-access-unavailable login messages remain distinct.
- Thai/English error surfaces are responsive and use the same Mangmee theme as login/workspace.
