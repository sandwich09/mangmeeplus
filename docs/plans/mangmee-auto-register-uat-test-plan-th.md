# แผนทดสอบ UAT — Auto-register + Plan Term (เหมือนจริงแบบ production)

สถานะ: เขียน 2026-08-30 ตามคำสั่ง Owner ("แผนสำหรับทดสอบ uat ด้วย เหมือนจริงแบบ prod"); ใช้หลัง SES setup เสร็จ (ดู [runbook SES](../runbooks/ses-email-setup.md)) และ deploy UAT แล้ว

หลักการ "เหมือนจริง": ใช้อีเมลจริงที่เปิดกล่องได้จริง (Gmail ส่วนตัว), มือถือจริงทั้ง iOS/Android, LINE จริงของผู้ทดสอบ, เดินจากเว็บ official → /signup เหมือนลูกค้าเดิน, และทุกเคสจบด้วยการตรวจ "ของจริง" (เมลใน inbox, บริษัทใน DB, สิทธิ์ที่ใช้ได้จริง) ไม่ใช่แค่หน้าจอบอกสำเร็จ

เตรียมก่อนเริ่ม: `EXTERNAL_SIGNUP_ENABLED=true` บน UAT เท่านั้น; อีเมลทดสอบ 4 บัญชี (A=เจ้าของใหม่, B=พนักงานเดิมที่มีบัญชีอยู่แล้ว, C=สมัครแล้วเงียบ, D=อีเมลพิมพ์ผิด/โดเมนมั่ว); LINE จริง 2 เครื่อง

## รอบ 1 — เส้นหลัก (ผู้สมัครใหม่ 1 คน จบใน 1 นั่ง)

1. เปิด official.mangmeeplus.com → กดลิงก์สมัคร → ฟอร์ม /signup บนมือถือ 390px: กรอกครบ เลือกได้เฉพาะ PRO ทดลองฟรี (อีก 3 tier ต้องกดไม่ได้ + เห็นราคา)
2. Submit → หน้า "ได้รับคำขอแล้ว" (ห้ามมีคำว่าบริษัทถูกสร้าง) → เช็คสถานะ = รอตรวจสอบ
3. แอดมินเปิดคิว: เห็นรายการ + hint MX ผ่าน + ไม่มีธงซ้ำ → กดอนุมัติ
4. เมลถึง inbox จริง "ยินดีต้อนรับสู่มั่งมีพลัส…" ภายใน ~1 นาที: ตรวจ (ก) DKIM=pass ใน header (ข) ไม่มีรหัสผ่านในเมล (ค) ปุ่มตั้งรหัส + ลิงก์ fallback + ไม่มีเครื่องหมาย +
5. กดปุ่ม → หน้า claim: ชิปยืนยันอีเมล, username แก้ได้, ตั้งรหัส (ปุ่มตาทำงานทั้ง 2 ช่อง), กด "เริ่มใช้งาน"
6. หน้า "พร้อมใช้งาน": เห็นวันหมด trial (อีก 30 วันตรงชั่วโมง) → กด "เชื่อมกับ LINE" → จอ LINE ยืนยัน + ติ๊กเพิ่มเพื่อนน้องมั่งมีในจอเดียว → กลับเข้าระบบ
7. ตรวจของจริง: login ออก/เข้าใหม่ด้วย **อีเมล** ได้, ด้วย username ได้, ส่งรูปใบเสร็จผ่าน LINE แล้ว AI ตอบ, หน้า Partner console เห็น term = PRO เหลือ 30 วัน
8. เช็คซ้ำอีเมล: กดลิงก์ในเมลซ้ำ → ต้องเจอ "ลิงก์ไม่พร้อมใช้งาน" (single-use)

## รอบ 2 — พนักงานเดิมเปิดร้านตัวเอง (เส้น attach)

1. B เป็นพนักงานร้านเดิม (มี username+LINE ผูกแล้ว, ไม่มีอีเมลในระบบ) → สมัครร้านใหม่ด้วยอีเมล B
2. อนุมัติ → เมลถึง → หน้า claim → เลือก "เข้าสู่ระบบด้วยบัญชีเดิม" → ใส่ username+รหัสเดิม
3. ตรวจ: ไม่มี user ใหม่เกิด, ร้านใหม่ผูกบัญชีเดิมเป็น OWNER, สลับร้านเห็นทั้งสองร้านพร้อม role ต่างกัน, อีเมล B ถูกบันทึกเข้าบัญชี (login ด้วยอีเมลได้), LINE เดิมใช้ได้ทั้งสองบริษัท
4. เส้นพลาด: B ทำรอบใหม่แต่เผลอเลือก "ตั้งรหัสใหม่" แล้วไปกดเชื่อม LINE → ต้องเจอ dialog "LINE นี้เชื่อมกับบัญชีอื่น" → ทดสอบทั้ง "ยังไม่รวมตอนนี้" (สองบัญชีแยก ใช้เว็บได้ปกติ) และเส้นรวม (ตามที่ backend รองรับในรอบนี้)

## รอบ 3 — คิวและ lifecycle เมล

1. ปฏิเสธ: สมัครใหม่ → แอดมินกดปฏิเสธแบบค่าเริ่มต้น → ต้อง**ไม่มีเมลออก**; ปฏิเสธอีกรายพร้อมติ๊กแจ้ง → มีเมลแจ้งสุภาพ
2. เตือนก่อนหมดอายุลิงก์: จำลอง claimEmailLastSentAt ย้อนหลัง 49 ชม. (SQL บน UAT DB) → รอบ sweep ต้องส่งเมลเตือน 1 ฉบับ ครั้งเดียว (token ใหม่ ลิงก์เก่าตาย)
3. ลิงก์หมดอายุ (จำลอง 73 ชม.): กดลิงก์ → "ไม่พร้อมใช้งาน" → ผู้สมัครกดขอส่งใหม่จากหน้าสถานะ → เมลใหม่มา ใช้ได้
4. Reissue โดยแอดมิน: รายการ EXPIRED เก่า → กดส่งลิงก์ใหม่ → ใช้ได้ (ไม่มีทางตัน)
5. เมลตีกลับ: สมัครด้วย bounce@simulator.amazonses.com → อนุมัติ → คิวต้องติดธง "เมลตีกลับ" (ตามระดับที่ต่อ SNS ไว้)
6. กันสแปม: ยิงสมัครซ้ำ ๆ จาก IP เดียว → เจอ rate limit สุภาพ; ยิง externalSignupId เดิม payload เดิม → ได้ requestId เดิม (ไม่เกิดซ้ำ)

## รอบ 4 — P29 term (บีบเวลาให้เห็นจริง)

1. บริษัททดสอบใหม่ผ่านแอดมิน (ไม่ใช่ signup) → term ต้องเป็น STARTER 30 วันอัตโนมัติ; ลูกค้าเดิม (บริษัท UAT เก่า) ต้อง**ไม่มี** term และใช้งานปกติทุกอย่าง
2. ลิมิต: บริษัท STARTER (1 สาขา/2 คน) → สร้างสาขาที่ 2 ต้องเจอ 422 ข้อความไทย; เพิ่มพนักงานคนที่ 3 ต้องโดนบล็อก; แอดมินขยับ limit แล้วสร้างต่อได้ทันที
3. บันไดเตือน: SQL ตั้ง termEndsAt = now+6 วัน → sweep แล้ว OWNER ได้แจ้งเตือน (web+LINE) 1 ครั้ง; ตั้ง +2 วัน → เตือนรอบ 3 วัน; ตั้ง +20 ชม. → เตือนรอบ 1 วัน; **พนักงานต้องไม่เห็นแบนเนอร์/ไม่ได้แจ้งเตือน**
4. หมดอายุจริง: ตั้ง termEndsAt = now-5 นาที → (ก) ยิง API ทันทีต้องโดน block ก่อน sweep (ข) sweep แล้ว company → DISABLED + OWNER ได้แจ้ง (ค) เว็บ: OWNER เจอหน้าแดงต่ออายุ, พนักงานเจอ "ติดต่อเจ้าของร้าน", ป้ายหมดอายุใน switcher (ง) LINE ตอบสุภาพ (จ) ข้อมูลไม่หาย
5. ต่ออายุ: แอดมินกดต่อ 30 วัน → บริษัทกลับ ACTIVE เอง ใช้งานได้ทันที เตือนไม่เด้งซ้ำ; เคสเทียบ: บริษัทที่แอดมิน disable เอง → ต่ออายุแล้วต้อง**ไม่**เปิดอัตโนมัติ
6. ต่อก่อนหมด: บริษัทเหลือ 3 วัน กดต่อ 30 → วันหมดใหม่ = วันหมดเดิม+30 (ไม่ใช่ วันนี้+30)

## รอบ 5 — ความปลอดภัย/ขอบเขต

1. ปิด flag `EXTERNAL_SIGNUP_ENABLED=false` → /signup ขึ้นหน้า "ยังไม่เปิดรับสมัคร", POST โดน 403, แต่หน้า claim ของคนที่อนุมัติแล้วยังใช้ได้
2. เดารหัส requestId/token มั่ว → ข้อความกลางเดียวกัน ไม่บอกใบ้ว่ามี/ไม่มี
3. ชื่อร้านซ้ำกับบริษัทเดิม → สมัครผ่านได้ (ซ้ำได้ตาม spec) และคิวไม่สับสน
4. audit: ทุกอนุมัติ/ปฏิเสธ/reissue/ตั้ง term/ต่ออายุ/auto-disable มี audit ครบ ไม่มี PII เกินจำเป็นใน outbox evidence

ผ่านครบทุกรอบ = พร้อมเดิน release production ตาม runbook V2 (จำ: flag production ยังปิดจนกว่า Owner สั่งเปิด)
