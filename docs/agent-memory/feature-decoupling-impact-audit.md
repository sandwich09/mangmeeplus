## Mechanism (verified)

`filterPermissionsByEntitlement` (apps/api/src/modules/employee-access/domain/logic/feature-gate.logic.ts:75-88) strips permissions of disabled features at permission-resolve time, OWNER included. Ownership = capability-pack `featureEntitlementKey` + `PREFIX_FEATURE_RULES` + submenu rules (packages/contracts/src/feature-entitlements.ts). Submenus auto-enable with parent unless explicitly false (apps/api/src/modules/employee-access/application/entitlement.helper.ts:25-29). `LEGACY_FEATURE_INHERITANCE` applies only when the key has no explicit row (entitlement.helper.ts:20-24) — new companies get explicit rows, so no masking. Worker/system contexts (system-worker-context.ts:16-26) and public webhooks BYPASS the chokepoint entirely — that bypass is the root of most "off isn't really off" findings.
