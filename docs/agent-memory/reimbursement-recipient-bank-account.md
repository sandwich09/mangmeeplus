- Owner decisions 2026-10-01 (binding; D1–D4 in the spec):
  - D1: the payout account is a default account kept in the employee data and pulled into the claim; the claim still freezes its own snapshot, so a later change never alters a submitted or approved claim, a payment record or a printed form. This supersedes the 2026-09-29 recommendation of "per-request first, default later".
  - D2: the full account number is visible only to the requester, that claim's approver and holders of the right to record payment; everyone else sees the last 4 digits. Same rule for API projection, print, export, attachments, audit, LINE and AI tools.
  - D3: a transfer slip is required when the payment method is bank transfer; other methods left to the designer.
  - D4: an account found wrong after approval but before payment goes back to be corrected and re-approved on the same claim, never cancel-and-recreate.
- Designer decisions 2026-10-01 (K1–K13 in the spec §7), the ones a later session must not re-derive:
  - Default account lives in a new table keyed by company membership, not `EmployeeAccessProfile` (owners have no employee profile). Bank account or PromptPay by mobile number; no national-ID PromptPay.
  - A draft follows the member's current default until submit; submit copies it into an immutable version row. Approval hash and signature acknowledgement hash gain a `payout` part only when the claim has a payout method, so legacy claims keep their hashes.
  - Ordinary API projections carry the last 4 digits for everyone. The full number leaves the system two ways only, both limited to the D2 groups by one shared check and both audited: the "reveal" command and the printed form (owner answer Q1 below; the designer's earlier default, last 4 digits on print for everyone, is superseded).
  - The approver attests the account before approving a transfer claim; the payer confirms the account on every transfer payment, which also covers auto-approved and self-approved claims. No account attestation at the finance-review step.
  - Slip required for BANK_TRANSFER only; optional otherwise; a payment method different from the claim's needs a reason. Slip has its own attachment purpose and its own download path; the generic attachment download refuses it. Slip viewers are the D2 groups plus `reimbursement.finance_review` holders (owner answer Q2 below).
  - Correction after approval reuses PENDING_APPROVAL plus correction columns (no new status): only the account is editable, projections/expenses/duplicate state untouched, same approvers re-approve, digital signatures removed, old paper copies stop counting. Chosen over a hold flag on READY_FOR_PAYMENT because anything unaware of the round then refuses payment by itself.
  - Legacy claim = submitted with no payout method; payable as before; the slip rule applies to it when paid by transfer.
  - Misfiled slips are moved with one command ("use this file as the payment slip"), which also withdraws the false paper-signature declaration.
  - No new status, enum value, permission key or feature switch.
- Code findings 2026-10-01 that contradict common assumptions (spec §6): approver roles built or forked before the 2026-09-21 permission change can approve but cannot record payment and no backfill exists; ADMIN/MANAGER have no "waiting for payment" list because the finance queue needs `reimbursement.finance_review`; the page says the claim is with "ฝ่ายการเงิน" even with finance review off; signed-copy files are downloadable by every claim reader through the generic attachment endpoint; the payment form silently defaults to cash; LINE can already write claim drafts. - Owner answers 2026-10-01 to Q1–Q5 (binding; spec §24; applied to the spec and plan the same day):
  - Q1, printed claim form: “เอาเลขเต็มได้เลยไม่เป็นไร”. The print shows the full account number when the person printing is the requester, that claim's approver or a holder of the payment-record right; every full-number print is audited the same way as a reveal; anyone else who may read the claim gets the last 4 digits, without a refusal. No extra restriction on scanned signed copies: the owner accepts that a scan may carry the full number. What this forces beyond wording: the print use case must evaluate the viewer (the renderer only shows what it is handed, and its default is the last 4 digits); the full number appears once, on the "รับเงินคืนทาง" line, and the payment line keeps the last 4 digits; there is no print job shared between viewers, because the form is rendered per request for the caller and never stored (spec E39, §17.1); a copy the system might later store or send must be the last-4 variant.
  - Q2, payment slip: “ให้เปิดดูได้”. Holders of `reimbursement.finance_review` who lack the payment-record right may open the slip (spec §11.4). They still see only the last 4 digits of the account number on screen and on print, and the reveal command still answers 403 for them. What this forces: the slip-viewer group is now wider than the full-number group, so the claim detail carries a separate "can open the slip" flag and the two checks must never be merged.
  - Q3, role backfill: confirmed. `reimbursement.payment.record` and `reimbursement.payment.void` are added to company roles that already hold `reimbursement.approve` (K12, plan 0.6). The release note and the audit of the backfill stay: count the affected roles before release, compare with the `sync-permissions` report after deploy. The backfill re-runs on every deploy and is never revoked, so an approve-only company role cannot persist.
  - Q4, default payout account of a subordinate: confirmed. A manager may set or edit it within the existing employee-edit scope, with audit and a notice to the account owner. What this forces: the notice (plan 4.4, AC45) is a condition of the answer, so it can no longer be cut or deferred, and setting an account for someone else must not reach production before it.
  - Q5, the six waiting production claims: not blocking. They are recorded as paid now with the method โอนเงิน (the current form preselects cash, so the payer must change it), and the misfiled slips are moved after Phase 2 ships.
