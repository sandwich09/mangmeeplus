# Stripe settlement observation — developer notes, 2026-09-15

Status: API research for remaining C07 implementation; no native account read, financial mutation or acceptance claim.

- A Balance Transaction reports signed gross `amount`, `fee`, `net = amount - fee`, currency, source and when funds become available. Its `pending`/`available` status concerns the Stripe balance. It is not a customer's unpaid/paid state. The documented object has no `livemode` field, so bind retrieval to the verified Stripe account/client mode and exact source instead of inventing a required field. [Object](https://docs.stripe.com/api/balance_transactions/object), [retrieve](https://docs.stripe.com/api/balance_transactions/retrieve).
- List supports a creation window, currency, original source, automatic payout and cursor, at most100 rows. Persist a bounded cursor and distinguish partial coverage. A source result does not establish that every account transaction was examined. [List](https://docs.stripe.com/api/balance_transactions/list).
- Payouts expose amount/currency, mode, automatic/method, status, expected arrival, balance transaction and reconciliation status. `paid` can later become `failed`; keep observation time and do not claim independent bank confirmation. Only completed standard automatic payouts support listing their constituent balance transactions. [Object](https://docs.stripe.com/api/payouts/object), [retrieve](https://docs.stripe.com/api/payouts/retrieve).
- Stripe cannot allocate instant payouts to particular transactions. Manual payouts require balance reconciliation; automatic payout reports can arrive later than transaction capture. These conditions must produce an explicit manual/pending result and a provider report route, never revoke paid access or fabricate a matched invoice. [Payout reconciliation](https://docs.stripe.com/reports/payout-reconciliation).

Implementation must keep account-level settlement data behind current platform financial scope. A company operator must not see other customers' payout rows. Reuse retained operations, source/lease fences, audited results and existing invoice/case links; observation never changes package rights, triggers a payout or retries a charge. Exact pinned-API native behavior still needs its separate test evidence.
