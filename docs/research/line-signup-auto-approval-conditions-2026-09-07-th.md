## เข้า AUTO_FREE เมื่อครบทุกข้อ

| เงื่อนไข | ความหมาย |
|---|---|
| สมัครผ่าน LINE และเปิด LINE_SIGNUP_ENABLED | Flow B บนเว็บมีเส้นทางรออนุมัติของตนเอง |
| LINE_SIGNUP_APPROVAL_MODE=AUTO_FREE | ค่า default ใน config schema คือ MANUAL; ต้องอ่านค่าที่ตั้งจริงเวลา deploy |
| ผ่านการตรวจ token, ข้อมูล, legal และ rate limit | การกดรับเงื่อนไขต้องตรงกับ legal release ปัจจุบัน |
| LINE นี้ไม่เคยมี membership บทบาท OWNER ที่พ้น DRAFT | ร้านที่ปิด/สมาชิกเจ้าของที่ไม่ได้ ACTIVE แล้วก็ยังเป็นประวัติ; เคยเป็นพนักงานอย่างเดียวไม่นับเป็นเจ้าของร้านเดิม |
| อีเมลไม่เคยใช้ในข้อมูลที่กำหนด | กฎ Owner ที่เพิ่มรอบนี้: ตรวจ User.email, username เก่าที่เป็นอีเมลเดียวกัน, Company.email และคำขอสมัครอื่นที่บันทึกไว้; ตัดคำขอปัจจุบันออก |
| มี SYSTEM_ADMIN ที่ใช้งานได้ให้บันทึกเป็นผู้ดำเนินการ | ตรวจ membership ACTIVE และ User ACTIVE พร้อมบทบาท SYSTEM_ADMIN; การได้ชื่อผู้ดำเนินการไม่ได้แปลว่าคนนั้นกดอนุมัติเอง |
| ยังมีช่องอนุมัติอัตโนมัติของวันนั้น | ใช้ LINE_SIGNUP_AUTO_DAILY_CAP ตามวันกรุงเทพ ค่าเริ่มต้น20 คำขอที่ได้รับ autoApproved นับเข้าช่องนี้แม้การเปิดร้านภายหลังล้มเหลว |
| ขั้นตอนสร้างร้านสำเร็จ | บันทึกร้าน เจ้าของ LINE สิทธิ์/เงื่อนไขการใช้ และสถานะจน COMPLETED แล้วจึงเป็นร้านพร้อมใช้ |

## รับคำขอแล้วรอแอดมิน: PENDING_REVIEW

| กรณี | ผล |
|---|---|
| เปิดโหมด MANUAL | ทุกคำขอที่ผ่านการตรวจเข้าแถวรออนุมัติ |
| LINE เคยเป็นเจ้าของร้าน | เข้าคิวตรวจการทดลองซ้ำ รวมเคยยกเลิกผูก LINE หรือร้านเดิมปิดแล้ว |
| อีเมลเคยใช้แล้ว | กฎใหม่ของ Owner: รับคำขอ แต่ไม่เปิดร้าน/ให้สิทธิ์ทดลอง/ใช้ช่อง AUTO_FREE จนแอดมินอนุมัติ |
| ไม่มี SYSTEM_ADMIN ที่เข้าเงื่อนไข | เก็บคำขอไว้ให้ตรวจ ไม่สร้างร้านด้วยผู้ดำเนินการปลอม |
| ช่อง AUTO_FREE รายวันเต็ม หรือกำหนด cap=0 | คำขอใหม่เข้าคิวรอแอดมิน |
| สมัครจากเว็บไซต์ Flow B | หลังผ่าน validation/MX จึงเข้าคิวแอดมินตาม flow เดิม ไม่ใช้สวิตช์ AUTO_FREE ของ LINE |

คำขอใหม่พร้อมกันที่ใช้อีเมลเดียวกันต้องไม่เปิดอัตโนมัติทั้งคู่ การส่งทั้งคู่เข้าคิวตรวจเมื่อมาพร้อมกันเป็นผลที่ยอมรับได้ การพบอีเมลซ้ำเป็นเพียงสัญญาณให้ตรวจ ไม่ใช่หลักฐานให้รวม/ผูกบัญชีโดยอัตโนมัติ

## ไม่ได้เข้า AUTO และไม่ใช่การส่งเข้าคิวใหม่โดยอัตโนมัติ

| กรณี | ผลที่โค้ดปัจจุบันกำหนด |
|---|---|
| ปิด LINE_SIGNUP_ENABLED | ปฏิเสธการสมัคร/อ่านสถานะผ่าน public route |
| token LINE ไม่ถูกต้อง หมดอายุ หรือผิด channel | ปฏิเสธก่อนสร้างคำขอ |
| บัญชีผู้ใช้ถูกบล็อก หรือ LINE identity ถูก DISABLED | ปฏิเสธ; การยกเลิกผูก LINE ไม่ใช่ทางลัดเลี่ยงการบล็อก |
| ชื่อร้าน/มือถือ/อีเมล/ข้อมูล legal ผิดรูปแบบ | แจ้งให้แก้ ไม่ใช้ช่องจำนวนร้านต่อวันกับการพิมพ์ผิดที่ยังไม่สร้างคำขอ |
| legal release เปลี่ยนจากหน้าที่ค้างไว้ | ต้องโหลดหน้าปัจจุบันและรับเงื่อนไขใหม่ |
| LINE เดียวกันมีคำขอเปิดค้างอยู่ | ใช้สถานะคำขอเดิม/แจ้ง already_pending ไม่สร้างคำขอใหม่ซ้ำ |
| เกิน rate limit | ปฏิเสธชั่วคราว429; ไม่ใช่คิวอนุมัติ โดย LINE signup มี20 attempts/ชั่วโมงต่อLINE,20/ชั่วโมงต่อIP และ3คำขอที่สร้างต่อ24ชั่วโมงต่อLINE |
| Redis/ฐานข้อมูลหรือขั้นตอนเปิดร้านขัดข้อง | อาจตอบผิดพลาดหรือค้างในสถานะงาน/PROVISIONING_FAILED ให้กู้ผ่านทางเดิม ต้องดูสถานะจริง ไม่อ้างว่าร้านเปิดหรือแอดมินรออนุมัติแล้ว |

## สิ่งที่ไม่ได้เป็นเงื่อนไขกัน AUTO

- นอกเวลาทำการ: businessHours ใช้เลือกข้อความ/SLA ของคิวรอ ไม่ได้ปิดการอนุมัติอัตโนมัติ
- ยังไม่ได้ตั้งรหัสผ่านหรือยืนยันกล่องอีเมล: สมัครผ่าน LINE ได้ทันทีตามที่ Owner ยืนยัน
- ยังไม่มีเลขภาษี ที่อยู่ หรือข้อมูลร้านส่วนเสริม: ไม่ใช่เงื่อนไขก่อนเปิดร้านหรืออ่านบิล
- ชื่อร้านซ้ำ: public signup ยอมให้ชื่อร้านเหมือนกันได้ ไม่ใช่หลักฐานว่าร้านเดียวกัน
- เบอร์มือถือซ้ำอย่างเดียว: ปัจจุบันเป็นข้อมูลช่วยตรวจในคิวแอดมิน ไม่ใช่เงื่อนไขกัน AUTO_FREE
- เคยเป็นพนักงานในร้านคนอื่น: ไม่ใช่ประวัติเจ้าของ แต่ถ้าอีเมลที่ใช้สมัครซ้ำ ก็เข้ากฎอีเมลรออนุมัติใหม่
- คำขอเก่าถูกปฏิเสธและยังไม่เคยเปิดร้านสำเร็จ: LINE เดิมที่เปลี่ยนเป็นอีเมลใหม่อาจเข้า AUTO ได้ หากไม่ชนประวัติเจ้าของหรือเงื่อนไขอื่น; อีเมลเดิมยังต้องรออนุมัติ
- มี referral code: รับ/ตรวจรูปแบบ แต่ไม่มีเงื่อนไขอนุมัติอัตโนมัติพิเศษจาก code นี้

ช่องว่างเชิงนโยบายที่แจ้ง Owner: การเปลี่ยนทั้ง LINE และอีเมล แต่ใช้เบอร์เดิม/ชื่อร้านเดิม ยังอาจเข้า AUTO ได้ตามเงื่อนไขปัจจุบัน รอบนี้ไม่เพิ่มกฎบล็อกเบอร์หรือชื่อเอง
