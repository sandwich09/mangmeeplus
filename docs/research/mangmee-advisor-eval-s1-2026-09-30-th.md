## สภาพแวดล้อม (สเปก §9.1)

- **Runtime:** AgentCore runtime แยก process ด้วย env ของ `infra/ai-gateway/agentcore-deploy.sh` (ค่าเริ่มต้นแบบ deploy) และ gateway เรียกผ่าน `LINE_AI_AGENT_RUNTIME=agentcore` ตามแบบการรันทวน NAT05/NAT06

- **API:** Nest API ที่ build แล้วรันใน process ของ harness (`scripts/line-ai-reliability-runtime.ts`) ใช้ค่า `api` ของ `scripts/line-ai-expense-advisor/production-ai-env.json` ตาม allowlist ของ runtime ส่วน gateway ใช้ค่า `gateway` ของไฟล์เดียวกัน
- **ข้อมูล:** ร้านสังเคราะห์ที่สร้างจาก fixture NAT-12 เปิดฟีเจอร์ตามแพ็กเกจ STARTER (ฟีเจอร์เท่ากันทุกแพ็กเกจที่ขาย) แต่ละข้อรันในแชตใหม่บนฐานข้อมูลที่ reset แล้ว
- **LINE:** HTTP sink ในเครื่อง

- ทุกข้อต้องผ่านในการรันสองรอบติดกันบน commit เดียวกัน
- ข้อที่ไม่ผ่าน: ตัวเลขไม่ตรง oracle, ข้อความตอบไม่ได้แบบสำเร็จรูป (dead end), รหัสเครื่องหลุด, เลขผู้เสียภาษีหรือที่อยู่หลุด, อ้างว่าเซ็นหรืออนุมัติแล้ว, เรียกเครื่องมือต้องห้าม, ไม่มีเครื่องมือที่ต้องเรียก, มีการเขียนข้อมูล (เครื่องมืออ่านอย่างเดียว), ลงท้าย ครับ

## สิ่งที่แก้ระหว่างรอบ

1. **หลังรอบ 1**
   - router และคำอธิบายเครื่องมือเขียนคำ Q1 ภาษาไทยไว้ชัด ("วันนี้มีอะไรต้องทำบ้าง") ให้อ่าน closing อย่างเดียว เฉพาะข้อความที่บอกว่างาน **ค้าง** เท่านั้นที่เป็นงานค้างของฉัน (Q2)
   - Q2 เติมคิวที่ขาดครั้งเดียวต่อคำขอ ไม่อ่านซ้ำในทุกส่วน
   - คิวฝั่งอนุมัติคืนจำนวนแยกตามขั้น (`byStep`: รอคุณอนุมัติ / ฉบับกระดาษรอคุณตรวจรับ) นับจากฐานข้อมูล คำตอบที่แบ่งกลุ่มจึงมีตัวเลขรองรับ
   - คิวนี้อยู่ในความจำการอ่าน คำถามต่อเนื่องจึงรู้ว่าหมายถึงรายการชุดไหน
2. **หลังรอบ 2**
   - คำตอบ Q2 สั้นลง: แต่ละส่วนไม่เกินสามบรรทัด บอกจำนวนและว่าทำบนเว็บ
   - ตัวกรองข้อความตัดชื่อ field แบบ camelCase ในวงเล็บ
3. **หลังรอบ 3:** Q2 ต้องตอบแยกตามลำดับส่วนของตัวเอง
4. **หลังรอบ 4**
   - router พูดถึงคิวอนุมัติใบเบิกเฉพาะเมื่อผู้ถามได้รับเครื่องมือนั้น
   - ถ้าผู้ถามไม่มีคิวอนุมัติ ส่วนใบเบิกของ Q2 จะอ่านสรุปใบเบิกของตัวเองแทน
5. **หลังรอบ 5:** ถ้าข้อความไม่ได้เอ่ยวันใดเลย วันที่ของวันนี้บน closing ถือเป็นค่าเริ่มต้นของเครื่องมือเอง ข้อความที่เอ่ยวันอื่นยังใช้กฎเดิม

## ข้อที่ยังเปิดอยู่

- **ลิงก์ของ Q2:** สเปก §4.2 ให้มีลิงก์กดได้หนึ่งลิงก์ แต่การ์ดใส่ปุ่มให้ทุกแหล่งข้อมูล Q2 จึงมีได้ถึงสามปุ่ม (closing, ใบรับรองแทนใบเสร็จ, ใบเบิก) รอเจ้าของตัดสิน
- **รายการใน Q2:** ส่วนคิวลายเซ็นของ Q2 บางครั้งยังไล่รายการเอกสาร แม้ prompt จะให้สรุปแค่จำนวน ตัวเลขทุกตัวยังถูกตรวจกับข้อมูลจริง
