## สถานการณ์สมมติที่ควรออกแบบรองรับ

ตารางนี้เป็นสถานการณ์เพื่อออกแบบ ไม่ใช่สถิติเหตุการณ์ที่ยืนยันจากลูกค้า

| สถานการณ์ | ผลที่เสนอ |
|---|---|
| เปลี่ยนมือถือแต่ยังเข้า LINE เดิมได้ | กลับร้านเดิมตามสิทธิ์ ไม่สมัครซ้ำ ไม่เริ่ม trial ใหม่ |
| จำไม่ได้ว่าเคยสมัครแล้ว | ทางเข้าร้านเดิมก่อนเปิดร้าน โดยแสดงข้อมูลร้านได้หลังพิสูจน์บัญชีแล้ว |
| เข้า LINE เดิมไม่ได้/ใช้ LINE ใหม่ | กู้การเข้าบัญชีเดิมหลังพิสูจน์ตัวตน; ไม่เปิดร้านเปล่าทดแทน |
| เจ้าของเพิ่มร้านอีกแห่ง | เพิ่มร้านให้บัญชีเดิมหลังยืนยันเจตนา แยกการให้ trial ออกจากการมีสิทธิ์สร้างร้าน |
| เพิ่มสาขาร้านเดิม | ใช้การเพิ่มสาขาตามแพ็กเกจ ไม่สร้างบริษัทใหม่โดยอัตโนมัติ |
| คู่สมรส/คนทำบัญชีใช้อีเมลติดต่อร่วมกัน | ไม่ถือว่าเป็นบุคคลเดียวกัน; ถ้าต้องเข้าร้านเดียวกันให้เชิญสมาชิกตามบทบาท |
| พิมพ์อีเมลผิด หรือมีคำขอเก่าที่ไม่เคยเปิดร้าน | ให้แก้ข้อมูล/กลับมาทำคำขอเดิม; ประวัติที่ยังไม่พิสูจน์ไม่ควรเป็นการจองอีเมลถาวร |
| ร้านเดิมหมดทดลอง/ปิดใช้งาน | เข้าทางต่ออายุหรือแก้สถานะเดิม การกู้บัญชีไม่รีเซ็ต trial |

## ทางเลือกและข้อแลกเปลี่ยน

1. อีเมลซ้ำทุกกรณีรอแอดมิน: ทำง่าย กัน auto ได้ แต่คิวรวมคนหลายเจตนาและยังเปิดร้านซ้ำได้หากปุ่มอนุมัติไม่แยกผล
2. เปิดร้านใหม่ต่อได้ทั้งหมดแล้วรวมบัญชีภายหลัง: สมัครเร็ว แต่ข้อมูลกระจาย ผู้ใช้เห็นร้านว่าง และการรวมสิทธิ์/ประวัติภายหลังซับซ้อน
3. ใช้ตัวตนที่พิสูจน์แล้วและเจตนาผู้ใช้เลือกทาง: เพิ่มงานเชื่อม flow ตอนแรก แต่ใช้ทางด่วนกับคนทั่วไปและส่งเฉพาะการกู้/ความขัดแย้งไปให้เจ้าหน้าที่ เป็นแนวทางที่เสนอให้พิจารณา

## Flow ที่เสนอ

- LINE ที่รู้จัก: แสดงร้านที่มีสิทธิ์และปุ่มเข้าร้านเดิมเป็นหลัก มีปุ่มเพิ่มร้านแยกต่างหาก การเปลี่ยนมือถือไม่ถือว่าเปลี่ยนตัวตน LINE
- ผู้มาใหม่: เปิดร้านครั้งแรกได้ตามกฎเดิมโดยไม่ตั้ง password/รออีเมล มีทางเลือก “เคยใช้แล้ว / เข้าร้านเดิมไม่ได้” ที่หาเจอ
- เมื่อมีความขัดแย้ง: เก็บแบบฟอร์มเดิมไว้ เสนอทางไปบัญชีเดิม แก้ข้อมูล หรือขอเจ้าหน้าที่ช่วย ไม่สร้างร้าน/แจก trial ระหว่างรอข้อสรุป และไม่เปิดเผยชื่อร้านของผู้อื่นเพียงเพราะกรอกอีเมลตรง
- พิสูจน์ตัวตนด้วยการเข้าบัญชี/LINE เดิมเมื่อทำได้; กู้บัญชีผ่านเจ้าหน้าที่เมื่อทำไม่ได้ อย่าใช้แค่ชื่อร้าน เบอร์ที่พิมพ์ใหม่ หรืออีเมลตรงกันเป็นหลักฐานพอให้ย้ายสิทธิ์
- ขณะส่งเมลยังไม่พร้อม ไม่เสนอ OTP อีเมลเป็นทางบังคับ และไม่อ้างว่าส่งแล้ว เมื่อพร้อมภายหลังให้เป็นตัวเลือกเฉพาะที่เข้าเงื่อนไข ไม่ใช่หลักฐานว่าครองทุกร้านที่เคยใส่อีเมลนั้น
- ผู้ใช้ทั่วไปเห็นคำว่าร้านและการเข้าใช้งาน ไม่ต้องเรียนเรื่อง User.email / Company.email; แสดงชื่อร้านและผลที่จะเกิดก่อนยืนยัน ถ้ายังใช้อีเมลล็อกอินไม่ได้ต้องบอกตรง ๆ

## ฝั่งแอดมินที่ต้องเปลี่ยนควบคู่

แยกผลการตัดสินใจอย่างชัดเจน: ช่วยกลับบัญชี/ร้านเดิม; เพิ่มร้านให้บัญชีที่พิสูจน์แล้ว; เปิดร้านใหม่ให้ผู้สมัครคนละคน; ขอข้อมูลเพิ่ม/ปฏิเสธ การย้ายสิทธิ์ต้องมีหลักฐานและบันทึกการตัดสินใจ ปุ่ม approve ทั่วไปไม่ควรครอบทั้งการคืนบัญชีและสร้างร้าน

จัดรายการข้อมูลที่ขาดครั้งเดียว บันทึกคำขอให้กลับมาทำต่อได้ ไม่บังคับตอบทันที ไม่ส่งเตือนถี่ และไม่มีการเปิดร้านหรือหมดอายุ trial ระหว่างยังรอตรวจ

AI ช่วยสรุปข้อมูลและชี้ว่าต้องตรวจอะไรได้ แต่การย้ายสิทธิ์/เลือกบัญชีปลายทาง/ให้ trial ต้องใช้เงื่อนไขและหลักฐานที่ตรวจสอบได้ ไม่ใช้ข้อสรุปจากการคาดเดาของโมเดล

## ข้อเสนอเรื่องอีเมลและสิทธิ์ทดลอง

- อีเมลติดต่อร่วมกันเป็นไปได้ จึงไม่ควรใช้เป็นรหัสประจำร้าน
- อีเมลบัญชีใช้ร่วมหลายร้านภายใต้บัญชีเดียวได้ แต่ไม่ควรสร้างบัญชีล็อกอินคนละคนด้วยอีเมลเดียวกันอย่างเงียบ ๆ
- อีเมลซ้ำกับบัญชีที่พิสูจน์แล้ว และซ้ำแค่คำขอที่ไม่เคยเปิดร้าน มีน้ำหนักต่างกัน ควรแยกหลักฐานก่อนกำหนดว่าเคสไหนต้อง manual; ยังไม่อนุมัติให้คลายกฎปัจจุบัน
- การกู้ร้านเดิมไม่แจก trial ใหม่ ส่วนการเปิดร้านใหม่โดยเจ้าของเดิมควรตัดสิน entitlement แยกจากสิทธิ์เข้าใช้งาน; เสนอให้แอดมินยืนยันสิทธิ์ทดลองเพิ่มในระยะแรก ไม่ถือว่าอนุมัติให้เปิดร้านเท่ากับแจก trial ซ้ำเสมอ

## สิ่งที่ต้องพิสูจน์ก่อนยืนยันแบบ

ลองต้นแบบกับเจ้าของร้านที่ใช้ LINE คล่อง/ไม่คล่อง รวมผู้สูงอายุ: กลับร้านเดิม เปิดร้านเพิ่ม และกู้บัญชี โดยไม่บอกวิธีกดล่วงหน้า ดูว่ากลับถึงร้านถูกแห่งได้หรือไม่ ต้องขอความช่วยเหลือกี่ครั้ง และเกิดร้านซ้ำหรือสิทธิ์ผิดบัญชีหรือไม่ ยังไม่กำหนดตัวเลขเป้าหมายที่ไม่มี baseline

ทดสอบการสมัครซ้ำ/กดซ้ำ/ค้างแล้วกลับมา/พิมพ์ผิด/ผู้ใช้คนอื่นกรอกอีเมลเรา/บัญชีถูกระงับ/ร้านหมดทดลอง/เพิ่มสาขา/ผู้ใช้มีหลายบทบาท กำหนดผลให้ชัดก่อน coding

## แหล่งอ้างอิงด้านการผูกบัญชี

- [Auth0 User Account Linking](https://auth0.com/docs/manage-users/user-accounts/user-account-linking): ขอให้พิสูจน์ทั้งสองบัญชีก่อนเชื่อม; อีเมลตรงกันใช้แนะนำให้เชื่อมหลัง authentication ได้ ไม่ใช่สิทธิ์เชื่อมทันที
- [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html): re-authentication สำหรับการกู้/เปลี่ยนข้อมูลสำคัญ และหลีกเลี่ยงการเปิดเผยว่าบัญชีอื่นมีอยู่ผ่านข้อความสมัคร/ล็อกอิน

การใช้แนวทางเหล่านี้เป็นข้อเสนอออกแบบสำหรับระบบนี้ ไม่ใช่ข้ออ้างว่าต้องเปลี่ยนผู้ให้บริการ authentication หรือติดตั้ง Auth0
