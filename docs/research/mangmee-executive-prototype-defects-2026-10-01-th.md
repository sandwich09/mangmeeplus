## 3. รายละเอียด — ต้องแก้

### PD-01 กดเจาะแล้วกดกลับ ตัวกรองร่วมถูกเขียนทับ

- **อาการ:** การกดกลุ่มในกราฟหรือตารางเขียนค่าของกลุ่มนั้นลงตัวกรองร่วมของรายงาน เมื่อกดกลับ ตัวกรองนั้นยังอยู่ ตัวเลขของทุกหน้าหลังจากนั้นจึงเป็นของกลุ่มเดียวโดยที่ผู้ใช้ไม่ได้ตั้งตัวกรองเอง
- **วิธีดู (1):** ลูกค้าและที่มา → แท็บช่องทาง (ตารางมี 5 แถว) → กด Facebook → รายชื่อ 16 บริษัท → “← กลับลูกค้าและที่มา” → ตารางเหลือ 1 แถว แถบเงื่อนไขขึ้น “Facebook” และการ์ดแรกของหน้าภาพรวมเปลี่ยนจาก 72 เป็น 16
- **วิธีดู (2):** ภาพรวม → ตั้งตัวกรอง “รู้จักมั่งมีจากไหน” เป็น Facebook (การ์ดแรก 16) → เปรียบเทียบ → “ดูรายชื่อฝั่ง A” → กลับ → ภาพรวมเป็น 14 เงื่อนไขขึ้น “ร้านอาหาร” ตัวกรอง Facebook หายไป
- **ไฟล์และบรรทัด:** tsx:155 `drill` ใส่ `[key]:value` ลงตัวกรองชุดเดียวกับตัวกรองร่วม; tsx:208 `drillSide` ตั้ง `{...defaults,month,[kind]:id}` จึงล้างตัวกรองร่วมทั้งชุด; tsx:153 `go` และปุ่มกลับที่ tsx:290 เรียก `persist(next,filters)` ด้วยตัวกรองที่ถูกเขียนทับแล้ว; check-demo:31 เรียก `reset()` ทันทีหลังกดกลับ จึงไม่เห็นอาการ; check-demo:42–43 ทดสอบเฉพาะกรณีที่ไม่ได้กดดูรายชื่อฝั่ง
- **วิธีแก้:** แยกสถานะเป็นสองชุด คือตัวกรองร่วมของรายงาน กับเงื่อนไขเฉพาะรายชื่อ (รวมเงื่อนไขที่กดเจาะมา) ตาม[สเปกหน้าจอ §3.3](../specs/mangmee-executive-business-ui-spec-th.md)
  - `drill` ของมิติที่เป็นตัวกรองร่วม (ธุรกิจ ช่องทาง เซลล์) เก็บเงื่อนไขเป็น `pick` ของรายชื่อ ไม่แตะตัวกรองร่วม
  - `drillSide` เก็บ `pick` กับที่มา `compare` และรายชื่อนั้นใช้เฉพาะเดือนกับ `pick` พร้อมข้อความ “รายชื่อนี้มาจากหน้าเปรียบเทียบ ไม่ใช้ตัวกรองของรายงาน”
  - ปุ่มกลับคืนสถานะของหน้าต้นทางที่จำไว้ตอนกด (เดือน ตัวกรองร่วม แท็บ) ไม่ส่งตัวกรองของรายชื่อกลับไป
  - รายชื่อแสดงเงื่อนไขที่กดมาเป็นป้ายที่ลบได้
- **ตรวจหลังแก้:** ลบ `reset()` ที่ check-demo:31 แล้วยืนยันว่าหลังกลับ ตารางช่องทางยังมี 5 แถวและการ์ดแรกของภาพรวมยังเป็น 72; เพิ่มเส้นทาง “ตั้ง Facebook → เปรียบเทียบ → ดูรายชื่อฝั่ง A → กลับ → ภาพรวม” แล้วยืนยันว่ายังเป็น 16 และเงื่อนไขยังเป็น Facebook (เคส REP-23, REP-24)

### PD-02 เงินแสดง “฿…”

- **อาการ:** ยอดเงินทุกจุดขึ้น “฿245,806.00” และค่าติดลบขึ้น “-฿4,000.00” กติกาของเจ้าของคือ “1,234.50 บาท” ไม่ใช้ ฿ หรือ THB
- **วิธีดู:** ภาพรวม การ์ดใบที่สี่; เปรียบเทียบ แถวยอดรับสุทธิ แล้วกด “สลับ A / B”; แผงส่งออก ตัวอย่างชีตรายบริษัท ซึ่งหัวคอลัมน์เขียน “(บาท)” แต่ค่าในช่องยังมี ฿
- **ไฟล์และบรรทัด:** tsx:75 `money` ใช้ `Intl.NumberFormat('th-TH',{style:'currency',currency:'THB'})`; ค่าในชีตตัวอย่างที่ tsx:233 และ tsx:245 ใช้ `money` ใต้หัวคอลัมน์ “(บาท)”; ตัวตรวจยืนยันรูปแบบผิดที่ check-demo:13, 35, 38 และ check-export:20, 21, 24
- **วิธีแก้:** เปลี่ยน `money` ให้คืนตัวเลขคั่นหลักพัน ทศนิยม 2 ตำแหน่ง เว้นวรรคแล้วตามด้วยคำว่า บาท เช่น

  ```ts
  const money = (satang:number) => `${new Intl.NumberFormat('th-TH',{minimumFractionDigits:2,maximumFractionDigits:2}).format(satang/100)} บาท`;
  ```

  ช่องใต้หัวคอลัมน์ที่มี “(บาท)” ให้เขียนเฉพาะตัวเลข ไม่มีหน่วยซ้ำ ค่าที่ไม่มีข้อมูลยังเป็น — ไม่ใช่ “0.00 บาท”
- **ตรวจหลังแก้:** แก้ค่าที่ตัวตรวจคาดเป็น “245,806.00 บาท”, “58,464.00 บาท”, “54,464.00 บาท”, “4,000.00 บาท”, “-4,000.00 บาท”, “204,930.00 บาท” และเพิ่มข้อยืนยันว่าข้อความทั้งหน้าไม่มีอักขระ ฿ (เคส FE-19)

### PD-10 สีกราฟ: สีเดียวสองความหมาย และแยกไม่ออกเมื่อไม่เห็นสี

### PD-15 ชื่อตัวเลขและกลุ่มไม่ตรงกัน และ “ใช้งาน” มีสองนิยาม

- **อาการ:** ตัวเลขเดียวกันมีหลายชื่อ และชื่อคล้ายกันนับคนละอย่าง
- **วิธีดูและบรรทัด:**
  - ใช้งานในเดือน: การ์ด “ใช้ระบบในช่วงนี้” นับบริษัทที่มีเอกสารหรือใช้ผู้ช่วย และแสดง “อย่างน้อย N” (tsx:174, 237); หน้าเปรียบเทียบ “บริษัทที่ใช้ในเดือน” นับบริษัทที่วันใช้งานมากกว่า 0 และแสดง “—” เมื่อมีบริษัทที่ไม่ทราบ (tsx:122–123) ตัวอย่าง: กรองธุรกิจ “บริการ” การ์ดขึ้น “อย่างน้อย 5” แต่หน้าเปรียบเทียบของ “บริการ” ขึ้น “—”

  - ยอดเงิน: “ยอดรับสุทธิ” (tsx:174, 196, 292), “รับสุทธิในเดือน” (tsx:176, 194), “รับสุทธิ” (tsx:290), “ยอดรับหลังหักคืนเงิน (บาท)” (tsx:233, 245), “ยอดรับสุทธิในเดือน” (tsx:122); “รับเงินจริง” กับ “คืนเงิน” (tsx:196, 247, 260) เทียบกับ “เงินรับในเดือน” กับ “คืนเงินในเดือน” (tsx:292)
  - กลุ่มการชำระและใช้งาน: “เคยใช้ แต่ไม่ใช้ในช่วงนี้” กับ “จ่ายแล้ว ใช้งานอยู่” (tsx:25) เทียบกับ “เคยใช้ แต่ไม่ใช้ในเดือนนี้” (tsx:198); “ยังประเมินการใช้งานไม่ได้ — ยังมีข้อมูลการใช้งานไม่เพียงพอ” (tsx:176, 196, 197) เทียบกับ “จ่ายแล้ว แต่ข้อมูลการใช้ไม่ครบ” (tsx:240)

- **วิธีแก้:** รวมข้อความไว้ในตารางเดียวในโค้ด ใช้ชื่อตาม[เอกสารคำบนหน้าจอ](../specs/mangmee-executive-plain-language-spec-th.md) และนิยามตามรหัส N ของ[สเปกหน้าจอ §4.2](../specs/mangmee-executive-business-ui-spec-th.md): บริษัทลูกค้า, ใช้งานในเดือน (นิยามเดียว และ “อย่างน้อย” แบบเดียวทุกที่), ชำระในเดือน, เคยชำระเงิน, ยอดรับสุทธิในเดือน, เงินรับในเดือน, คืนเงินในเดือน, “เคยใช้ แต่ไม่ใช้ในเดือน”, “จ่ายแล้ว ใช้งานในเดือน”, “ยังประเมินไม่ได้” พร้อมเหตุผล, “ยังไม่พบการเพิ่มใบเสร็จ” (แทน “ยังไม่เคยเพิ่มใบเสร็จ”), “เข้าเว็บล่าสุด” (แทนทั้ง “เข้าสู่ระบบล่าสุด” และ “เข้าใช้ล่าสุด”) และเพิ่ม “ใช้ผ่าน LINE ล่าสุด” เป็นอีกช่อง, “ผู้ใช้ที่ใช้งาน”, “รู้จักมั่งมีจากไหน”, “สรุปรายรับ”, “รายรับในเดือนมาจากลูกค้ากลุ่มใด”, “ลูกค้านอกกลุ่มที่จ่ายสูงสุด 20% แรก”, “แตะสีหรือชื่อกลุ่มเพื่อดูบริษัท” ตารางกลุ่มใช้คอลัมน์ “ชำระในเดือน” ให้รวมทุกแถวเท่ากับการ์ด และเพิ่มบรรทัดอธิบายเมื่อสองตัวเลขต่างกัน

### PD-16 คำของค่าที่ไม่ทราบและเซลล์ผู้แนะนำไม่ตรงกัน

- **อาการ:** ค่าที่ไม่ทราบของช่องทางขึ้น “ไม่ระบุ” ในป้ายเงื่อนไขและตาราง (มาจาก `signupDiscoveryLabel`) แต่ขึ้น “ยังไม่ระบุ” ในตัวเลือกของตัวกรอง เซลล์ขึ้น “ไม่มีเซลล์” / “เซลล์ยังไม่ระบุ” ในป้ายเงื่อนไข แต่ขึ้น “ไม่มีเซลล์ผู้แนะนำ” / “ยังไม่ระบุ” ในตัวเลือก และรายละเอียดบริษัทแสดง “เซลล์ผู้แนะนำ —” ทั้งกรณีที่ยืนยันว่าไม่มีและกรณีที่ไม่ทราบ
- **วิธีดู:** ตั้งตัวกรองเซลล์เป็น “ไม่มีเซลล์ผู้แนะนำ” แล้วอ่านป้ายเงื่อนไขใต้ตัวกรอง; เปิดรายละเอียดของบริษัทที่มาจาก Website
- **ไฟล์และบรรทัด:** tsx:170 (ป้ายเงื่อนไข), 171 และ 203 (ตัวเลือก), 193 (ตาราง), 225, 227, 252 (แผงส่งออก); tsx:78 `sales(null)` คืน “—” ใช้ที่ 176, 196, 233, 259; tsx:176 แสดงเซลล์เฉพาะเมื่อช่องทางเป็นเซลล์
- **วิธีแก้:** ใช้คำเดียว “ไม่ระบุ” กับค่าที่ไม่ทราบทุกมิติ และแยกสามกรณีของเซลล์เป็นข้อความ: “ไม่มีเซลล์ผู้แนะนำ”, “ไม่ระบุ”, “เซลล์ที่ไม่พบข้อมูลแล้ว” ให้ `sales` รับบริษัทแล้วคืนหนึ่งในสามข้อความนี้ ไม่คืน —
- **ตรวจหลังแก้:** ไม่มี “ยังไม่ระบุ”, “เซลล์ยังไม่ระบุ”, “ไม่มีเซลล์” (คำสั้น) ในข้อความใด และไม่มี “เซลล์ผู้แนะนำ —”

### PD-17 บริษัทตัวอย่าง MM009 ขัดกันเอง และไม่มีบริษัทที่ใบเสร็จ “ยังประเมินไม่ได้”

- **อาการ:** MM009 (สบายดีสตูดิโอ) ไม่มีข้อมูลการใช้งาน จึงขึ้น “ยังประเมินการใช้งานไม่ได้” แต่ในแถวเดียวกันขึ้น “ใบเสร็จในเดือน 0 ใบ · ยังไม่เคยเพิ่มใบเสร็จ” ซึ่งเป็นข้อสรุปที่ต้องมีข้อมูลครบ และอีเมลกับเบอร์โทรของบริษัทนี้เป็น “—” โดยไม่มีเหตุผล ผลข้างเคียงคือไม่มีบริษัทตัวอย่างใดอยู่ในกลุ่ม “ยังประเมินไม่ได้” ของกราฟใบเสร็จ ส่วนสีเทาจึงไม่เคยถูกวาดและไม่เคยถูกตรวจ
- **วิธีดู:** รายชื่อบริษัท ค้น “สบายดี”; เปิดรายละเอียดแล้วดูช่องอีเมลและเบอร์โทร; กราฟการเริ่มใช้ใบเสร็จไม่มีส่วน “ยังประเมินไม่ได้”
- **ไฟล์และบรรทัด:** tsx:38 (แถวข้อมูลที่การใช้งานเป็น null), tsx:44 (ใบเสร็จสะสมและใบเสร็จในเดือนถูกตั้งเป็น 0 แทน null), tsx:81 (`ownerContact` คืน “—” สองช่อง); check-export:11 ยืนยัน “ยังประเมินไม่ได้ 0”
- **วิธีแก้:** ให้ใบเสร็จสะสมและใบเสร็จในเดือนของ MM009 เป็น null เพื่อให้เป็น “ยังประเมินไม่ได้” จริง; ให้ `ownerContact` คืนเหตุผลเป็นข้อความ เช่น “มีเจ้าของหลายบัญชี”; เพิ่มบริษัทตัวอย่างของสถานะ “ไม่มีในแพ็กเกจ” หนึ่งราย ([เอกสารกราฟและอันดับ §3](../specs/mangmee-executive-usage-pareto-spec-th.md))
- **ตรวจหลังแก้:** ค่าตรวจของข้อมูลตัวอย่างเปลี่ยนจาก 40 / 32 / 0 ตามที่แก้ ต้องแก้ค่าในตัวตรวจและในเอกสารกราฟและอันดับ §9 ให้ตรงกัน; ส่วน “ยังประเมินไม่ได้” ถูกวาดและกดได้ (เคส FE-21, REP-30)

### PD-18 ค่าธรรมเนียมสมมติ 3% และ 0.00

- **อาการ:** 12 บริษัทแรกมีค่าธรรมเนียมเท่ากับ 3% ของยอดรับ อีก 60 บริษัทมีค่าธรรมเนียม 0.00 ซึ่งเป็นค่าที่ไม่ทราบแต่แสดงเป็นศูนย์ และบริษัทที่คืนเงินเต็มจำนวนยังมีค่าธรรมเนียม
- **วิธีดู:** รายละเอียดบริษัท → แท็บการใช้งานและรายรับ ของ MM012 (ชื่นใจครัวบ้าน) และ MM013
- **ไฟล์และบรรทัด:** tsx:53 `feeSatang: Math.round(Number(r[7])*3)`; tsx:65 `feeSatang:0`; แสดงที่ tsx:196 และ tsx:260
- **วิธีแก้:** ให้ค่าธรรมเนียมเป็น null และแสดง — พร้อมเหตุผล “ยังไม่มีข้อมูลค่าธรรมเนียม” เว้นแต่ข้อมูลตัวอย่างจะมีค่าธรรมเนียมรายรายการที่เขียนไว้ชัดว่าเป็นค่าสมมติ ชื่อช่องเป็น “ค่าธรรมเนียมการรับชำระในเดือน”
- **ตรวจหลังแก้:** ไม่มีค่าธรรมเนียมที่คิดจากเปอร์เซ็นต์ และไม่มี “0.00 บาท” ในช่องที่ไม่มีข้อมูล

### PD-19 กราฟแนวโน้มแต่งจากสูตร และวาดค่าติดลบเป็นแท่งบวก

- **อาการ:** กราฟแนวโน้ม 6 เดือนของหน้ารายรับคำนวณจากยอดเดือนกันยายนคูณด้วย 55% บวก 8% ต่อเดือน ขณะที่อีกสามจุดในต้นแบบบอกว่ายังไม่มีข้อมูลย้อนหลัง และการเลือกเดือนสิงหาคมขึ้น “ยังไม่มีข้อมูลตัวอย่างสำหรับเดือนนี้” แท่งของเดือนที่ยอดติดลบจะถูกวาดเป็นแท่งบวกสูง 2 px
- **วิธีดู:** รายรับ → แท็บรายรับ ดูกราฟ แล้วเปลี่ยนเดือนเป็น ส.ค. 2569
- **ไฟล์และบรรทัด:** tsx:175 (`0.55+i*0.08` และ `Math.max(2,…)`); ข้อความที่ขัดกันที่ tsx:198 (“เทียบเดือนก่อน: ยังไม่มีข้อมูลย้อนหลังครบในตัวอย่าง”), tsx:209 (“ตัวอย่างมีข้อมูลครบเฉพาะกันยายน 2569”), tsx:247 (“ไม่รวมแนวโน้มเดือนก่อน”); tsx:165 `monthReady`
- **วิธีแก้:** เลือกทางเดียว: ลบกราฟแนวโน้มจนกว่าจะมีข้อมูลตัวอย่างรายเดือนจริง หรือเพิ่มยอดรายเดือนเป็นข้อมูลตัวอย่างที่เขียนไว้ชัด แล้วให้เดือนเหล่านั้นเลือกดูได้ และแก้ข้อความสามจุดให้ตรงกัน กราฟต้องมีเส้นฐานที่ 0 และวาดค่าติดลบใต้เส้นฐาน
- **ตรวจหลังแก้:** เพิ่มเดือนตัวอย่างที่ยอดรับสุทธิติดลบ แล้วยืนยันว่าแท่งอยู่ใต้เส้นฐานและป้ายเป็น “-… บาท” (เคส FE-20)

### PD-20 แพ็กเกจและสถานะที่ต้นแบบตั้งเอง

- **อาการ:** มีแพ็กเกจชื่อ “ทดลองใช้” ทั้งที่ระบบไม่มีการทดลองใช้ฟรีแล้ว ชื่อแพ็กเกจตั้งจากราคาด้วยเกณฑ์สองชุดที่ไม่ตรงกัน และสถานะ “ใช้งานได้ / หมดอายุ / เก็บถาวร” รวมสถานะบริษัทกับสถานะบริการไว้ในช่องเดียวและตัวกรองเดียว
- **วิธีดู:** รายชื่อบริษัท คอลัมน์ “บริการ / การชำระ”; ตัวกรองรายชื่อเพิ่มเติม → สถานะบริการ
- **ไฟล์และบรรทัด:** tsx:51 (`'ทดลองใช้'`, เกิน 2,000 = Pro, เกิน 1,000 = Plus), tsx:65 (เกิน 2,990 = องค์กร, เท่ากับ 2,990 = Pro), tsx:50 (สถานะ), tsx:290 (ตัวกรองสร้างจากค่าเหล่านี้)
- **วิธีแก้:** เปลี่ยนชื่อช่องและตัวกรองเป็น “สถานะแพ็กเกจ” และใช้ป้ายชุดเดียวกับ `PLAN_TERM_STATE_LABEL_TH` ใน `packages/contracts/src/plan-term.ts` (ใช้งานได้ / กำลังทดลองใช้ / ยังไม่มีแพ็กเกจ / หมดอายุ / พักการใช้งาน); สถานะบริษัทเป็นอีกช่องและอีกตัวกรอง (ใช้งานอยู่ / ปิดใช้งาน / เก็บถาวร / ระงับชั่วคราว); ชื่อแพ็กเกจเป็นชื่อสมมติที่ไม่ผูกกับราคา และบริษัทที่ยังไม่เคยชำระใช้ “ยังไม่มีแพ็กเกจ”
- **ตรวจหลังแก้:** ไม่มี “ทดลองใช้” เป็นชื่อแพ็กเกจ และตัวกรองสถานะแพ็กเกจไม่มี “เก็บถาวร”

### PD-21 ข้อมูลสมมติอื่นที่ดูเหมือนกติกา

- **อาการ:** ค่าต่อไปนี้เป็นค่าของต้นแบบ แต่ไม่มีอะไรบอกว่าไม่ใช่กติกา คนทำแอปอาจคัดไปใช้
- **ไฟล์และบรรทัด:**

  | ค่า | บรรทัด | ข้อกำหนดจริง |
  |---|---|---|
  | 12 แถวต่อหน้า | tsx:163 | 20 แถวต่อหน้า (ค่าเริ่มต้นของสัญญาหลังบ้าน §12.4) ด้วย `Pagination` เดิม |
  | ช่วงใบเสร็จ 0 / 1–5 / 6 รายการขึ้นไป | tsx:265 | มาจากไฟล์แม่แบบของเจ้าของ อยู่ในไฟล์เท่านั้น และต้องมีคำอธิบาย |
  | ใบเสร็จสะสม = ในเดือนบวก 14 หรือบวก 50 | tsx:44, 65 | ไม่ใช่สูตร |
  | ยอดชำระครั้งแรก 499 บาทเมื่อไม่มียอด | tsx:48, 65 | ไม่ใช่สูตร |

- **ตรวจหลังแก้:** ค้นไฟล์แล้วไม่มีข้อความ “30 ก.ย. 2569” ที่พิมพ์ตายตัวนอกวัตถุข้อมูลตัวอย่าง

### PD-22 กลุ่มลูกค้าที่จ่ายสูง: ยอดเท่ากันที่ขอบกลุ่ม กลุ่มเล็ก และช่วงเวลา

- **อาการ:** ข้อมูลตัวอย่างมี 14 บริษัทที่จ่าย 2,990.00 บาทเท่ากัน กลุ่ม 20% (15 บริษัท) ตัดกลางกลุ่มนี้ อยู่ในกลุ่ม 7 นอกกลุ่ม 7 และกลุ่ม 80% (13 บริษัท) อยู่ในกลุ่ม 5 นอกกลุ่ม 9 โดยหน้าจอไม่บอก เมื่อกรองจนเหลือบริษัทเดียวหน้าจอขึ้น “ลูกค้าที่จ่ายสูงสุด 20% แรก 1 จาก 1 บริษัท (100.0%)” หัวข้อ “รายรับมาจากลูกค้ากลุ่มใด” ไม่บอกว่านับเงินช่วงไหน
- **วิธีดู:** รายรับ → ลูกค้าที่สร้างรายรับสูง → “ดูรายชื่อ” ของกลุ่มที่จ่ายสูงสุด แล้วดูบริษัทท้ายรายชื่อกับบริษัทแรกของกลุ่มที่เหลือ (MM005, MM010, MM021 ถึง MM025 อยู่ในกลุ่ม; MM026 ถึง MM032 อยู่นอกกลุ่ม ทั้งหมดจ่าย 2,990 บาท); ตั้งตัวกรองให้เหลือบริษัทเดียวแล้วเปิดแท็บเดิม
- **ไฟล์และบรรทัด:** tsx:187–188 (หัวข้อ ข้อความ และไม่มีบรรทัดบอกยอดเท่ากัน); analytics:10–18 `spendConcentration` ไม่คืนจำนวนบริษัทที่จ่ายเท่ากันนอกกลุ่ม และไม่มีกติกากลุ่มเล็ก; analytics:8 ค่าเท่ากันเรียงตามรหัส; tsx:244 ชีตสรุปของการส่งออกไม่มีบรรทัดนี้เช่นกัน
- **วิธีแก้:** ทำตาม[เอกสารกราฟและอันดับ §5](../specs/mangmee-executive-usage-pareto-spec-th.md): ให้ `spendConcentration` คืนจำนวนและยอดของบริษัทนอกกลุ่มที่จ่ายเท่ากับลำดับสุดท้ายของกลุ่ม ทั้งของกลุ่ม 20% และของกลุ่ม 80% แล้วแสดงใต้แต่ละกลุ่มว่า “มีอีก N บริษัทที่จ่ายเท่ากับลำดับสุดท้ายของกลุ่ม (X บาท) แต่อยู่นอกกลุ่ม” ซึ่งกดเปิดรายชื่อบริษัทที่จ่ายเท่ายอดนั้นทั้งหมดได้ รายชื่อที่เรียงตามยอดมีบรรทัด “ถ้ายอดเท่ากัน บริษัทที่สมัครก่อนอยู่ก่อน”; ประชากรน้อยกว่า 10 ไม่แบ่งกลุ่ม แสดงอันดับกับ “บริษัทน้อยเกินไปสำหรับการแบ่งกลุ่ม”; ค่าเท่ากันเรียงตามวันที่สมัครก่อน; หัวข้อเป็น “รายรับในเดือน <ชื่อเดือน> มาจากลูกค้ากลุ่มใด”; ป้าย “บริษัทที่เหลือ” เป็น “ลูกค้านอกกลุ่มที่จ่ายสูงสุด 20% แรก”
- **ตรวจหลังแก้:** ข้อมูลตัวอย่างแสดง “มีอีก 7 บริษัท…” ที่กลุ่ม 20% และ “มีอีก 9 บริษัท…” ที่กลุ่ม 80% รายชื่อที่เปิดจากประโยคทั้งสองมี 14 บริษัท และบรรทัดสรุปของรายชื่อนั้นแสดง 41,860.00 บาท; ประชากร 1, 4 และ 9 ไม่มีคำว่า “20% แรก” และไม่มีประโยคยอดเท่ากัน (เคส REP-29, REP-33); เพิ่มกรณีเดียวกันใน `check-analytics.ts` (PD-34)

### PD-23 อันดับ: ค่าเท่ากันได้เลขต่างกัน และหน่วยลอย

- **อาการ:** เลขอันดับคือลำดับของแถว บริษัทที่ค่าเท่ากันจึงได้เลขต่างกัน บรรทัดสรุปลงท้ายด้วยหน่วยที่ไม่ติดกับตัวเลข และกราฟ 10 อันดับไม่บอกเมื่อมีบริษัทที่ค่าเท่ากับรายการสุดท้ายแต่ไม่ได้แสดง
- **วิธีดู:** การใช้งาน → อันดับการใช้; ชีต “อันดับการใช้” และ “อันดับยอดรับ” ในแผงส่งออก
- **ไฟล์และบรรทัด:** tsx:184 (`{i+1}` และข้อความ “10 อันดับแรกจาก … บริษัท · เดือนที่เลือก · ใบ”); tsx:242 และ 245 (`String(i+1)`); analytics:8
- **วิธีแก้:** ค่าเท่ากันได้เลขอันดับเดียวกัน (1, 1, 3); ค่าที่ไม่มีข้อมูลไม่มีเลขอันดับ; บรรทัดสรุปเป็น “10 อันดับแรกจาก 72 บริษัท ตามใบเสร็จในเดือน <ชื่อเดือน>” และหน่วยอยู่ติดกับตัวเลขของแต่ละแถว; ใต้กราฟแสดง “มีอีก N บริษัทที่ค่าเท่ากับอันดับสุดท้ายที่แสดง (V <หน่วย>)” เมื่อมีบริษัทที่ค่าเท่ากับรายการสุดท้ายแต่ไม่ได้อยู่ในกราฟ ตาม[เอกสารกราฟและอันดับ §4](../specs/mangmee-executive-usage-pareto-spec-th.md)
- **ตรวจหลังแก้:** เพิ่มบริษัทตัวอย่างสองแห่งที่ค่าเท่ากันในสิบอันดับแรก แล้วยืนยันว่าได้เลขเดียวกัน; เพิ่มบริษัทตัวอย่างให้ค่าเท่ากันคร่อมรายการที่สิบ แล้วยืนยันว่าประโยคใต้กราฟบอกจำนวนที่ไม่ได้แสดงถูกต้อง และไม่มีประโยคเมื่อไม่มีค่าเท่ากันคร่อมขอบ (เคส REP-34)

### PD-24 รายชื่อบริษัท: ข้อมูลไม่ครบ แบ่งหน้าทำเอง

- **อาการ:** แต่ละแถวไม่มีชื่อจดทะเบียน ป้ายสถานะแพ็กเกจที่เป็นป้าย และเวลาใช้ระบบล่าสุด การแบ่งหน้าเป็นปุ่ม “ก่อนหน้า / ถัดไป” ที่ทำเอง หน้าละ 12 แถว และบรรทัดสรุปใช้คำว่า “รับสุทธิ”
- **วิธีดู:** บริษัทลูกค้า
- **ไฟล์และบรรทัด:** tsx:176 (5 คอลัมน์); tsx:290 (บรรทัดสรุป การแบ่งหน้า และข้อความ “บริษัทที่นำมาคำนวณหลังตัวกรองร่วม”); tsx:163
- **วิธีแก้:** ข้อมูลของแต่ละบริษัทตาม[สเปกหน้าจอ §6](../specs/mangmee-executive-business-ui-spec-th.md); ใช้ `Pagination` เดิม (`apps/web/src/common/components/data-table/Pagination.tsx`) หน้าละ 20 แถว โดยให้ปุ่มสูง 44 px; บรรทัดสรุปเป็น “พบ N บริษัท · ยอดรับสุทธิในเดือน X บาท · เรียงตาม …”; ตัวเลือกเรียงตามรายการของสเปกหน้าจอ §6
- **ตรวจหลังแก้:** ไล่ทุกหน้าของรายชื่อ 40 บริษัทแล้วได้ครบโดยไม่ซ้ำ และกลับจากรายละเอียดแล้วอยู่หน้าเดิม

### PD-25 รายละเอียดบริษัท: หัวหน้าและกล่องไม่ครบ ข้อมูลติดต่อเห็นได้ทุกคน

- **อาการ:** ส่วนหัวมีแต่ชื่อบริษัท ไม่มีกลุ่มธุรกิจ จังหวัด และการ์ดตัวเลขสี่ใบ กล่อง “ที่มาของบริษัท” ใช้ชื่อไม่ตรงสเปก อีเมลและเบอร์โทรเจ้าของบัญชีแสดงให้ทุกมุมมองสิทธิ์ และไม่มีจำนวนสมาชิก จำนวนสาขา กับวันสิ้นสุดแพ็กเกจ
- **วิธีดู:** บริษัทลูกค้า → เปิดบริษัทใดก็ได้ แล้วสลับ “มุมมองสิทธิ์” เป็น “ผู้บริหารอ่านรายงาน” ในเครื่องมือทดลอง ข้อมูลติดต่อยังแสดง
- **ไฟล์และบรรทัด:** tsx:196 (`profile`), tsx:295 และ tsx:306 (ส่วนหัวของหน้า)
- **วิธีแก้:** ทำตาม[สเปกหน้าจอ §8](../specs/mangmee-executive-business-ui-spec-th.md): ส่วนหัวมีชื่อ ชื่อจดทะเบียน กลุ่มธุรกิจ จังหวัด; การ์ดยอดรับสุทธิในเดือน ใบเสร็จในเดือน วันใช้งานในเดือน และใช้ผู้ช่วยในเดือน; กล่องเรียง “รู้จักมั่งมีจากไหน” → “ข้อมูลบริษัท” → “การใช้บริการมั่งมี (ปัจจุบัน)”; เพิ่มตัวเลือกสิทธิ์ “ดูข้อมูลติดต่อ” ในเครื่องมือทดลอง และเมื่อไม่มีสิทธิ์แสดง “ไม่มีสิทธิ์ดูข้อมูลติดต่อ”; ตัดช่อง “รูปแบบกิจการ” ออก (ไม่อยู่ในรุ่นแรกตาม Q27 ของสเปกหลังบ้าน — ตัดสินแล้ว 2 ต.ค. 2569 (เจ้าของ: ตามที่แนะนำ))
- **ตรวจหลังแก้:** มุมมองที่ไม่มีสิทธิ์ดูข้อมูลติดต่อไม่เห็นอีเมลและเบอร์โทร (เคส SEC-21)

### PD-26 ตัวกรอง: ไม่มี “ไม่ระบุ” ปุ่มล้างแสดงตลอด เดือนล้างได้

- **อาการ:** ตัวกรองประเภทธุรกิจไม่มีตัวเลือก “ไม่ระบุ”; ปุ่ม “ล้างตัวกรอง” แสดงตลอดแม้ไม่มีเงื่อนไข; ตัวเลือกเดือนมีปุ่มล้าง กดแล้วเดือนกลับเป็นกันยายน 2569 โดยไม่บอก; มีตัวกรองและการจัดกลุ่ม “รูปแบบกิจการ” ซึ่งระบบจริงไม่มีข้อมูล
- **วิธีดู:** ภาพรวม → เปิด “ตัวกรอง”; กดล้างในตัวเลือกเดือน; บริษัทลูกค้า → “ตัวกรองรายชื่อเพิ่มเติม”; ลูกค้าและที่มา → ธุรกิจ → “จัดกลุ่มตาม”
- **ไฟล์และบรรทัด:** tsx:168 (`opts` สร้างตัวเลือกจากข้อมูลที่มี), tsx:171 (ปุ่มล้างไม่มีเงื่อนไข และ `e.target.value||'2026-09'`), tsx:200 และ tsx:290 (รูปแบบกิจการ)
- **วิธีแก้:** เพิ่ม “ไม่ระบุ” ในตัวกรองประเภทธุรกิจ; แสดง “ล้างตัวกรอง” เมื่อมีเงื่อนไขอย่างน้อยหนึ่งข้อ; ตัวเลือกเดือนไม่มีปุ่มล้าง และเลือกได้เฉพาะเดือนที่มีข้อมูล; ตัดตัวกรอง การจัดกลุ่ม และคอลัมน์ “รูปแบบกิจการ” ออก (ตัดสินแล้ว 2 ต.ค. 2569 (เจ้าของ: ตามที่แนะนำ) — Q27)
- **ตรวจหลังแก้:** เปิดหน้าครั้งแรกไม่มีปุ่ม “ล้างตัวกรอง”; ไม่มีคำว่า “รูปแบบกิจการ” บนหน้าใด

### PD-27 สถานะของหน้า: กล่องทำเอง ไม่มีปุ่มกลับ ปุ่มส่งออกไม่บอกเหตุผล

- **อาการ:** สถานะกำลังอ่าน ผิดพลาด ไม่มีสิทธิ์ และไม่พบข้อมูล ใช้กล่อง `Empty` ที่ต้นแบบทำเอง ไม่ใช่ component กลาง; หน้ารายละเอียดในเดือนที่ไม่มีข้อมูลหรือเดือนก่อนสมัครเหลือแต่ข้อความ ไม่มีปุ่มกลับรายชื่อ; ปุ่ม “ส่งออก Excel” ถูกปิดโดยไม่บอกเหตุผล ทั้งที่โค้ดคำนวณเหตุผลไว้แล้ว
- **วิธีดู:** เครื่องมือทดลอง → “การอ่านข้อมูลรายงาน” เลือกแต่ละค่า; เปิดรายละเอียดบริษัทแล้วเปลี่ยนเดือนเป็น ส.ค. 2569; เปรียบเทียบ → เลือกฝั่ง A และ B เป็นกลุ่มเดียวกัน แล้วดูปุ่มส่งออก
- **ไฟล์และบรรทัด:** tsx:117 (`Empty`), tsx:287–288, tsx:306; ปุ่มกลับมีเฉพาะที่ tsx:295; tsx:211–220 (`exportBlockReason`) กับ tsx:304–305 (ใช้เพียงปิดปุ่ม)
- **วิธีแก้:** ใช้ `LoadingState`, `ErrorState`, `ForbiddenState`, `EmptyState` เดิมของแอป; ให้สถานะเดือนที่ไม่มีข้อมูลของหน้ารายละเอียดมีปุ่ม “← กลับรายชื่อบริษัท”; แสดงข้อความของ `exportDisabledReason` ใกล้ปุ่มส่งออก
- **ตรวจหลังแก้:** ทุกสถานะของ[สเปกหน้าจอ §11](../specs/mangmee-executive-business-ui-spec-th.md) มีทางกลับ และปุ่มที่ใช้ไม่ได้มีเหตุผลเป็นข้อความ

### PD-28 หน้าเปรียบเทียบ: dropdown ทุกบริษัท คู่เริ่มต้น ตัวเลือกเดือนที่ใช้ไม่ได้

- **อาการ:** การเทียบบริษัทกับบริษัทใส่ทุกบริษัทของเดือนเป็นตัวเลือกใน dropdown สองช่อง พร้อมรหัส `MM###`; เปิดหน้าเปรียบเทียบครั้งแรกระบบเลือกคู่ให้เอง; ตัวเลือก “เดือนนี้กับเดือนก่อน” อยู่ในเมนูแต่ใช้ไม่ได้ทุกครั้ง
- **วิธีดู:** เปรียบเทียบ → “เปรียบเทียบอะไร” เลือก “บริษัทกับบริษัท” แล้วเปิดตัวเลือกฝั่ง A; เลือก “เดือนนี้กับเดือนก่อน”
- **ไฟล์และบรรทัด:** tsx:203 (ตัวเลือกของแต่ละมิติ), tsx:92, 200 และ 209 (คู่เริ่มต้น และตัวเลือก `period`), tsx:215
- **วิธีแก้:** ทำตาม[เอกสารโครงหน้า §4](../specs/mangmee-executive-navigation-comparison-spec-th.md): เปิดหน้าครั้งแรกยังไม่เลือกฝั่งใด; การเทียบบริษัทเริ่มจากการเลือกสองบริษัทในหน้ารายชื่อ ไม่ใช้ dropdown ที่บรรจุทุกบริษัท; ตัดตัวเลือกเทียบเดือนออกจนกว่าจะมีข้อมูลย้อนหลัง; บนมือถือแสดงเป็นบล็อกทีละรายการ (PD-03)
- **ตรวจหลังแก้:** ไม่มี dropdown ใดที่มีรายการเท่าจำนวนบริษัท และเปิดหน้าครั้งแรกเห็น “เลือกสองกลุ่มที่ต้องการเปรียบเทียบ”

### PD-29 แผงส่งออก: ตัวอย่างไฟล์ที่ประกาศสีเอง ปุ่มอยู่ท้าย ข้อมูลติดต่อทุกไฟล์ หัวคอลัมน์ไม่ตรงสเปก

- **อาการ:** แผงวาดตัวอย่างไฟล์ด้วยสีที่ประกาศเองเป็นรหัสสี และคำนวณตัวเลขเป็นชุดที่สามนอกจากหน้าจอกับไฟล์; ปุ่มสร้างไฟล์อยู่หลังตัวอย่าง; ทุกการส่งออกมีคอลัมน์อีเมลและเบอร์โทรเจ้าของบัญชี; ชีตรายบริษัทมี 11 หัวคอลัมน์ที่ไม่ตรงกับรายการของสเปก; ค่า “อย่างน้อย 38” เขียนเป็นข้อความก้อนเดียว; การ์ด “ใบเสร็จสะสม” และช่วง 0 / 1–5 / 6 รายการขึ้นไป เป็นตัวเลขที่ไม่มีบนหน้าจอและไม่มีคำอธิบาย
- **วิธีดู:** ภาพรวม → “ส่งออก Excel” → “ดูตัวอย่างรูปแบบไฟล์” แล้วสลับชีต
- **ไฟล์และบรรทัด:** tsx:280 (ตัวอย่างไฟล์ ตำแหน่งปุ่ม และตัวเลือกดูตัวอย่างชีต), css:128–157 (รหัสสีที่ประกาศเอง), tsx:265–270 (ตัวเลขของตัวอย่าง), tsx:233 และ tsx:235 (หัวคอลัมน์และข้อมูลติดต่อในทุกการส่งออก), tsx:237 (ข้อความ “อย่างน้อย”)
- **วิธีแก้:** ทำตาม[เอกสารส่งออก Excel §2 และ §4.1](../specs/mangmee-executive-excel-export-spec-th.md): แผงแสดงบรรทัดสรุป ปุ่มสร้างไฟล์ รายการชีต และรายการหัวคอลัมน์เป็นข้อความ ไม่มีตัวอย่างไฟล์; หัวคอลัมน์ใช้รายการของ §4.1; ช่องติ๊ก “รวมข้อมูลติดต่อเจ้าของบัญชี” มีเฉพาะการส่งออกจากรายชื่อและรายละเอียดบริษัท ค่าเริ่มต้นไม่ติ๊ก และแสดงเฉพาะผู้มีสิทธิ์ดูข้อมูลติดต่อ; ลบ css:128–157
- **ตรวจหลังแก้:** ที่ 390×844 เห็นปุ่มสร้างไฟล์ในจอแรก; การส่งออกจากภาพรวมไม่มีหัวคอลัมน์ข้อมูลติดต่อ (เคส EXL-08, EXL-20)

### PD-30 บัญชีผู้บริหาร: ใช้งานได้ทันที ระงับในครั้งเดียว ไม่มีสิทธิ์รายคน

- **อาการ:** บัญชีที่สร้างขึ้นสถานะ “เปิดใช้งาน” ทันที; ระงับได้ด้วยการกดครั้งเดียว ไม่มีการยืนยันและไม่มีเหตุผล; สถานะมีสองค่า และค่าของตัวกรองคือ `DISABLED`; ค้นไม่พบแล้วแสดงทั้งข้อความและตารางเปล่า; ฟอร์มมีชื่อกับอีเมล ไม่มีสิทธิ์ส่งออกและสิทธิ์ดูข้อมูลติดต่อ; หัวคอลัมน์ “เข้าใช้ล่าสุด”
- **วิธีดู:** บัญชีผู้บริหาร → “เพิ่มผู้บริหาร” → บันทึก; เปิดบัญชีใดก็ได้ → “จำลองระงับบัญชี”; ค้นด้วยคำที่ไม่มี
- **ไฟล์และบรรทัด:** tsx:282 (`active:true`), tsx:301 (ระงับ), tsx:299 (ตัวกรอง ตาราง และ `Empty` ที่ตามด้วยตาราง), tsx:300 (ฟอร์ม), tsx:285
- **วิธีแก้:** ทำตาม[สเปกหน้าจอ §9.2](../specs/mangmee-executive-business-ui-spec-th.md): ช่องชื่อผู้ใช้ ชื่อที่แสดง เบอร์มือถือและอีเมลที่ไม่บังคับ; ช่องติ๊กสิทธิ์สองช่อง; หลังบันทึกแสดงรหัสผ่านชั่วคราวครั้งเดียวและสถานะ “รอเปิดใช้งาน”; ระงับต้องยืนยันและกรอกเหตุผล; สถานะสี่ค่าตามที่สเปกกำหนด; ไม่พบบัญชีแสดงเฉพาะข้อความ; หัวคอลัมน์ “เข้าเว็บล่าสุด”
- **ตรวจหลังแก้:** เคส USR-19 ถึง USR-22 ในส่วนที่ต้นแบบจำลองได้

### PD-31 โหลดใหม่บนหน้ารายละเอียดหรือบัญชี กลับไปหน้าภาพรวม

- **อาการ:** สถานะของหน้าเก็บในสถานะของ widget ไม่ใช่ใน URL และหน้ารายละเอียดบริษัท รายละเอียดบัญชี กับฟอร์มเพิ่มผู้บริหาร ถูกบันทึกเป็นหน้าภาพรวม โหลดใหม่จึงกลับไปภาพรวม
- **วิธีดู:** เปิดรายละเอียดบริษัทแล้วโหลดหน้าใหม่
- **ไฟล์และบรรทัด:** tsx:146 (`persist` แปลง `detail`, `user`, `new-user` เป็น `overview`); tsx:128–130 (อ่านสถานะที่บันทึก)
- **วิธีแก้:** แอปจริงเก็บสถานะใน URL ตาม[สเปกหน้าจอ §3.2](../specs/mangmee-executive-business-ui-spec-th.md) ต้นแบบทำงานในกรอบที่ไม่มี URL ของตัวเอง จึงให้บันทึกเส้นทางพร้อมบริษัทหรือบัญชีที่เปิดอยู่ แท็บ และเลขหน้า แล้วคืนได้ครบ ถ้าทำไม่ได้ให้เขียนใน README ว่าเป็นข้อจำกัดของต้นแบบ ไม่ใช่พฤติกรรมที่ต้องการ
- **ตรวจหลังแก้:** โหลดใหม่บนรายละเอียดบริษัทแล้วได้บริษัทและแท็บเดิม (เคส REP-25 ตรวจกับแอปจริงเท่านั้น)

## 5. รายละเอียด — เล็กน้อย

### PD-32 การเข้าถึง

- **อาการและบรรทัด:** กล่องแถบสัดส่วนมี `aria-label` แต่ไม่มี role จึงไม่ถูกอ่าน (tsx:179, 188); แท็บของรายละเอียดบริษัทไม่มี `aria-pressed` สถานะที่เลือกจึงบอกด้วยสีอย่างเดียว (tsx:196) ต่างจากแท็บหน้าอื่น (tsx:173); `aria-live` ครอบเนื้อหาทั้งหน้า ทุกครั้งที่เปลี่ยนตัวกรองโปรแกรมอ่านหน้าจออ่านใหม่ทั้งหน้า (tsx:306); ปุ่ม “ดูรายชื่อลูกค้ากลุ่มนี้” มีชื่อสำหรับโปรแกรมอ่านหน้าจอเป็นอีกข้อความ (tsx:188); ตารางไม่มี caption และ `scope` (tsx:118)
- **วิธีแก้:** ใส่ `role="group"` หรือย้ายป้ายไปที่หัวข้อ; ใส่ `aria-pressed` ให้แท็บทุกชุด; จำกัด `aria-live` ไว้ที่บรรทัดสรุปผล; ให้ชื่อของปุ่มตรงกับข้อความที่เห็น; ตารางมี caption และ `scope` แบบ `PartnerListPage.tsx`
- **ตรวจหลังแก้:** เคส FE-24

### PD-33 README และข้อความ PASS กล่าวเกินสิ่งที่ตรวจจริง

- **อาการและบรรทัด:** README เขียนว่าคำสั่งตรวจครอบคลุม “ขนาดหน้าจอ 320–1440px” ซึ่งจริงเฉพาะ 5 หน้ารายงานกับแผงส่งออก และเฉพาะการล้นของทั้งหน้า; check-export:36 เขียน “keyboard/theme” ทั้งที่กดแป้นเพียง Escape ครั้งเดียว; check-demo:70 เขียน “cross-page Back” และ “desktop/mobile navigation” โดยไม่บอกว่าการกดกลับถูกตรวจหลังล้างตัวกรอง และมือถือถูกตรวจเพียง 5 หน้า
- **วิธีแก้:** เขียนสิ่งที่ตรวจจริงและสิ่งที่ไม่ได้ตรวจเป็นสองรายการใน README และอ้างเอกสารนี้
- **ตรวจหลังแก้:** อ่าน README แล้วรู้ว่าตารางบนมือถือ การกดกลับ และไฟล์ Excel จริง ถูกตรวจหรือไม่

### PD-34 `check-analytics.ts` ตรวจเฉพาะสูตร และยืนยันการเรียงตามรหัส

- **อาการและบรรทัด:** ตัวตรวจยืนยันสูตรล้วน (สัดส่วน สามสถานะใบเสร็จ จำนวนกลุ่ม 20% ขอบ 80% ยอดศูนย์และติดลบ) ไม่มีกรณีข้อความเมื่อยอดเท่ากันที่ขอบกลุ่มหรือกลุ่มเล็ก; check-analytics:7 และ check-analytics:14 ยืนยันว่าค่าเท่ากันเรียงตามรหัส
- **วิธีแก้:** หลังแก้ PD-22 และ PD-23 เพิ่มกรณี: จำนวนบริษัทนอกกลุ่มที่จ่ายเท่ากับลำดับสุดท้ายของกลุ่ม 20% และของกลุ่ม 80%, จำนวนบริษัทที่ค่าเท่ากับรายการสุดท้ายของ 10 อันดับ, ประชากร 1, 4 และ 9, เลขอันดับของค่าที่เท่ากัน, การเรียงตามวันที่สมัคร และสถานะใบเสร็จแบบที่สี่ “ไม่มีในแพ็กเกจ”
- **ตรวจหลังแก้:** ตัวตรวจผ่านด้วยกรณีใหม่ และข้อความ PASS ระบุกรณีที่เพิ่ม

## 6. สิ่งที่ต้นแบบทำถูกและควรคงไว้

- รายการ “อันดับการใช้” เป็นบล็อกทีละบริษัท อ่านครบที่ 390 px (tsx:184) ใช้เป็นแบบของรายการบนมือถือได้
- ส่วนของกราฟเป็นปุ่มจริงที่กดได้ด้วยแป้นพิมพ์ และมีรายการคำอธิบายที่มีชื่อ จำนวน และเปอร์เซ็นต์ใต้กราฟ (tsx:179, 188)
- ข้อมูลติดต่อเป็นข้อมูลสมมติ (`@example.com`, เบอร์ที่ปิดบางหลัก) และมีบริษัททดสอบกับบริษัทภายในในข้อมูลตัวอย่างเพื่อพิสูจน์ว่าถูกตัดออก (tsx:67, 81)
- วันที่บนหน้ารายงานเป็นรูปแบบไทย พ.ศ. (tsx:77) และค่าที่ไม่มีข้อมูลแสดง — ไม่ใช่ 0 (tsx:76)
- การเปลี่ยนหน้า เดือน หรือสิทธิ์ระหว่างเตรียมไฟล์ ยกเลิกผลเก่า (tsx:141–143, 275)
- เส้นทางคำขอที่บันทึกไว้เดิมกลับหน้าภาพรวม (HIDE-03, HIDE-04)
