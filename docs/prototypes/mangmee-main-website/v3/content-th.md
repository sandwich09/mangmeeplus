## กติกาความจริงที่ใช้ทั้งเอกสาร

- ราคาและจำนวนมาจาก CAT เท่านั้น ทุกจุดที่มีราคาติดป้าย **ตรวจราคาก่อนเผยแพร่**
- ไม่มีตัวเลขลูกค้า รีวิว โลโก้ รางวัล หรือคะแนนที่แต่งขึ้น ที่ว่างใช้ป้าย **[รอรีวิวลูกค้าจริง]**
- พูดตรงว่า AI ไม่ได้แทนนักบัญชี สิ่งที่ AI อ่านเป็นร่างจนกว่าคนกดยืนยัน
- ภาพหน้าจอ แชต และใบเสร็จเป็นข้อมูลสมมติ ติดป้าย “ภาพจำลอง · ข้อมูลสมมติ” ทุกภาพ

**กดปุ่มแล้วจะเกิดอะไรขึ้น** — 4 ขั้น จากกดปุ่ม ถึงใบเสร็จใบแรก ตอนสมัครยังไม่ต้องใช้บัตร

1. เพิ่มเพื่อน LINE มั่งมีพลัส — แล้วกด “เปิดร้านใหม่”
2. กรอกชื่อร้านและเบอร์มือถือ — บางคำขอทีมงานมั่งมีตรวจก่อนเปิดร้าน
3. ได้ข้อความ “เปิดร้านแล้ว” — กด “เลือกแพ็กเกจ” แล้วเลือกรายเดือนหรือรายปี
4. จ่ายด้วยบัตรหรือพร้อมเพย์ — แล้วส่งใบเสร็จใบแรกให้น้องมั่งมี

**คำถามเรื่องราคา**

- จ่ายรายปีต่างจากรายเดือนอย่างไร? — รายปีจ่ายครั้งเดียว ในราคาเท่ากับ 10 เดือน ได้ใบเสร็จเท่ากับ 12 เดือนเป็นก้อนเดียว ใช้ได้ตลอดปี ไม่ได้เติมใหม่ทุกเดือน
- ใบเสร็จครบจำนวนในแพ็กเกจแล้วทำอย่างไร? — น้องมั่งมีจะแจ้งในแชต และหยุดอ่านรูปจนถึงรอบใหม่ ซื้อแพ็กเกจเดิมซ้ำเพื่อเพิ่มจำนวนได้ทันที หรือเปลี่ยนเป็นแพ็กเกจที่ใหญ่ขึ้น ข้อมูลเดิมไม่หาย
- เปลี่ยนแพ็กเกจภายหลังได้ไหม? — ได้ เปลี่ยนเป็นแพ็กเกจใหญ่ขึ้นมีผลเมื่อจ่ายส่วนต่าง วันหมดอายุเท่าเดิม เปลี่ยนเป็นแพ็กเกจเล็กลงมีผลเมื่อครบรอบที่จ่ายแล้ว
- มีทดลองใช้ฟรีไหม? — ตอนนี้ไม่มี สมัครเปิดร้านได้โดยไม่ต้องใช้บัตร แล้วจ่ายเมื่อเลือกแพ็กเกจ
- ราคานี้รวม VAT หรือยัง ออกใบกำกับภาษีไหม? — [รอฝ่ายบัญชียืนยัน: แคตตาล็อกระบุว่ายังไม่ได้จด VAT ราคาจึงไม่บวก VAT และยังไม่มีใบกำกับภาษีเต็มรูป]

ทำไมช่วยขาย:
- มือถือเรียงคอลัมน์เดียว ราคา 40 px ข้อมูลสำคัญ 15–16 px ตาม UX ข้อแก้ 3
- ตัวช่วยเลือกแทนการคิดเลขเอง; “รวมเจ้าของ” กันการเลือกแพ็กเกจเล็กเกินไป
- กล่อง “นับใบเสร็จอย่างไร” ตอบคำถามที่ทำให้ลูกค้าผิดหวังหลังซื้อได้บ่อยที่สุด (รูปลายเซ็นก็นับ)
- 4 ขั้นหลังกดปุ่มตรงกับ flow สมัครจริงใน LINE และบอกว่าแพ็กเกจไม่ถูกส่งต่อ (UX ข้อแก้ 4)
- ไม่ใช้ “ยอดนิยม” หรือ “คุ้มที่สุด” ([GL ข้อ 6](../../../research/mangmee-thai-main-website-guideline-2026-10-20-th.md))

ข้อสำหรับการทำจริง: ราคาและตารางต้องอยู่ใน HTML ที่ server ส่งมา ให้ Google และ AI อ่านเห็นทั้งรายเดือนและรายปีโดยไม่ต้องกดปุ่ม

## 4. ความเร็วและการอ่านบนมือถือ (สำหรับคนทำเว็บจริง)

- HTML ส่งข้อความทั้งหมดมาเลย หัวเรื่องอ่านได้ทันที ไม่รอ animation
- ภาพหลักทำด้วย HTML/CSS โลโก้เป็น SVG เล็ก ภาพหน้าจอจริงภายหลังใช้ WebP/AVIF ระบุ `width`/`height` และ `loading="lazy"` นอกหน้าจอแรก
- ฟอนต์ Anuphan + Inter (`display=swap`) ถ้าวัดแล้วช้า ให้ self-host เฉพาะน้ำหนักที่ใช้
- JavaScript มีแค่ปุ่มสลับรายเดือน/รายปี ตัวช่วยเลือก และเมนูมือถือ FAQ ใช้ `<details>`
- เป้าหมาย Core Web Vitals (field p75): LCP ≤ 2.5 วินาที, INP ≤ 200 ms, CLS ≤ 0.1
- เนื้อหา 17 px (มือถือ) / 18 px (จอกว้าง), line-height 1.7, H1 34 / 54 px ตาม [GL ข้อ 8](../../../research/mangmee-thai-main-website-guideline-2026-10-20-th.md)
- Contrast ที่คำนวณ (ต้องตรวจซ้ำในเบราว์เซอร์จริง): ตัวอักษร 14.41:1; ตัวอักษรรอง 7.69:1; ลิงก์ 7.13:1; ปุ่มเขียว 5.02:1; ปุ่มทองบนเขียวเข้ม 6.32:1; ข้อความบนพื้นเข้ม 8.30:1; สถานะ 6.37–6.57:1; ขอบปุ่มตัวเลือก 3.97:1
- เป้าหมายกด: ปุ่มหลัก 52 px อื่น ๆ 44 px ขึ้นไป มีลิงก์ข้ามไปเนื้อหาหลัก และกรอบ focus `#B45309` / `#FCD34D`

## 5. BreadcrumbList (ใช้เมื่อมีหน้าย่อยจริงเท่านั้น)

หน้าแรกหน้าเดียวไม่ต้องมี BreadcrumbList ถ้าเจ้าของอนุมัติหน้าย่อยตาม “งานภายหลัง” ใน [SEO-P](../../../plans/mangmee-google-seo-implementation-plan-2026-10-20-th.md) ให้ใช้แบบนี้ พร้อม URL 200, canonical ของตัวเอง และอยู่ใน sitemap (`/pricing` เป็นตัวอย่าง ยังไม่ได้ตัดสินใจ)

```json
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    {"@type": "ListItem", "position": 1, "name": "มั่งมีพลัส", "item": "https://mangmeeplus.com/"},
    {"@type": "ListItem", "position": 2, "name": "ราคาแพ็กเกจ", "item": "https://mangmeeplus.com/pricing"}
  ]
}
```

## 6. ร่าง llms.txt (ทางเลือก ไม่เร่งด่วน)

Google ระบุว่า `llms.txt` ไม่เพิ่มหรือลดอันดับใน Search ([SEO-E ข้อ 3](../../../research/mangmee-google-seo-evidence-2026-10-20-th.md)) และยังไม่มีหลักฐานว่า ChatGPT, Gemini หรือ Perplexity ใช้ไฟล์นี้เลือกแหล่งอ้างอิง สิ่งที่ช่วยจริงคือข้อความบนหน้าในข้อ 1.3–1.4 ร่างนี้ต้องอัปเดตทุกครั้งที่ราคาเปลี่ยน
